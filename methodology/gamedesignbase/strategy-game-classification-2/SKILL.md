# 策略游戏分类与边界判定

## 何时使用
- 游戏要求玩家通过计划与对手对抗
- 需要判断游戏是否属于策略游戏类型
- 区分策略游戏与益智游戏
- 区分策略游戏与建设管理模拟游戏
- 确定游戏的抽象程度

## 执行步骤

### 1. 识别核心挑战维度

**必备挑战：**
- 战略挑战
- 后勤挑战
- 逻辑挑战

**可选扩展挑战：**
- 经济挑战
- 探索挑战（用于延迟游戏时间并丰富游戏类型）

**实体对抗特征：**
游戏进行一段时间后会出现实体对抗，但需注意"这对于那些有战略思维的玩家来说，并不是很感冒"

### 2. 判定与益智游戏的边界

| 特征 | 策略游戏 | 益智游戏 |
|------|----------|----------|
| 计划要求 | 包含冲突的计划 | 要求无冲突的计划 |
| 对手 | 必须与一个或多个对手对抗 | 无对手 |
| 决策点 | 检查是否存在"对手"和"对抗性冲突" | 无对抗性冲突 |

### 3. 判定与建设管理模拟游戏的边界

| 特征 | 策略游戏 | 建设管理模拟 |
|------|----------|--------------|
| 计划要求 | 要求计划 | 要求计划 |
| 对抗动作 | 包含"直接和对手对抗的动作" | "没有直接和对手对抗的动作" |
| 决策点 | 检查对抗是否为直接动作性对抗 | 无直接对抗 |

### 4. 确认核心胜利目标

**主要目标：** 减少敌人的力量

**游戏性质：** 因此大部分策略游戏都或多或少具有"抽象的战争游戏"特征

### 5. 确定抽象程度

| 抽象程度 | 特征 | 示例 |
|----------|------|------|
| 高度抽象 | 最简化的表现形式 | 西洋跳棋（国际跳棋） |
| 中度抽象 | 保留一定主题元素 | 《Risk》 |
| 具象化 | 具体的主题和表现 | 《轴心与同盟》（二战主题棋盘游戏） |

## 判定流程

```
IF (游戏要求包含冲突的计划
    AND 与一个或多个对手对抗
    AND 包含直接和对手对抗的动作
    AND 主要目标是减少敌人的力量)
THEN 识别为策略游戏

IF (无冲突 OR 无对手)
THEN 识别为益智游戏

IF (无直接对抗动作)
THEN 识别为建设管理模拟游戏
```

## 关键变量

| 变量 | 类型 | 描述 |
|------|------|------|
| 挑战类型集合 | Array | 包含的战略/后勤/逻辑/经济/探索挑战类型 |
| 冲突存在性 | Boolean | 是否存在对抗性冲突 |
| 对手数量 | Integer | 对抗的对手数量（一个或多个） |
| 对抗直接性 | Boolean | 是否存在直接和对手对抗的动作 |
| 主要目标 | String | 是否为减少敌人的力量 |
