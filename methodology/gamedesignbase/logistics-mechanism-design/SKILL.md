# 后勤机制设计

## 何时使用

- 设计包含资源管理或部队维持机制的游戏系统
- 需要为RTS、RPG或传统战争游戏设计差异化的后勤表现
- 平衡后勤深度与玩家娱乐性

## 核心设计原则

### 1. 后勤定义
后勤是指支持战场上的部队并向前线供应新部队的事务。

### 2. 按游戏类型选择后勤深度

| 游戏类型 | 后勤重点 | 典型机制 |
|---------|---------|---------|
| 传统战争游戏 | 极简或省略 | 开局固定军队，无补给线 |
| RTS游戏 | 武器生产为核心 | 原材料采集、科技研究、设施保护 |
| RPG游戏 | 物品栏管理为核心 | 有限背包空间、装备取舍决策 |

### 3. 设计执行

**RTS后勤设计：**
1. 定义有限原材料种类
2. 设计生产链（采集→加工→成品）
3. 添加科技树解锁新武器类型
4. 设计生产设施的保护需求

**RPG后勤设计：**
1. 设定物品栏容量上限
2. 设计物品重量/体积系统
3. 规划队伍角色装备互补
4. 创建危险情境下的取舍决策点

### 4. 关键权衡
- 后勤深度 vs 战斗流畅性
- 真实模拟 vs 玩家管理负担
- 策略丰富度 vs 学习曲线

## 避免过度设计

玩家趋向于认为打斗比较有趣，发现后勤是对打斗无聊的中断。仅在后勤本身构成核心玩法时深入设计。
