# 游戏进度与故事设计

## 何时使用
- 游戏很长且处于设计阶段
- 需要决定前进感的来源
- 需要配置关卡结构
- 需要确定故事需求
- 游戏具有多个关卡
- 游戏具有明显进步感
- 游戏包含故事线

## 执行步骤

### 1. 决定前进感的来源

**核心问题：** 使玩家感觉到"在前进"而非"原地踏步"

**选项：**
- 选项A：关卡（Level）
- 选项B：故事（Story）
- 选项C：两者都有（Level + Story）

### 2. 配置关卡结构

**问题1：游戏是否太长以至于应该分为不同的关卡？**
- 是：进入关卡结构设计
- 否：考虑其他进度机制

**问题2（若分关卡）：关卡之间的关系是什么？**

| 配置类型 | 特征 | 适用场景 |
|----------|------|----------|
| 不相关 | 玩家可以在任何时间玩任何一关 | 休闲游戏、迷你游戏合集 |
| 按一定顺序 | 玩家只有完成了一关才能进行下一关 | 线性叙事游戏、难度递进游戏 |
| 分支配置 | 完成一关后解锁多个可选下一关 | 非线性探索游戏、多路径RPG |

**问题3：什么情况才能确定玩家已经完成了一关？**
- 必须明确定义通关条件

### 3. 确定故事需求

**需要故事的情况：**
- 故事赋予游戏上下文环境和目标
- 角色扮演游戏（RPG）
- 冒险游戏（Adventure）
- "具体的游戏"通常都有故事背景

**通常不需要故事的情况：**
- 运动游戏（上下文环境自解释）
- 益智游戏（上下文环境自解释）
- "抽象的游戏"一般都没有故事
- 例外：《吃豆人小姐》在小地方有故事元素
- 很少有涉及抽象角色的故事

### 4. 编制故事和关卡进度文档

**确定文档必要性：**
检查游戏是否为单关卡游戏（如计算棋盘游戏）或无故事的多关卡游戏。如果不是，则需要此文档。

**记录核心内容：**
- 游戏中的大型故事线（如存在）
- 玩家从一个关卡行进到另一个关卡的方式
- 玩家从开始到结束体验的大体轮廓（无需记录所有细节，只需大体轮廓）

**处理分支叙事：**
如果故事根据玩家动作建立分支，需记录：
- 关键决策点
- 什么样的决定会导致游戏采取这条路径而不是另一条
- 不同路径的后果说明

**明确叙事体验方式：**
指出玩家如何体验故事，包括但不限于：
- 场景插叙（cutscenes）
- 任务简报
- 对话
- 其他叙事元素

**关键概念区分：**
明确故事或关卡进度与游戏结构并非同一概念：
- 完整故事可能仅发生在单一可玩性模式中
- 游戏可能有多种不同的游戏模式却不包含故事
- 虽然游戏随着时间会改变模式，故事也会跟随时间改变，但两者之间并没有必然的联系

## 关键变量

| 变量 | 类型 | 描述 |
|------|------|------|
| 游戏时长 | 时间维度 | 完成游戏所需的预计时间 |
| 关卡配置类型 | 枚举 | 不相关/顺序/分支三种结构 |
| 通关条件 | 条件定义 | 判定关卡完成的明确标准 |
| 游戏类型 | 分类标签 | RPG、冒险、运动、益智等类型 |
| 关卡数量 | integer | 游戏中的关卡总数 |
| 故事分支点 | array | 导致故事线分歧的玩家决策点列表 |
| 叙事交付方式 | enum | 场景插叙/任务简报/对话/其他 |
