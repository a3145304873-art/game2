# 命令与动作系统设计

## 何时使用

- 设计RTS、战术游戏或RPG的命令系统
- 实现从输入设备检测到游戏动作执行的流程
- 需要定义单位选择、命令下达和反馈机制
- 设计基于化身的动作触发机制

## 命令下达机制

### 核心功能
玩家向游戏内的单位或角色发出指令，使其执行特定行为

### 标准三步流程

**步骤1：指定接收命令的单位（Specify the unit）**
- 选择方式：点击选择、框选、快捷键选择、预设编队
- 多选支持：同时选择多个单位接收相同命令

**步骤2：下达命令（Issue the command）**
- 命令形式：**动词（Verb）**
- 典型命令：攻击（attack）、拥抱（embrace）、打开（open）、卸下（unload）
- 输入方式：点击命令按钮、快捷键、手势、语音

**步骤3（可选）：给出命令的对象或目标（Give the object or target）**
- 目标形式：动词的直接宾语
- 典型目标：暴徒（thug）、狗（dog）、装货箱（crate）
- 说明：哪个单位应该攻击、拥抱或打开的具体目标
- 某些命令无需此步骤（如"停止"、"警戒"）

### 语法结构
完整命令 = [主语：玩家指定的单位] + [谓语：命令动词] + [宾语：目标对象]

**示例**："（你，士兵）攻击（那个）暴徒"

### 设计变体
- 即时执行 vs 队列执行（命令排队）
- 单个命令 vs 复合命令（移动+攻击）
- 上下文敏感命令（根据目标自动选择合适动词）

### 反馈要求
- 单位确认收到命令（语音、动画、UI指示）
- 命令执行状态显示
- 无法执行时的反馈

## 动作触发与执行机制

### 设计阶段要求
在每一种游戏可玩性模式中，必须为每个可能开始事件、启动或停止过程的动作，指定一种实现机制

### 输入检测与映射
- 当UI检测到来自输入设备的数据时，通过查找**动作和按钮的对应关系**确定玩家渴望的动作类型
- 对应关系由游戏可玩性模式的**交互模型**确定

### 机制触发流程
1. UI检测输入设备数据
2. 查找动作-按钮映射关系
3. AI触发为该动作指定的特定机制

### 机制执行示例：蹲伏动作

**属性变更1：姿势状态**
- 改变化身的符号姿势属性（从直立行走变为蹲伏状态）
- **重要限制**：蹲伏机制本身不能实现连锁影响（如目标大小变化），仅负责状态变更本身

**属性变更2：视觉反馈**
- 降低化身的头高度属性（确定头高于地面的距离）
- 目的：提供动作反馈（所有动作都应该有反馈伴随）

**渲染反馈**
- 图像引擎检测到头高度变化后，从蹲伏视角显示第一人称视野

### 约束
机制本身不能实现由状态变更引起的连锁影响，仅负责触发状态变更本身
