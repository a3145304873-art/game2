# 角色设计方法论

## 使用场景
- 游戏处于角色设计初期阶段
- 需要确定角色的设计起点（视觉优先还是叙事优先）
- 需要为角色命名和定义核心特征
- 角色需要跨媒体商业化开发

## 设计方法选择

### 艺术驱动角色设计
**适用条件：**
- 角色相对简单，行为和视觉在游戏过程中改变不多
- 游戏风格为卡通类
- 需要角色在游戏外媒体（玩具、漫画）上有价值
- 设计者倾向于视觉设计

**设计流程：**
1. 从角色的视觉外表开始创建
2. 优先关注视觉呈现效果
3. 适用于简单角色和卡通风格游戏

**不适用场景：**
- 第一人称视角不可见的指定化身（如戈登·弗里曼）
- 无实体角色（仅通过耳机、心灵感应沟通）
- 需要深度故事驱动的复杂角色

### 故事驱动角色设计
**适用条件：**
- 角色需要深度和沉浸感
- 视觉外表无法传达所有角色信息（作用、行为、与核心机制的交互）
- 需要定义角色的背景故事或行为逻辑

**设计流程：**
1. 以角色的作用、个性和行为作为设计起点
2. 确定深层属性："这个角色是谁"、"他的行为方式是什么样的"
3. 为艺术人员提供详细描述（作用、个性、行为）
4. 让艺术人员基于描述开发身体外貌
5. 重视角色之间的交互，这是故事中最有趣的方面

## 角色命名与特征设计

### 特征数量控制
- 限制角色特征数量为 **2-3个** 即可
- 警告：特征数量过多会让角色看起来"可笑"

### 命名策略

**显眼名字（卡通风格）：**
- 示例：迪恩·马涅利、伊兹·霍恩、"先生"法弥尔
- 效果：反映种族多样化，但具有"卡通类样式"
- 适用：需要卡通风格的游戏
- 约束：如果游戏目标是"真实性"，避免使用此类名字

**含蓄名字（真实风格）：**\- 名字不需要清楚表达个性
- 可使用昵称暗示个性（如西尔维斯特→Sly）
- 名字可暗示社会阶层或气质（如劳拉·克劳馥→英国上层人气质）

## 设计决策检查清单
- [ ] 确定角色复杂度（简单/复杂）
- [ ] 确定游戏风格（卡通/写实）
- [ ] 评估跨媒体价值需求
- [ ] 选择设计方法（艺术驱动/故事驱动）
- [ ] 定义2-3个核心特征
- [ ] 选择符合目标风格的命名方式
