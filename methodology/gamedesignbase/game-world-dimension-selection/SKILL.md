# 游戏世界维度选择

## 使用时机
- 设计包含战术机动的游戏空间
- 需要定义游戏世界的物理空间特性
- 评估现有游戏空间设计方案
- 决定游戏采用2D、2.5D、3D还是4D实现

## 维度选择决策流程

### 第一步：排除不适用场景

**无需物理空间模拟的游戏**
- 纯抽象游戏（如某些卡牌游戏、文字游戏）不涉及战术机动空间设计
- 此类游戏跳过维度选择流程

### 第二步：默认选择2D或2.5D

**历史验证原则**
- "涉及战术机动的绝大多数游戏都是2D或2.5D的"
- 三维棋盘游戏"从来没有像它们的2D对手那样流行"
- 原因："常规棋类游戏的复杂性已经足以管理"，3D会叠加额外认知负担

**2D特征**
- 角色可在平面内移动，但不能向玩家方向（出屏幕）或反方向（进屏幕）移动
- 典型应用：2D滚屏游戏，如《波斯王子经典版》
- 核心优势：二维世界直接对应显示器屏幕的两个维度，无需考虑深度概念传递

**2.5D特征**
- 看起来是三维空间，实际包含一系列重叠的二维图层
- 水平方向：物体可精确地在屏幕内水平移动
- 纵向：物体必须在一个或另一个平面上，平面中间无内容
- 飞行物限制：不能在空中上下移动，只能在空气层里
- 典型应用：《星际争霸》

### 第三步：评估3D维度适用性

**受限3D（表面3D但实际受限）**
- 案例：《柏拉图之柱》（方垛式四子棋）
- 特征：
  - 必须从最底层开始放置
  - 本质是"机动的游戏"而非"类似3D版本的井字游戏"
  - 玩家没有完全的自由

**完全3D实时机动（极窄范围）**
- **仅适用于**：空中战斗 或 空间战斗
- **地面战术游戏**：不适用完全3D机动

**3D太空战斗（无重力）的特殊复杂性**
- 控制区域形态：从2D的圆形扩展为3D的球形
- 巡航复杂性显著增加
- 与空中作战的关键区别：
  - 空中作战有重力约束（"空中交通工具的机动性受到他们为维持升力的补给的限制"）
  - 太空无此约束
- 战术目标差异：
  - 空中作战："消灭敌机而不是控制领土"
  - 拦阻气球：仅作为"控制领土的暂时手段"

### 第四步：评估4D维度适用性

**关键建议**
- 不要作为真正的4D空间实现
- 作为3D的可选择版本实现

**实现方式**
- 创造两个（或多个）三维空间，使其看起来相似，但随着角色移动提供不同经历

**典型案例：《凯恩的遗产》系列**
- 两个3D世界：鬼怪领域和物质领域
- 背景相同，但：
  - 物质世界：被白色灯光照亮
  - 鬼怪世界：蓝色灯光，建筑物歪曲
- 可用操作不一样
- 规则：看起来相似，但用不同的规则统治的不同地方

### 第五步：核心原则验证

**禁止性错误**
- 不要因为三维看起来更真实，或者最大限度地利用了机器硬件，就立即假定选择三维

**核心准则**
- 物理空间维度必须服务于游戏的娱乐价值
- 确保每个维度都能得到合理利用

**反面案例警示**
- 《疯狂小旅鼠》(Lemmings)：非常成功的2D游戏
- 《疯狂小旅鼠3D》：3D版本非常不成功，因为玩起来太难了
- 失败原因：加入的第三维度不仅没能增添玩家的乐趣，反而起到了相反的作用

## 地形高度设计（适用于2D/2.5D地面游戏）

**基础形态**
- 完全平坦（如棋盘）

**进阶形态**
- 高度略有变化

**高度优势规则**
- "较高的区域通常会提供战术上的优势"

## 关键变量

| 变量名 | 类型 | 描述 |
|--------|------|------|
| game_genre | string | 游戏类型：棋盘游戏/实时战术/空中战斗/太空战斗 |
| mobility_type | string | 机动类型：地面/空中/太空 |
| gravity_presence | boolean | 是否存在重力（影响3D机动复杂度） |
| control_area_shape | string | 控制区域形状：圆形(2D)/球形(3D) |
| terrain_elevation | string | 地形高度设计：平坦/有高度变化 |

## 输出结果

推荐的游戏空间维度（2D/2.5D/受限3D/完全3D）及关键设计约束，包括：
- 控制区域几何形态
- 地形高度策略
- 重力机制影响
- 娱乐价值验证
