# 鼠标相对/绝对数据模式转换

## 概述
鼠标硬件原生输出相对位移数据（相对于上一位置的移动距离），但屏幕光标控制需要绝对坐标数据（屏幕像素位置）。本技能指导如何在驱动层或应用层执行数据模式转换，并根据交互需求选择合适的工作模式。

## 适用场景
使用此技能当需要：
- 实现鼠标驱动软件，处理硬件原始输入数据并映射到屏幕坐标系
- 开发游戏输入系统，区分FPS视角控制（相对模式）与UI光标定位（绝对模式）
- 处理跨平台输入适配，对接不同操作系统API的坐标映射需求
- 排查光标漂移、坐标偏移或输入模式冲突问题

## 核心工作流程

### 1. 检测原始数据
监听鼠标硬件持续输出的相对位移数据（`raw_relative_data`），格式为二维向量（X轴/Y轴位移增量，单位：mickeys或counts）。

### 2. 评估转换需求
判断当前交互场景：
- **IF** 鼠标用于控制屏幕光标（GUI操作、点击）→ **启动绝对模式转换流程**
- **IF** 鼠标用于控制游戏视角（FPS相机、3D旋转）→ **保持相对模式，直接传递原始数据给应用逻辑**

### 3. 执行数据转换（绝对模式）
当选择绝对模式时，驱动软件执行以下转换：
- 将相对位移增量累加到当前光标位置基准
- 映射到屏幕坐标系（Screen Coordinates），生成绝对坐标（`cursor_absolute_position`）
- 约束坐标值在有效屏幕边界内（0 ≤ X ≤ 屏幕宽度，0 ≤ Y ≤ 屏幕高度）

### 4. 配置工作模式
显式设置 `mode_selection` 参数：
- **相对模式（Relative Mode）**：直接传递位移增量，不维护绝对位置状态，支持无限旋转
- **绝对模式（Absolute Mode）**：驱动层维护坐标状态机，输出屏幕像素坐标

### 5. 应用模式特定逻辑
**相对模式适用场景**：
- FPS游戏视角旋转（无边界限制，支持360°无限旋转）
- 3D建模软件相机轨道控制
- 飞行模拟器方向舵控制

**绝对模式适用场景**：
- 操作系统GUI光标定位
- 游戏内菜单/背包/地图界面操作
- 绘图软件画布光标定位

### 6. 区分应用层数据类型
确保应用架构明确区分数据来源：
- **原始相对数据**：用于相机控制、物理计算、相对运动逻辑
- **驱动转换后的绝对数据**：用于UI渲染、点击检测、屏幕边界碰撞检测

## 关键变量定义
- `raw_relative_data` (Vector2): 鼠标硬件输出的原始相对位移
- `cursor_absolute_position` (Vector2): 转换后的屏幕绝对坐标（像素单位）
- `mode_selection` (Enum): 工作模式选择（`RELATIVE` | `ABSOLUTE`）

## 约束与前提条件
- **驱动层支持**：确认操作系统允许驱动层拦截和转换输入数据（如Windows的Filter Driver或Linux的evdev）
- **API可用性**：检查目标平台是否提供原始输入API（如Raw Input、DirectInput）或仅提供已转换的绝对坐标
- **硬件检测**：确保鼠标硬件正确检测并报告相对位移事件

## 常见陷阱与解决方案
- **双重转换错误**：避免应用层在驱动已输出绝对数据后再次进行坐标转换，导致光标加速异常
- **边界处理不一致**：相对模式下应忽略屏幕边界，绝对模式下必须实现边缘约束（如指针吸附、屏幕环绕或边界钳制）
- **模式混淆**：游戏开发中严格分离游戏世界相机控制（订阅相对数据）与UI系统（订阅绝对数据），避免单帧内数据类型混用
- **坐标系方向**：确认屏幕坐标系原点在左上角（Y轴向下）与鼠标位移方向（Y轴向上通常为负）的映射关系
