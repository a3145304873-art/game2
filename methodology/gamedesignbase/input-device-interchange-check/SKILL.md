# 输入设备互换验证

## 使用场景
当需要实现以下功能时使用此技能：
- 允许玩家互换两个输入设备的控制映射
- 实现灵活的游戏控制配置系统
- 评估不同输入设备之间的兼容性

## 验证步骤

### 步骤1：检查信号类型兼容性
验证两个设备的信号类型是否一致：
- 两个设备必须都是数字信号或都是模拟信号
- 如果信号类型不匹配，设备不可互换

### 步骤2：验证自由度匹配
计算并比较两个设备的自由度（DOF）：
- 按键/按钮：自由度为1
- 操纵杆/鼠标：自由度为2
- Wii遥控器等：自由度为3
- 自由度必须相同才能互换

### 步骤3：检查自中心特性
验证两个设备的自中心特性是否一致：
- 自中心设备：释放后自动回到中心位置（如模拟摇杆）
- 非自中心设备：释放后保持当前位置（如某些数字方向键）
- 特性不一致可能导致操作困难

### 步骤4：验证移动限制
检查两个设备的移动限制是否一致：
- 无限制移动：可以无限向某个方向移动（如鼠标）
- 有限制移动：有物理边界限制（如摇杆）
- 限制不一致可能导致操作困难

### 步骤5：评估功能映射完整性
分析互换后是否会丢失功能或便利性：
- 检查所有功能是否都能正确映射
- 识别可能丢失的辅助功能

## 决策输出

根据以上检查结果，输出以下决策之一：
- **可互换**：所有条件满足，设备可以安全互换
- **有风险可互换**：基本条件满足但存在操作风险，需要警告用户
- **不可互换**：基本条件不满足，禁止互换

## 风险提示
当以下情况存在时，即使设备可以互换，也可能出现操作困难：
- 自中心特性不匹配
- 移动限制不匹配
- 功能映射不完整
