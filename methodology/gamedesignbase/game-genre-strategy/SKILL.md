# 基于开发背景的游戏类型选择策略

## 何时使用

- 开始游戏概念设计，需要确定类型方向
- 评估创新自由度与商业风险的平衡
- 菜鸟设计师选择入门项目类型
- 为大型出版商工作时的类型决策

## 开发者类型判断与策略选择

### 路径A：学生或独立开发者

**策略**：定义玩家的角色，考虑该角色可以使用的操作。

**优势**：
- 最大灵活性
- 允许创建任何喜欢的游戏类型
- 不受现有类型框架限制

### 路径B：大型常规出版商

**策略**：做适合现有类型的游戏。

**原因**：
- 发行商投资规模与保守程度正相关
- 高投资风险导致对成熟类型的依赖

## 经验水平调整

### 菜鸟阶段特殊规则

**建议**：先进行射击游戏或赛车游戏等**知名类型**的创作。

**原因分析**：
- 这些类型"根据它们的挑战来定义"
- 游戏中自然有一套相当标准的行为
- 玩家对同类型游戏有互通性期望

**效果**：提供早期设计过程的捷径，减少设计不确定性。

## 类型定义核心原则

| 原则 | 说明 |
|-----|------|
| 挑战定义类型 | 游戏类型本质上由"挑战"定义 |
| 标准行为集合 | 同类型游戏存在标准行为集合 |
| 互通性期望 | 玩家对同类型游戏有互通性期望 |

## 决策流程图

```
开始概念设计
    ↓
开发者类型？
    ├── 独立/学生 → 创新角色定义策略
    │                 └── 自由创建任何类型
    └── 出版商雇佣 → 现有类型适配策略
                      └── 投资规模越大，创新自由度越低
    ↓
经验水平？
    └── 菜鸟 → 优先选择射击/赛车等已知类型作为设计捷径
```

## 输出标准

确定采用以下策略之一：
- 【创新角色定义】策略
- 【现有类型适配】策略
- 【菜鸟优先：射击/赛车等已知类型】

## 约束条件

- 出版商投资规模越大，类型创新自由度越低
- 菜鸟阶段应避免过度创新的类型定义
