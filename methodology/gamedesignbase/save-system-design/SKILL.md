# 存档系统设计

## 关卡访问代码（密码系统）

### 适用场景

- 无存储器设备（复古硬件）
- 复古风格游戏
- 特定平台限制

### 术语规范

使用"**关卡访问代码**"代替"密码"，避免与现代登录密码混淆。

### 工作流程

```
完成关卡 → 生成并显示代码 → 记录代码
                    ↓
游戏启动 → 询问是否输入代码 → 验证 → 加载对应关卡
```

### 功能特性

- 跳转到指定关卡，无需重玩前置关卡
- 允许回到之前已完成的任何关卡重新开始
- **局限**：不适用于关卡中间保存进度

## 复活惩罚机制

### 核心设计

复活时失去"存储的"金钱、工具、衣服和清单物品。

### 变异性设置

失去财产的数量和后果根据游戏设计大幅变化。

### 安全存储机制

| 要素 | 说明 |
|-----|------|
| 地下室/仓库 | 游戏中安全存放不需要随时携带的物品 |
| 安全保障 | 存放物品在复活后保留 |
| 容量限制 | 防止无限囤积 |

### 防滥用设计

**风险**：玩家创建第二个不玩游戏的"骡子"角色专门保存物品（常见于MMOG）

**对策**：
- 设计合理的安全存储容量
- 限制角色间物品转移
- 绑定关键物品至角色
