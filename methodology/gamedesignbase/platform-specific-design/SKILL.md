# 平台特定设计考虑

## 何时使用
- 游戏平台被识别为个人计算机(PC)
- 涉及便携式设备的设计、开发、评估
- 设计用户界面
- 设计输入控制系统
- 处理音频控制
- 管理游戏进度保存

## 执行步骤

### 1. 识别平台类型

**个人计算机(PC)包括：**
- 运行 Windows 的 IBM PC
- 麦金托什机
- 运行 Linux 的机器
- 笔记本电脑
- 平板设备

**便携设备包括：**
- 便携式游戏设备
- 移动电话
- 平板设备
- 联网手持设备

### 2. 应用PC平台设计原则

**物理环境设置：**
- 位置：通常远离公共生活空间，放置在桌子上
- 姿态：玩家坐在设备面前进行管理
- 便携性限制：虽然笔记本便携，但通常仍需在桌上使用

**输入控制设备：**
- 标准配置：键盘（方便输入文本）、鼠标（允许精确指向和更复杂的用户界面）
- 扩展配置：可能包含操纵杆
- 特殊情况：很少使用专用的游戏控制器（如手柄）

**显示与视觉参数：**
- 屏幕距离：玩家坐在距离高分辨率显示器 12 至 18 英寸远的地方
- 图形能力：高分辨率意味着游戏可以包含微小、详细的图形

**沉浸感增强技术：**
- 多屏幕设置：玩家可能添加额外的左右屏幕
- 功能：显示游戏世界的一部分及周边视角
- 优势：帮助在赛车游戏和在线多人游戏中更好地看到对手

**使用模式限制：**
- 用户数量：PC 控件是为个体设计的，每次通常仅供一人使用
- 社交隔离：设计上倾向于孤立使用

### 3. 应用便携设备设计原则

**屏幕与用户界面（UI）设计：**
- 视觉距离：由于手持使用，用户的眼睛比使用任何其他设备时离屏幕都更近
- 屏幕限制：屏幕尺寸是关键限制，不同制造和型号的屏幕分辨率差异很大
- UI 要求：用户界面必须非常简单和清晰，甚至应比在大电视屏幕上显示的控制台游戏更简单

**音频控制要求：**
- 公共场合使用：由于经常在公共场合使用，每个游戏必须包含一种关闭声音的方式
- 原因：玩家可能需要关闭主音量以听到传入的短信或电话通知，同时关闭游戏声音以防止影响周围的人

**电池寿命与游戏机制：**
- 资源消耗：游戏往往是 CPU 和图形密集型应用程序，电池寿命会限制使用时长
- 保存机制：不能指望玩家长时间游戏，游戏必须允许在任何时候保存进度

**物理尺寸与便携性：**
- 尺寸范围：从非常小的移动电话到接近膝上型笔记本大小的平板计算机
- 便携性判断：关键在于设备是否适合放于口袋中
  - 适合口袋：几乎可以去任何地方
  - 不适合口袋：用户必须使用钱包、公文包或背包携带

## 设计检查清单

### PC平台
- [ ] 适配键盘鼠标操作
- [ ] 支持近距离高分辨率显示
- [ ] 设计单人使用模式
- [ ] 考虑多屏幕设置可能性
- [ ] UI支持精确指向和复杂交互

### 便携设备
- [ ] UI简单清晰
- [ ] 提供关闭声音的方式
- [ ] 支持随时保存进度
- [ ] 考虑电池寿命限制
- [ ] 适配不同屏幕分辨率
- [ ] 考虑手持使用距离
