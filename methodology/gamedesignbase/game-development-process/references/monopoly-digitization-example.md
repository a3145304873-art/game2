# 《大富翁》电子化文档化示例

## 纸质规则缺陷

Parker Brothers发行的游戏规则仅用不到三页纸，缺乏构建计算机游戏所需的完整数据文档。

## 必须补充的文档内容

### 1. 财产价格数据

必须包含棋盘上所有财产（不动产）的具体价格数据，而不仅仅是规则说明。

**示例数据结构**：
| 位置名称 | 颜色组 | 购买价格 | 房屋价格 | 酒店价格 |
|---------|--------|---------|---------|---------|
| 地中海大道 | 棕色 | $60 | $50 | $50 |
| 波罗的海大道 | 棕色 | $60 | $50 | $50 |
| 东方大道 | 浅蓝色 | $100 | $50 | $50 |
| ... | ... | ... | ... | ... |

### 2. 详细化租金计算规则

必须定义每一个位置可能收取的不同数量的租金，特别注意铁路和公共实业等特殊位置的非标准租金计算机制。

**标准房产租金计算**：
- 无房屋：基础租金
- 1栋房屋：租金A
- 2栋房屋：租金B
- 3栋房屋：租金C
- 4栋房屋：租金D
- 酒店：租金E

**特殊位置租金**：

**铁路**：
- 拥有1条铁路：$25
- 拥有2条铁路：$50
- 拥有3条铁路：$100
- 拥有4条铁路：$200

**公共实业**：
- 拥有1个实业：骰子点数 × 4
- 拥有2个实业：骰子点数 × 10

### 3. 棋盘布局

必须精确文档化棋盘的完整布局，包括所有位置的空间关系和路径连接。

**数据结构示例**：
```
位置列表（按顺序）：
0. 起点（GO）
1. 地中海大道
2. 社区公益金
3. 波罗的海大道
4. 所得税
5. 南方铁路
...
39. 著名大道
40. 去监狱
```

### 4. 卡片效果完整定义

必须详细说明所有偶然性和公益金卡片的具体作用机制。

**偶然性卡片示例**：
| 卡片ID | 效果描述 | 具体数值 |
|-------|---------|---------|
| 1 | 前往最近的铁路 | 移动到位置5、15、25或35 |
| 2 | 银行给你分红 | 获得$50 |
| 3 | 前往伊利诺伊大道 | 移动到位置24 |
| 4 | 支付医院费用 | 失去$100 |
| ... | ... | ... |

### 5. 验证文档完整性

最终的核心机制详细说明必须比一般规则详细很多，确保包含玩游戏必需的所有数据，足以支撑计算机程序的实现。

**完整性检查清单**：
- [ ] 所有财产价格数据
- [ ] 所有租金计算公式
- [ ] 特殊位置规则
- [ ] 棋盘完整布局
- [ ] 所有卡片效果
- [ ] 玩家初始资金
- [ ] 经过起点奖励
- [ ] 入狱规则
- [ ] 破产条件
- [ ] 胜利条件
