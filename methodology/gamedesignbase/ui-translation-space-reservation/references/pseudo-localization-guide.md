# 伪本地化测试指南

## 什么是伪本地化

伪本地化（Pseudo-localization）是一种测试技术，通过将原始文本替换为扩展后的伪文本，模拟翻译后的效果，用于验证UI的本地化适应性。

## 伪本地化方法

### 1. 字符扩展法
在每个字符前后添加特殊字符，通常扩展30-50%：

```
原文: "Save"
伪本地化: "[S~a~v~e~]"
```

### 2. 长度倍增法
将文本长度增加指定比例（如30%）：

```
原文: "Submit"
伪本地化: "Submitxxxxx"
```

### 3. 特殊字符注入法
添加可能引起问题的特殊字符：

```
原文: "File not found"
伪本地化: "File ñôt fôùñd [!!!]"
```

## 测试流程

### 步骤1: 准备测试环境
- 创建伪本地化资源文件
- 配置应用加载伪本地化文本

### 步骤2: 执行测试
- 遍历所有UI界面
- 检查每个文本元素的显示

### 步骤3: 问题记录
- 记录文本截断位置
- 记录布局重叠区域
- 记录溢出问题

### 步骤4: 修复验证
- 调整UI布局
- 重新执行伪本地化测试

## 常见问题检测

### 文本截断
- 按钮文本被截断
- 菜单项显示不完整
- 标签文字被切断

### 布局重叠
- 文本与相邻元素重叠
- 多行文本覆盖其他内容
- 图标与文字冲突

### 布局溢出
- 文本超出容器边界
- 滚动条意外出现
- 页面布局破坏

## 工具推荐

### 在线工具
- Pseudolocalize.com
- Localize.js

### 开发工具
- Android Studio: 伪本地化测试
- Xcode: 伪本地化支持
- .NET: PseudoLocalizer类

## 最佳实践

- 在设计早期进行伪本地化测试
- 使用多种扩展比例测试（30%、50%、100%）
- 结合实际语言测试验证
- 将伪本地化测试纳入CI/CD流程
