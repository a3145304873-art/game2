# 投诉与警告机制

管理即时通讯软件和在线游戏聊天中的用户不当行为，通过人工审核和自动系统实施分级惩罚。

## 何时使用

- 用户举报冒犯性信息或不当行为时
- 需要配置自动化的社区管理系统（AIM模式）
- 设计用户行为管理策略和惩罚机制
- 处理客服转交的违规投诉案件
- 需要实施渐进式惩罚（从限速到禁言到封号）

## 人工举报处理流程

适用于文字举报的详细调查场景（必须人工介入）：

1. **发起举报**
   - 玩家/用户点击举报按钮，针对特定冒犯信息进行投诉
   - 系统自动记录被举报内容、时间和上下文

2. **人工审核**
   - 文字信息自动转发给当值网络客服
   - 客服调查核实违规情况（确认是否违反社区准则）

3. **执行处罚**
   根据违规严重程度选择措施：
   - **警告**：向冒犯者发送系统警告通知
   - **要求改正**：责令用户停止不当行为
   - **踢下线**：强制断开用户连接
   - **封号**：永久或长期禁止账户使用

## 自动警告系统（AIM模式）

适用于高频、实时的行为管理，支持用户间匿名或公开警告：

### 触发条件
- 用户接收到足够数量的匿名或公开警告（来自其他用户）
- 系统检测到异常行为模式

### 惩罚机制

**频率限制（限速）**
- 根据 `warning_count`（警告次数）动态调整
- 警告越多，`message_frequency_limit`（信息频率限制）越低
- 实施渐进式通信限制

**暂时禁言**
- 当投诉达到阈值时，执行 `ban_duration`（通常数小时）的禁言
- 禁止用户在特定时间段内发送任何信息

**恢复机制**
- 若用户在观察期内纠正行为，发送权限自动恢复正常
- 系统逐步解除频率限制

### 记录管理

**衰减机制**
- 投诉记录和警告历史随时间推移自动删除
- 坏行为不会被永久记录，给予用户改过机会
- 定期清理历史数据以维护系统性能

## 关键参数配置

| 参数 | 类型 | 说明 |
|------|------|------|
| `warning_count` | Integer | 用户累计收到的警告次数，决定惩罚等级 |
| `message_frequency_limit` | Float | 每分钟/每小时允许发送的信息数量，随警告增加而降低 |
| `ban_duration` | Time | 暂时禁言的持续时间，通常为数小时（如2-24小时） |
