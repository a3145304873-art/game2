# 游戏实体与资源数据建模

## 何时使用

- 从游戏概念提取名词列表并分类
- 定义游戏机制中的数据结构和数值关系
- 设计实体属性系统和资源流动规则

## 核心概念区分

| 概念 | 定义 | 示例 |
|-----|------|------|
| **资源** | 玩家可移动/交换的物体**类型**，作为数字量处理 | "弹球"类别、"分数"概念 |
| **实体** | 资源的**具体实例**或游戏元素的状态 | 玩家口袋中的15个弹球、某队得分值 |
| **简单实体** | 单一数据值描述 | 风的速度（数字）、方向（符号） |
| **复合实体** | 多个数据值/属性描述 | 队伍（名字+主场+统计资料+运动员集合） |

## 实体定义流程

### 步骤1：名词列表分类
对每项判定：
- [ ] 资源（可变条目/物质）
- [ ] 独立实体（特殊值/量）
- [ ] 另一实体的属性
- [ ] 无关项（划去）

### 步骤2：简单实体定义
- **符号类型**：确定可拥有的状态
- **数字类型**：确定数值范围
- **设定初始值**：记录为核心机制组成部分

### 步骤3：复合实体定义
1. 识别描述该实体的属性
2. 添加新属性到定义
3. 回到步骤2确定这些属性的量

### 步骤4：特殊强制检查
- 除非游戏仅有一种可玩性模式且无shell菜单，否则**必须**包含记录当前模式的实体

### 步骤5：细节具体化
将一般性描述转化为具体实体：
- 设计说明："关卡5由形式逻辑谜题组成"
- 具体实体：方块（位置属性）、开关（状态属性）、弹球（颜色属性）

## 复合实体三层结构

```
第三层：复合实体（含复合属性）
  └── 队伍
      ├── 名字（简单属性）
      ├── 主场（简单属性）
      ├── 统计资料（简单属性）
      └── 运动员集合（复合属性）
          └── 每个运动员：速度、灵活性等

第二层：复合实体（仅简单属性）
  └── 风
      ├── 速度（数字）
      └── 方向（符号）

第一层：简单实体
  └── 无属性，最基本元素
```

## 资源物理形态分类

| 类型 | 特征 | 示例 |
|-----|------|------|
| 离散型 | 单独个体操作 | 弹球、金币 |
| 连续/不可分型 | 容积等单位测量 | 水、燃料 |
| 抽象概念型 | 非物理概念量化 | 流行度、魔法值、战斗力 |

## 核心机制记录规范

### 机制组成要素
- **算法**：决定游戏如何运行的规则和流程
- **数据**：被操作和追踪的数值、状态
- **资源**：可获取、消耗、转换的游戏元素
- **实体**：简单实体、复合实体
- **事件**：触发机制的条件
- **过程**：随时间或操作执行的序列
- **条件**：机制生效的限制

### 机制分类
| 类型 | 运行规则 | 多模式游戏要求 |
|-----|---------|-------------|
| 全局机制 | 整个游戏过程始终运行 | **必须**至少一个，用于管理模式切换 |
| 特定模式机制 | 仅在特定可玩性模式下起作用 | — |

### 实体关系定义
- 若实体值依赖其他实体值/状态，必须说明关系
- 数字实体必须用数学方法表示关系
- 关系性质不变时，无需指定计算时机，由程序员决定实现
