# 文本游戏设计

设计纯文本交互体验，适用于无法或无需图形渲染的场景。

## 何时使用

- 目标设备仅有文本显示能力（打印终端、命令行界面）
- 目标用户包含盲人玩家，需配合文本语音合成器使用
- 设备资源受限（早期计算机、小型手机屏幕、低处理能力硬件）
- 游戏类型为智力题、小游戏或交互小说

## 设计流程

### 1. 评估适用性
确认以下至少一项条件成立：
- [ ] 显示类型为纯文本（`display_type = text_only`）
- [ ] 目标用户包含盲人（`target_user = blind`）
- [ ] 设备存在严重资源限制（`device_constraint = true`）

若条件不满足，停止文本游戏设计，改用图形化方案。

### 2. 架构内容结构
基于文本媒介特性设计信息架构：
- **空间描述**：使用文字建立场景拓扑关系（方位、距离、连接性）
- **状态反馈**：通过文本状态栏显示关键变量（生命值、物品栏、位置）
- **叙事分支**：设计基于输入指令的剧情树（动词+名词解析系统）

### 3. 设计交互机制
构建命令行式交互或菜单式交互：
- **解析器设计**：实现自然语言解析（如 "take lamp", "go north"）
- **输入简化**：为移动设备提供缩写指令或数字菜单选项
- **反馈即时性**：确保每次输入后提供明确的文本反馈

### 4. 配置无障碍支持（针对盲人玩家）
若 `target_user` 包含盲人：
- **语音合成集成**：确保所有文本输出可通过 TTS 引擎朗读
- **音频线索**：添加非语音音频提示（环境音、操作确认音）
- **导航辅助**：提供快捷键跳过重复文本、快速定位关键信息

### 5. 验证技术约束
检查以下限制条件：
- [ ] 避免依赖图形显示能力的谜题（如颜色匹配、图形模式识别）
- [ ] 控制文本量以适应小型屏幕分页显示
- [ ] 确认文本渲染性能在目标设备上可接受

## 输出模板

完成设计后，确认游戏方案满足：
```
IF (设备限制=真 OR 目标用户=盲人 OR 游戏类型∈{智力题,小游戏,交互小说}) 
THEN 采用文本游戏方案
ELSE 考虑图形化替代方案
```

## 注意事项

- 大型复杂游戏可能受限于纯文本表现形式，考虑分章节发布或简化机制
- 交互小说虽在商业市场衰退，但在爱好者社区（hobbyist communities）仍有受众，需明确目标市场
- 针对盲人的试验性语音游戏（audio games）可作为文本游戏的进阶形态探索
