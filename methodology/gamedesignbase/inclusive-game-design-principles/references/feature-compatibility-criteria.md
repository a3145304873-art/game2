# 功能兼容性评估标准

## 评估维度

### 1. 核心玩法兼容性

**高兼容**
- 动作 + RPG：战斗与角色成长结合
- 策略 + 模拟：资源管理与决策结合

**中兼容**
- 动作 + 解谜：需要精心设计节奏
- 策略 + 动作：需要平衡思考与反应

**低兼容**
- 纯动作 + 纯策略：节奏冲突严重
- 模拟 + 竞技：目标导向冲突

### 2. 操作模式兼容性

**兼容条件**
- 操作方式不冲突
- 控制方案可统一
- 学习曲线合理

**冲突示例**
- 需要复杂操作 + 需要快速反应
- 精确操作 + 宽松操作

### 3. 目标导向兼容性

**兼容条件**
- 长期目标与短期目标一致
- 不同玩法服务于同一核心体验

**冲突示例**
- 竞技目标 + 合作目标
- 探索目标 + 效率目标

### 4. 节奏兼容性

**兼容条件**
- 不同玩法的节奏可协调
- 玩家可自主控制节奏切换

**冲突示例**
- 高强度战斗 + 慢节奏经营
- 快速决策 + 长时间等待

## 评估流程

1. **列出所有拟整合功能**
2. **两两配对评估兼容性**
3. **识别核心冲突点**
4. **评估冲突是否可解决**
5. **决策：整合/分离/移除**

## 风险阈值

- **低风险**：1-2个核心玩法，兼容性高
- **中风险**：3个核心玩法，存在可解决冲突
- **高风险**：4个以上核心玩法，或存在根本性冲突

## 决策建议

**高风险场景**
- 缩减功能范围
- 专注于1-2个核心玩法
- 其他功能作为辅助或DLC

**中风险场景**
- 优化整合方案
- 解决核心冲突
- 加强玩法衔接设计
