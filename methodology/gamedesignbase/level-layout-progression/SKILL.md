# 关卡布局与进展机制设计

## 何时使用
- 设计关卡空间结构时
- 构建游戏事件序列时
- 设计玩家体验流程时
- 需要提供路径选择但保持整体方向性时

## 平行布局核心结构与玩家行为模式

### 核心结构定义

- 平行布局是线性布局的现代变种
- 采用铁路调车场隐喻
- 包含多条平行轨道，玩家可在轨道间切换

### 玩家移动模式

- 玩家从关卡一端移动到另一端
- 但可通过多种路径到达终点
- 形成"多轨道并行+横向切换"的流动体验

### 探索行为特征

- 虽然平行布局不要求玩家通过每条可用路径
- 但如果游戏机制允许
- 大部分玩家会自发寻找并尝试所有路径以完成探索

### 路径切换机制

- 设计必须提供明确或隐晦的方式
- 让玩家能够"不时地从一个轨道切换到另一轨道"
- 保持布局的平行特性而非完全分离的独立通道

## 游戏进展机制设计与验证流程

### 定义核心进展机制类型

- 从空间、时间和情节三种基本机制中选择或组合
- 目的是创建设计者预定的事件序列
- 区别于规则操作产生的涌现型事件

### 扩展机制功能（可选）

**可选挑战序列**
- 提供额外奖励供玩家克服

**平衡的选择**
- 设计需要高技能的捷径（环境挑战）
- 与需要较少技能的更长路径

**难度分级**
- 允许玩家选择容易、中等或困难的序列

**互斥方法**
- 设计一个玩家的选择会排除其他玩家的选项

### 记录与验证（关键步骤）

**必须详细记录**
- 所有想要的进展机制

**一旦在游戏中定义好**
- 必须进行试玩测试
- 确保机制能正常运转

## 设计决策流程

### 平行布局设计

1. **确定起点和终点**：明确关卡的开始和结束位置
2. **设计平行路径**：创建多条从起点延伸至终点的并行通道
3. **设置切换点**：在关键位置设置横向连接点允许玩家切换路径
4. **平衡路径难度**：确保不同路径的难度和奖励平衡
5. **测试探索体验**：验证玩家能否发现并尝试所有路径

### 进展机制设计

1. **选择进展类型**：从空间、时间、情节中选择或组合
2. **设计可选内容**：添加可选挑战、捷径、难度分级等
3. **记录机制细节**：详细记录所有进展机制的设计
4. **进行试玩测试**：验证机制是否正常运转
5. **迭代优化**：根据测试结果调整和优化机制

## 设计检查清单

### 平行布局
- [ ] 有明确的起点和终点
- [ ] 包含多条并行路径
- [ ] 提供路径切换机制
- [ ] 路径难度和奖励平衡
- [ ] 鼓励玩家探索所有路径

### 进展机制
- [ ] 明确的进展类型（空间/时间/情节）
- [ ] 详细的设计文档
- [ ] 完整的试玩测试
- [ ] 机制正常运转
- [ ] 提供可选挑战和选择
