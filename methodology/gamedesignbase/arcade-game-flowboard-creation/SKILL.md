# 街机游戏流程板创建

## 何时使用此技能

- 执行游戏设计练习2（Exercise 2）
- 需要可视化经典街机游戏的整体结构
- 分析游戏模式（gameplay modes）之间的关系
- 教学演示如何分解游戏系统架构
- 为含少量模式和菜单的街机游戏制作流程文档

## 执行步骤

### 步骤1：选择合适的街机游戏

选择符合以下标准的游戏：
- **经典且著名**（classic & famous arcade game）
- **结构简单**：仅含少量游戏可玩性模式（few gameplay modes）
- **菜单简洁**：shell菜单数量少
- **避免**：结构复杂的现代游戏（如开放世界、大量子系统）

**验证清单**：
- [ ] 能否在5分钟内口头描述完整游戏循环？
- [ ] 游戏模式是否≤5个？
- [ ] 菜单层级是否≤2层？

### 步骤2：识别核心元素

提取并列出：

| 元素类型 | 具体内容 | 示例（以《吃豆人》为例）|
|---------|---------|------------------------|
| 游戏可玩性模式 | 实际游玩状态 | 普通模式、追逐模式、奖励模式 |
| Shell菜单 | 非游玩界面 | 标题画面、高分榜、投币提示 |
| 状态转换 | 触发条件 | 吃光豆子→关卡完成、被鬼抓到→游戏结束 |
| 关键节点 | 开始/结束/暂停 | 投币开始、生命耗尽、暂停菜单 |

### 步骤3：创建流程板结构

绘制可视化图表，包含：

1. **层级布局**
   - 顶部：Shell菜单（标题、设置等）
   - 中部：游戏可玩性模式（核心循环）
   - 底部：结束状态（游戏结束、通关）

2. **连接关系**
   - 使用箭头标明玩家流动方向
   - 标注转换条件（如"按开始键"、"生命=0"）
   - 用不同线型区分：正常流程 vs 异常分支

3. **游戏循环可视化**
   - 用循环箭头表示核心玩法的重复性
   - 标明得分、难度递增等反馈机制

### 步骤4：处理分页限制（关键约束）

**必须创建微型版本**：

- **限制原因**：无法提交完整单页流程图
- **分页规则**：每个工作表（worksheet）仅含 **2-3个游戏可玩性模式**
- **连贯性处理**：
  - 使用页码标注（如"见工作表2，模式A继续"）
  - 使用连接符（off-page connector：○A、○B）
  - 在每张工作表角落标注总页数和当前页码

**分页示例**：
```
工作表1：标题菜单 → 普通模式（模式1）
                     ↓ [连接符 ○A]
工作表2：奖励模式（模式2）→ 关卡完成 → 模式1循环
                     ↓ [连接符 ○B]
工作表3：游戏结束处理 → 高分榜 → 返回标题
```

### 步骤5：验证完整性

检查清单：
- [ ] 所有模式都有入口和出口？
- [ ] 菜单到游戏的转换条件明确？
- [ ] 跨页连接符双向标注？
- [ ] 游戏循环清晰可识别？
- [ ] 开始状态和结束状态完整？

## 输出格式

最终交付物为**分页的微型流程板**，每张工作表包含：
1. 页眉：游戏名称 + 页码/总页数
2. 主体：2-3个游戏模式及其关系
3. 页脚：跨页连接符说明（如有）

## 常见错误

| 错误 | 正确做法 |
|-----|---------|
| 选择现代复杂游戏（如《街头霸王6》） | 选择经典简单游戏（如《太空侵略者》《吃豆人》） |
| 单页塞入所有模式 | 严格分页，每页2-3个模式 |
| 遗漏跨页连接标注 | 每张跨页连接必须有来源页和目标页标注 |
| 混淆shell菜单和游戏模式 | 菜单=不玩游戏的界面；模式=实际游玩的规则集 |
