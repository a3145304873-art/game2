# 游戏文档设计

## 游戏脚本（Game Script）

### 定义与范围

游戏脚本是专门记录**游戏规则和核心机制**的文档，区别于技术设计、屏幕文本、音频脚本。

**历史演变**：
- 早期：包含几乎所有预生产文档的"圣经"
- 现代：专注记录其他文档未覆盖的规则机制

### 核心质量标准

**"好的规则"测试**：
> 文档详细程度应达到：读者能够**在不使用计算机的情况下，理论上可以玩游戏**

- 可能转换为复杂的棋盘游戏
- 或桌上角色扮演游戏
- 不意味着实际可玩，但理论上可行

### 文档内容

| 包含 | 排除 |
|-----|------|
| 游戏规则详细描述 | 技术实现细节 |
| 核心机制运作方式 | 软件架构说明 |
| 目标机器和最低技术说明（可选） | 屏幕文本、对话 |
| 纸质玩法测试方法 | 音频录音脚本 |

### 纸质玩法测试

**目的**：廉价获取游戏设计反馈

**推荐对象**：无大团队和足够预算的设计者

**实施步骤**：
1. 根据游戏脚本准备纸质材料
2. 模拟游戏核心循环
3. 记录玩家理解和策略
4. 迭代规则设计

## 关卡编辑器设计

### 功能范围

从简单到复杂：
- 基础：定义新场景
- 中级：定义新角色、物品
- 高级：重建整个游戏（模组）

### 核心功能标准

好的关卡编辑器必须让玩家能够：
1. 构造一个崭新的场景
2. 在场景里面设置挑战
3. 编写游戏引擎能操作的文字

### 开发流程

| 阶段 | 要求 | 团队配置 |
|-----|------|---------|
| 内部工具 | 功能优先，可用性次要 | 关卡设计师+引擎程序员 |
| 商业发布 | 必须像游戏一样精心设计和有活力 | 专职工具程序员 |

### 参考案例

| 游戏 | 编辑器 | 特点 |
|-----|--------|------|
| 《星际争霸》 | 战役编辑器 | 2D，触发器系统 |
| 《半条命2》 | Hammer | 3D，专业级工具 |
| 《我的世界》 | 内置工具 | 直观，低门槛 |

## 技术文档责任

游戏脚本**不包含**技术设计。如有需要，由首席程序员或技术指导在游戏脚本基础上编写独立技术文档。

参考：《游戏架构和设计》(Rollings & Morris, 2003)
