# 射击游戏核心机制设计

## 何时使用

- 确定游戏是否属于射击类型及子类型
- 设计或调整瞄准机制和射击手感
- 分析玩家认知负荷和注意力分配
- 选择2D或3D技术实现方案
- 平衡弹药限制与技能要求的关系

## 核心定义

射击游戏的本质：**远程战斗 + 瞄准技能 + 双焦点注意力**

```
玩家 ──[武器]──→ 远程目标
  ↑                    ↑
  └──── 同时监控 ──────┘
   (自身安全)      (敌人动态)
```

## 关键机制设计

### 1. 瞄准系统层级

| 层级 | 机制 | 适用场景 |
|-----|------|---------|
| 自动瞄准 | 辅助锁定、吸附 | 休闲向、移动端 |
| 半辅助 | 轻微减速、弹道提示 | 中核向、主机端 |
| 纯手动 | 无辅助、物理弹道 | 硬核向、竞技端 |

**决策依据**：弹药限制严格程度与瞄准难度正相关

### 2. 双焦点注意力系统

玩家必须同时处理两个信息源：

**化身区域监控（近端）**
- 自身位置与掩体关系
- 生命值/护甲状态
- 弹药余量与换弹时机

**目标区域监控（远端）**
- 敌人移动轨迹预测
- 射击窗口识别
- 环境交互（爆炸物、可破坏物）

**设计要点**：通过UI布局、音效提示、视觉引导降低认知负荷

### 3. 维度选择决策树

```
需要复杂垂直移动？
  ├─ 是 → 3D（FPS/TPS）
  └─ 否 → 需要精确平台跳跃？
        ├─ 是 → 2.5D 或 3D
        └─ 否 → 2D（成本更低，机制更聚焦）
```

| 维度 | 核心体验 | 代表类型 |
|-----|---------|---------|
| 2D | 平面预判、弹幕躲避 | 清版射击、弹幕游戏 |
| 3D | 空间感知、peek对抗 | FPS、TPS、战术射击 |

## 快速设计检查

### 弹药-瞄准关系
- [ ] 无限弹药 → 可降低瞄准精度要求，强调节奏和移动
- [ ] 有限弹药 → 必须提供瞄准反馈（准星扩散、命中确认）

### 视角验证
- [ ] 第一人称：沉浸感强，适合精准瞄准
- [ ] 第三人称：空间感知好，适合掩体系统和战术移动
- [ ] 俯视/横版：机制纯粹，适合高分挑战

### 认知负荷测试
让测试者闭眼描述：
1. 当前自身位置的安全程度（1-10）
2. 敌人的数量和方位
3. 下一步行动优先级

若回答延迟>2秒，需简化信息呈现

## 排除场景

此技能**不适用**于：
- 纯近战格斗游戏（无远程瞄准要素）
- 回合制策略游戏（无实时动作要求）
- 自动战斗/放置类游戏
