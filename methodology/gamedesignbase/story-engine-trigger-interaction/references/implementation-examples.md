# 实现示例

## 级别一示例：愤怒的小鸟

**场景**：玩家完成一关

1. 核心机制检测：玩家完成关卡
2. 核心机制 → 故事讲述引擎：发送消息"玩家完成了一关"
3. 故事讲述引擎响应：显示关卡之间的场景插叙
4. 故事讲述引擎 → 核心机制：叙事结束后发送返回游戏信号
5. 核心机制响应：恢复游戏可玩性

## 级别二示例：桥上抢劫场景

**故事设定**："当化身到达桥上的时候，他会在一个场景插叙中遭到拦路抢劫，并且抢走他所有的财产"

**执行流程**：

1. 核心机制检测：玩家在游戏世界中的进度，发送消息"化身已经到达桥上"

2. 故事讲述引擎检测：识别为关键点

3. 故事讲述引擎行动：
   - 暂停游戏
   - 显示抢劫的场景插叙

4. 故事讲述引擎 → 核心机制：发送消息"把化身的财产转移到拦路盗贼身上并返回游戏"

5. 核心机制执行：游戏内部经济改变，财产转移完成

6. 核心机制响应：恢复游戏可玩性

## 技术实现要点

### 关卡构建工具需要包含的技术

1. **玩家位置检测技术**
   - 空间触发器
   - 区域检测
   - 路径跟踪

2. **场景插叙触发技术**
   - 叙事事件队列
   - 暂停/恢复机制
   - 用户中断处理

3. **化身财产转移技术**
   - 游戏内部经济系统接口
   - 属性修改API
   - 状态持久化

### 当前限制

- 开发公司不能像许可图形引擎或物理引擎一样，对中间件公司许可一个故事讲述引擎
- 未来可能改变，但目前需要定制开发

### 概念设计价值

即使无现成中间件，利用两个独立组件之间发送触发信息的方式，仍可帮助设计：
- 故事结构
- 故事与游戏可玩性的交互点
- 玩家决策对叙事的影响
