# 玩家化身系统设计

## 使用场景
- 游戏包含角色扮演或社交互动元素
- 需要支持玩家个性化表达
- 设计玩家角色定义和化身系统
- 确定玩家-化身关系模式

## 玩家角色定义框架

### 核心定义原则
- 定义玩家在游戏世界中的角色是定义游戏概念的关键部分
- **清晰性测试**：如果玩家的角色很难描述，说明游戏面临概念性问题

### 多重角色设计
- 允许玩家在游戏中扮演多种角色（如体育游戏中的运动员、教练、总经理）
- **角色切换上下文**：
  - 熟悉语境（体育游戏）：转换角色较容易
  - 不熟悉世界：角色必须非常清晰
- **无意角色变更**：必须告知玩家角色改变的原因和适应方式

### 真实度决策
- 在概念设计阶段决定游戏是抽象还是具体
- 影响行为约束和规则设计
- 目标人群可能影响此决定

### 商业可解释性
- 易于解释的角色有助于发行商、零售商和顾客理解
- 影响购买决策

## 玩家设计化身原则

### 化身本质
- 化身是玩家为了游戏目的而采用的人物
- 本质上是戴着各种面具的玩家
- 除玩家选择的个性外，化身没有其他固有特点

### 定制选项设计

**外观定制：**
- 种族、性别、身体类型
- 发型、衣着和其他自然属性

**属性定制：**
- 力量、敏捷性等属性
- 直接关系到化身遇到困难时的表现

### 设计者职责
- **核心目标**：不是为玩家创建化身，而是提供允许玩家创建自己化身的工具
- **实现方式**：构建能够表现玩家个性的机会
- **效果评估**：提供的表现机会越多，玩家越喜欢实现创造性

## 化身指定化程度

### 三级指定化

**完全非指定化身：**
- 仅提供控制机制，几乎没有可辨识特征
- 化身就是玩家本人
- **语言特征**：不说话或极少说话

**部分指定化身：**
- 玩家能看到和了解化身的一小部分
- 没有内部生命或复杂心理
- **典型例子**：马里奥、劳拉·克劳馥、戈登·弗里曼
- **语言特征**：说得不多

**完全指定化身：**
- 与玩家明确分离，拥有独立个性
- 具有内在思想、情感和背景故事
- **典型例子**：艾波·瑞恩（《半条命》）
- **语言特征**：说话很多

### 语言交流作为指标
- 一个人说得越多，我们对她就知道得越多
- 知道得越多，她和玩家的区别就越大
- 玩家越难将自己投射到角色中

## 控制-指定化整合

### 控制方式与化身关系

**间接控制 + 指定化：**
- 化身被视为具有自己思想的其他人
- 保持独立性
- 适合完全指定或部分指定角色

**直接控制 + 指定化：**
- 在某种程度上化身就是玩家本人
- 增强身体代入感
- 指定化过高会产生认知失调

### 化身必备品质

**必须包含的品质：**
- 勇敢
- 聪明
- 庄重
- 某种感觉上的幽默

**设计目标：**
- 确保玩家愿意长时间与化身共处
- 支持化身的行动决策

### 风险规避

**最坏情况：**
- 化身具有玩家不喜欢的品质
- **负面案例**：《最终幻想VIII》斯考尔·里昂哈特（自私、令人厌烦）

**安全策略：**
- 制作半指定角色（如《塞尔达传说》林克）
- 玩家了解不够多，不足以进行积极或消极评论
- 避免冒犯玩家

## 设计检查清单
- [ ] 定义玩家角色并验证清晰性
- [ ] 确定是否支持多重角色
- [ ] 决定真实度级别（抽象/具体）
- [ ] 设计外观和属性定制选项
- [ ] 确定指定化程度（非指定/部分/完全）
- [ ] 匹配控制方式与指定化程度
- [ ] 验证化身具备必备品质
- [ ] 检查是否存在负面特质风险

## 参考案例
- 《指环王Online》：玩家设计化身系统
- 《美国陆军》：真实士兵角色，行为约束严格
- 《半条命》：戈登·弗里曼（部分指定，不说话）
- 《塞尔达传说》：林克（半指定，安全策略）
