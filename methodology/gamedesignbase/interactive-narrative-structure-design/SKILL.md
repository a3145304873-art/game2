# 交互式叙事结构设计

## 适用场景
- 设计玩家选择影响剧情发展的游戏
- 需要平衡玩家自由度与叙事连贯性
- 规划分支故事或多结局系统
- 设计非线性叙事结构

## 核心叙事结构类型

### 1. 反送故事结构

**何时使用**：希望在提供戏剧性自由的同时控制开发成本和复杂性。

**核心机制**：
- 情节多次分支，但最终都会"反送"回到一个单一的"不可避免的事件"
- 循环过程：回到不可避免事件后，继续分支，再次反送
- 大部分只有一种结局，但可在最后一个不可避免事件后分支多个结局

**设计步骤**：
1. 选择故事情节中关键的转折点作为"不可避免的事件"
2. 确定事件性质：必须是"永远改变事情"且"发生后不能变回来"的事件
3. 选取具体事件类型：英雄面对最终挑战、重要角色死亡等

**优势**：
- 在非线性交互故事的所有形式中设计最容易
- 商业上最成功
- 不用增加分支故事的花费和复杂性

### 2. 分支故事结构

**何时使用**：希望给玩家反映其戏剧性动作的结局。

**核心机制**：
- 设计者提供多个彼此分离的岔口（分支点）
- 预先定义各种可能的情节线及其相互联系方式
- 故事讲述引擎持续跟踪玩家当前跟随的情节线

**分支触发类型**：

**A. 基于挑战的分支**：
- 由玩家克服挑战的努力触发
- 通常产生成功分支与失败分支
- 可根据不同成功度提供多个分支

**B. 基于决定的分支**：
- 由故事要求的决定触发
- 每个选项必须有相应的独立分支路径

### 3. 多结局设计原则

**何时使用**：希望结局反映玩家在整个故事过程中的戏剧性动作。

**设计要点**：
- 戏剧性动作是对故事起作用的动作（克服挑战、做出选择）
- 玩家期望结局随其采取的动作而变化
- 避免让非戏剧性动作（如整理物品栏、购买衣服）影响结局

## 情感限制策略

### 单一结局限制

**问题识别**：非线性故事赋予玩家影响角色关系的重要选择自由，可能导致玩家做出"情感上感到错误"的决定，无法体验到设计者计划的"最具有情感意义的结局"。

**实施策略**：
1. 将非线性故事限制在单一结局里
2. 玩家在到达结局之前的"戏剧上的自由"只是一种"假象"
3. 不向玩家保证选择会改变结局
4. 只要结局令人满意，玩家可以忍受过程上的假象

**设计原则**：
- 不要不假思索地将非交互式媒体的传统规则应用到交互式故事中
- 如果规则不适合交互式媒体，就放弃它们

- [ ] 识别关键的"不可避免的事件"节点
- [ ] 定义分支触发条件（挑战/决定）
- [ ] 规划情感目标和结局策略
- [ ] 评估开发成本与玩家体验的平衡
- [ ] 验证玩家自由度与叙事连贯性的权衡
