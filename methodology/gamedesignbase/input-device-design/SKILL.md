# 输入设备设计

## 使用场景
- 设计游戏输入机制
- 确定支持的输入设备类型
- 评估特定输入设备（如Wii Remote）的适用性
- 设计输入映射和交互方式

## 核心设计原则

### 默认设备优先
- 优先为与机器一起出售的默认设备设计游戏
- 避免依赖昂贵外设（飞行控制架、方向盘等）
- 如果需要昂贵外设才能玩，将限制市场规模
- 仅在外设能"增强用户体验"时支持

### 输入设备的重要性
- 输入设备构建了玩家将意图投射到游戏中的方法
- 好的输入设计创造"无缝体验"与"令人沮丧体验"的差别

## 平台特性分析

### PC输入设备（键盘和鼠标）

**设计优势**
- 101键键盘支持复杂用户界面
- 适合制作复杂的计算机RPG
- 键盘使玩家可以方便地输入文本
- 支持网络聊天消息发送

**设计应用**
- 复杂UI和快捷键系统
- 基于文本的社交功能
- 需要精确指向的操作

### 家用游戏机控制器

**设计限制**
- 缺乏鼠标，较少使用屏幕按钮和菜单
- 文本输入不如PC方便

**设计应用**
- 简化UI设计
- 动作导向的游戏

### Wii Remote设计原则

**适用场景（效果非常好）**
- 动作游戏（Action games）
- 运动游戏（Sports games）
- 驾驶游戏（Driving games）
- 原因：身体动作与游戏内动作存在自然映射关系

**不适用场景（不那么成功）**
- 角色扮演游戏（RPG）
- 策略游戏（Strategy games）
- 建设游戏（Construction games）
- 管理游戏（Management games）
- 原因：需要精确指向和复杂界面操作

**关键设计原则**
1. **从头设计**
   - 必须从一开始就为Wii Remote设计游戏
   - 不能简单移植或事后添加支持

2. **易学习性与宽容度**
   - 设计要非常宽容
   - 案例：Wii Sports网球游戏中，化身自动跑到球着陆位置，玩家只需挥动遥控器

## 设计决策流程

### 1. 确定目标平台
```
IF PC平台
THEN 考虑键盘鼠标的复杂UI能力

IF 家用游戏机
THEN 考虑控制器的简化UI限制

IF Wii平台
THEN 评估是否适合身体活动映射
```

### 2. 评估游戏类型
```
IF 动作/运动/驾驶游戏
THEN Wii Remote可能适合

IF RPG/策略/建设游戏
THEN 键盘鼠标更合适
```

### 3. 确定输入复杂度
```
IF 需要复杂UI和快捷键
THEN 优先PC平台

IF 需要简单直观操作
THEN 控制器或Wii Remote更合适
```

### 4. 设计宽容度
```
IF 目标为新玩家
THEN 设计高宽容度操作（如Wii Sports）

IF 目标为核心玩家
THEN 可以设计精确操作
```

## 扩展应用场景

### 疗养院应用
- 基于运动的互动游戏有助于老年人锻炼

### 物理治疗应用
- 用于治疗受伤的人
- 玩游戏比做重复练习更有吸引力

## 平台兼容性
- Wii Remote可与PC一起工作
- 也可与Wii本身一起工作
