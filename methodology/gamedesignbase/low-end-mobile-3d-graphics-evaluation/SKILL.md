# 低端移动平台3D图形可行性评估

## 何时使用此技能

- 目标用户群体使用**低档手机**或**无GPU加速硬件**的移动设备
- 正在考虑为移动游戏或应用开发**3D图形功能**
- 需要评估在软件渲染条件下3D功能的**技术可行性与用户体验风险**
- 必须在3D视觉效果与设备性能之间做出技术决策

## 评估流程

### 1. 硬件能力识别
确认目标设备的图形处理能力：
- **检查GPU支持**：验证设备是否具备3D图形加速硬件（GPU/Graphics Processing Unit）
  - 变量：`has_gpu_acceleration`（Boolean）
  - 若值为`false`，进入风险警告流程
- **处理器评估**：确定处理器性能等级（低速/中速/高速）
  - 变量：`processor_speed`（String）
  - 重点关注低速处理器设备

### 2. 技术后果分析
当确认设备**无GPU加速**时：
- **渲染方式**：必须使用**软件渲染**（Software Rendering）
  - 变量：`rendering_method` = "软件渲染"
- **计算转移**：CPU必须完成本应由GPU处理的图形计算（顶点处理、光栅化、纹理映射等）
- **复杂度**：软件渲染是计算密集型任务，对移动CPU负担极大

### 3. 性能影响评估
量化软件渲染对用户体验的具体影响：
- **帧率下降**：CPU负载过重导致渲染帧率不稳定（可能低于15fps）
- **设备发热**：持续高负载运算导致设备温度显著升高
- **电池消耗**：CPU全速运行加速电池耗尽，缩短续航时间
- **响应延迟**：UI卡顿、触摸响应延迟、应用崩溃风险增加

### 4. 关键决策判断
应用核心原则：**"如果你不能做得很好，那么就干脆别去做"**

**决策标准**：
- 如果无法在该平台上实现**流畅的高质量3D渲染**（稳定≥30fps，无严重发热），则**不应尝试**3D方案
- 权衡3D视觉效果与性能成本的投入产出比
- 考虑团队是否有能力优化软件渲染性能

### 5. 替代方案执行
当硬件限制导致3D不可行时，立即制定替代策略：
- **改用2D图形**：使用Sprite动画、帧动画或2.5D（伪3D）方案替代纯3D渲染
- **平台分级**：实施设备分级策略
  - 高端设备：提供完整3D版本
  - 低端设备：提供2D降级版本或简化版3D（低多边形、低分辨率纹理）
- **功能裁剪**：移除复杂的实时光照、阴影、粒子效果等GPU密集型特性

## 风险警告模板

评估完成后，向团队输出以下结论：

> **⚠️ 高风险警告**  
> 目标低端设备缺乏GPU加速硬件，3D软件渲染将严重拖累系统性能。  
> **渲染方式**：`软件渲染` → CPU负载100%+  
> **预期后果**：帧率不稳定（<20fps）、设备严重发热、电池快速耗尽  
> **决策建议**：**放弃3D功能，改用2D图形** 或 **仅支持高端设备**  
> **风险等级**：高  

## 关键检查点

- [ ] 已确认目标设备`has_gpu_acceleration` = false
- [ ] 已评估软件渲染对CPU的性能负担（建议实际测试帧率）
- [ ] 已验证低速处理器下的实际发热和耗电情况
- [ ] 已制定2D替代方案或平台分级策略
- [ ] 已基于"做不好就不做"原则做出明确决策（做3D vs 改2D vs 放弃平台）
