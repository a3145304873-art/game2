# 失败案例分析

## Ubisoft《想象：时装设计师》

### 问题描述

游戏使用固定规则系统评价玩家设计，但存在严重用户体验问题。

### 具体错误

1. **规则不透明**：
   - 玩家不知道客户的具体偏好
   - 评价标准完全隐藏

2. **反馈缺失**：
   - 客户拒绝设计时不说明原因
   - 只提示"严重的设计缺陷"
   - 玩家无法知道哪里出错

3. **试错成本高**：
   - 玩家必须盲目尝试不同组合
   - 通过反复失败来猜测规则
   - 严重挫伤玩家积极性

### 教训总结

**固定规则系统的必要条件**：

1. **规则可见性**：
   - 在游戏开始时明确告知规则
   - 或在教程中逐步揭示规则
   - 提供规则查询界面

2. **反馈具体性**：
   - 指出具体违反的规则项
   - 说明为什么违反
   - 提供改进方向

3. **学习曲线**：
   - 从简单规则开始
   - 逐步增加复杂度
   - 允许练习模式

### 正确实现示例

```
评价结果：
- 总分：75/100
- 违反规则：
  1. 条纹与圆点图案混搭（-15分）
  2. 颜色超过三种主色调（-10分）
- 建议：
  - 将圆点图案改为素色
  - 减少一种辅助色
```

### 改进建议

1. **规则手册**：在游戏中提供可查阅的规则手册
2. **实时提示**：在设计过程中实时提示潜在违规
3. **解释系统**：每次评价都提供详细解释
4. **渐进式解锁**：随着游戏进程解锁更复杂的规则
