# 游戏模式与交互设计

## 游戏模式类型

### 可玩性模式
- **定义**：玩家采取影响游戏世界的动作，此时处于"玩游戏"状态
- **判定标准**：玩家动作影响核心机制，或影响可以推迟但仍作用于核心机制

### Shell 菜单
- **定义**：玩家不能影响游戏世界，但可做出其他改变（如载入/保存、设置音量/分辨率）
- **使用时机**：通常在游戏开始或结束之后使用（处于魔法圈之外）
- **例外**：暂停菜单通常是Shell菜单，但如果允许玩家采取影响游戏世界的动作，则属于可玩性模式

### Shell 屏幕
- **定义**：非交互式的屏幕序列（如截屏、标题屏幕）

## 可玩性模式判定流程

```
识别玩家当前所处的界面/屏幕
    ↓
分析玩家可执行的动作类型
    ↓
判断动作是否影响核心机制？
    ↓ 是 → 可玩性模式
    ↓ 否
判断影响是否可以推迟但仍作用于核心机制？
    ↓ 是 → 可玩性模式
    ↓ 否 → Shell菜单/屏幕
```

## 模式转换逻辑

### 触发类型
1. **玩家动作触发**：游戏在Shell菜单间切换，或从一种可玩性模式变为另一种模式
2. **环境/规则自动触发**：根据游戏要求的环境自动改变（如犯规动作导致罚球模式）

### 记录游戏结构
- 列出所有模式
- 说明转换原因
- 定义转换关系
- 标记转换触发器
- 推荐使用流程板记录

## 交互模型分类

### 1. 基于化身的模型
- **特征**：玩家大部分动作由控制一个角色（化身）组成
- **影响范围**：通常只能影响化身当前所在的区域
- **设计要求**：按钮分配应以导航为中心

### 2. 多处存在模型
- **特征**：玩家同时作用于游戏世界的不同部分
- **视角要求**：必须提供空中视角，且玩家可以改变视角
- **设计要求**：提供选择和拿起环境中的物体，或给单位发布命令的方法

### 3. 基于团队的交互模型
- **特征**：一个小组的全部角色通常保持在一起作为一组
- **常见类型**：角色扮演游戏（RPG）
- **设计要求**：可能使用点选式导航和空中视角

### 4. 竞赛模型
- **特征**：玩家回答问题并做出决定（类似电视游戏秀）
- **设计要求**：不需要导航，只需将不同的决定选项分配到不同的按键上

### 5. 桌面模型
- **特征**：模仿计算机（或实际）桌面
- **常见类型**：表现办公室活动的游戏（如商业模拟）

## 设计建议

- 遵循常见行业习惯的连贯设计通常属于上述熟悉模型中的一种
- 如果确实需要创建其他模型，必须设计更详细的教学关卡来让玩家学习其中的控制
