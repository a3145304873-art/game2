# 游戏模式与进展设计

## 何时使用
- 进行游戏系统架构设计
- 检测到游戏状态/交互发生重大变化
- 判断游戏是否包含"进展"机制
- 设计游戏关卡流程
- 需要维持玩家对游戏的长期兴趣
- 避免游戏因重复操作而变得单调乏味

## 执行步骤

### 1. 定义游戏可玩性模式

**核心定义：**
游戏可玩性模式由以下两部分组成：
- 游戏的所有时间里可用的全部游戏可玩性的子集
- 向玩家表示这个子集的用户界面

**一致性原则：**
在任何给定的时间里，玩家可用的挑战和动作在概念上都应该是彼此相连的。

**示例：** 在白刃化格斗中可以移动、挥舞武器、服药、逃跑，但不能整理背包或看地图。

### 2. 识别模式切换

当满足以下任一条件时，游戏离开当前模式进入另一种模式：
- 玩家可用的游戏可玩性做出重大改变
- 用户界面做出重大改变（改变了玩家的注意力中心）
- 输入设备上的按键与游戏中的动作之间的映射急剧改变

**判定标准：** 当玩家感觉到游戏的某些内容发生了显著的变化时，即认为进入了一种新的游戏可玩性模式。

### 3. 判定游戏进展机制

**进展定义：** 设计师为游戏设定的一系列直接明了的挑战，而非由机器算法随机生成的挑战。

**判定标准（必须满足以下条件）：**
- 挑战之间存在关联性：当前关卡的胜利必须对后续关卡产生影响
- 存在既定目标：挑战是朝着最终目标前进的

**排除标准：**
- 挑战随机生成且互不相关（如《宝石迷阵》）

**正面案例：** 《糖果粉碎传奇》- 每一关的胜利影响其他关卡，必须完成当前关卡才能进入下一关

### 4. 设计新奇性引入节奏

**核心规则：** 引入一个新的元素 → 暂时给玩家探索这一元素的机会 → 然后再引入下一个元素

**实施策略：**
1. 利用新奇性吸引玩家：提供看、听、做的新体验
2. 提供丰富多样的内容与视角：开辟全新的游戏世界，改变玩游戏的方式
3. 保持新奇感的连续性：当一种新奇感结束时，应立即产生另一种新奇感
4. 平衡挑战性与清晰度：确保新奇感带来的挑战性不会让玩家感到混乱

### 5. 验证设计

**检查清单：**
- [ ] 每个模式的挑战和动作概念相连
- [ ] 用户界面适配当前模式的动作
- [ ] 模式切换有明确的触发条件
- [ ] 进展机制包含关联的挑战
- [ ] 新奇性引入有合理的探索时间
- [ ] 新奇感变化不会让玩家混乱
