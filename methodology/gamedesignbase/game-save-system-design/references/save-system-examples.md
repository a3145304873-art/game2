# 存档系统设计示例

## 关颖珊花样滑冰锦标赛

### 保存内容
- 滑冰者的身体类型
- 肤色
- 头发颜色和样式
- 衣着
- 玩家头像图片

### 设计考虑
给予玩家或化身的定制自由度越大，需要保存的数据量就越多。现代控制台机器通常有足够空间存储大量定制数据。

## 游戏时长与存档必要性

### 40小时游戏
期望玩家从开始到结束不休息是不现实且不公平的。

### 存档功能必要性
| 游戏类型 | 存档必要性 | 替代方案 |
|---------|-----------|---------|
| 街机游戏 | 低 | 多条命 |
| 控制台动作游戏（传统） | 低 | 多条命 |
| 角色扮演游戏 | 高 | 一条命+存档 |
| 冒险游戏 | 高 | 一条命+存档 |
| 回合制策略游戏 | 高 | 允许尝试不同策略 |

## 玩家行为接受

### 常见玩家行为
- 通过反复载入来避免随机事件
- 通过反复尝试解决问题
- 使用代码来作弊

### 设计师态度
大部分游戏现在都认识到玩家希望——有时候需要——通过这些方式来玩游戏。

## 决策流程

### 限制保存评估
```
IF (限制保存的主要目的是增加难度)
THEN (拒绝该方案，重新设计挑战内容)
ELSE (允许保存，尊重玩家需求)
```

### 存档内容确定
```
基础保存：玩家位置
扩展保存：玩家定制信息（与定制自由度成正比）
```
