# 游戏存档系统设计

## 使用场景
- 设计游戏的保存/载入机制
- 评估游戏难度平衡策略
- 优化玩家体验
- 确定存档数据范围

## 核心定义

### 保存游戏
获取给定时间点的游戏世界快照及其所有细节并存储，使玩家能载入数据返回该时间点继续游戏。

## 执行步骤

### 步骤1：评估限制保存的动机

#### 评估标准
如果限制玩家保存游戏的主要目的是为了让游戏变得更加困难，则判定为"懒惰的游戏设计"。

#### 理由分析
- 这种做法"只添加了难度而没有添加乐趣"
- 强迫玩家因为"某个关卡的结果处犯了一个错误"就"重新玩整个关卡"
- 会"浪费他的时间"，并让他"变得沮丧和厌倦"
- 违背了以玩家为中心的设计原则

### 步骤2：确定正确的难度设计方法

#### 正确做法
如果确实希望游戏更加困难，应该"设计更难的挑战"，而不是通过剥夺保存功能来实现。

#### 玩家关系定位
- 不要假设玩家是对手
- 玩家玩游戏不是为了取悦设计师
- 玩家可能会由于相当合理的原因保存游戏

#### 接受玩家行为
承认玩家可能通过反复载入来避免随机事件或通过反复尝试解决问题。

### 步骤3：确定保存内容范围

#### 保存内容（数据完整性）
- 不仅保存玩家位置
- 必须保存玩家定制信息

#### 定制自由度与数据量
给予玩家或化身的定制自由度越大，需要保存的数据量就越多。

#### 示例
在《关颖珊花样滑冰锦标赛》中，需保存：
- 滑冰者的身体类型
- 肤色
- 头发颜色和样式
- 衣着
- 玩家头像图片

### 步骤4：确定实施理由

#### 理由一：允许中断与返回（最重要原因）
对于大型游戏（如40小时的游戏），期望玩家从开始到结束不休息是不现实且不公平的。

#### 理由二：从灾难性错误中恢复
通常指化身死亡。
- **对比**：街机游戏通常不提供存档，而是给予多条命
- **应用**：更丰富的游戏（如角色扮演或冒险游戏）通常给玩家一条命，但在化身死亡或意识到无法获胜时，允许重新载入已保存的游戏

#### 理由三：鼓励探索替代策略
在回合制策略游戏中，允许玩家尝试不同方法学习游戏。如果策略失败，可以返回到失败点并使用另一种方法。

## 设计检验标准

### 保存限制检验
- [ ] 限制保存是否是为了增加难度？
- [ ] 如果是，是否改为设计更难的挑战？
- [ ] 是否尊重玩家的合理保存需求？

### 存档内容检验
- [ ] 是否保存了玩家位置？
- [ ] 是否保存了所有定制信息？
- [ ] 数据量是否与定制自由度匹配？

### 实施理由检验
- [ ] 是否允许玩家中断与返回？
- [ ] 是否允许从灾难性错误中恢复？
- [ ] 是否鼓励探索替代策略？

## 约束条件

### 不适用场景
- 街机游戏通常不采用此机制
- 技术存储空间限制（现代已较少见）
- 竞技类多人游戏模式（通常需要公平性）

### 主要适用场景
- 单人游戏体验
- 大型游戏（如40小时的游戏）
- 角色扮演或冒险游戏
- 回合制策略游戏
