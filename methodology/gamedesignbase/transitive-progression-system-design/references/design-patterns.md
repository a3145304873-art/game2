# 可传递进度系统的设计模式

## 模式一：线性阶梯式

最简单的实现，单一路径逐级升降。

**适用场景：** 单一核心玩法的竞技游戏

**结构：**
```
Lv1 → Lv2 → Lv3 → Lv4 → Lv5
```

**参数建议：**
- 升级阈值：60%胜率或前40%排名
- 降级阈值：30%胜率或后30%排名
- 缓冲期：新升级后3场保护期

---

## 模式二：多轨并行式

多个独立的可传递链条，玩家可同时推进。

**适用场景：** 角色扮演、开放世界游戏

**结构：**
```
战斗链：铁剑 → 钢剑 → 银剑
魔法链：木杖 → 水晶杖 → 星辰杖
载具链：马车 → 战马 → 飞龙
```

**设计要点：**
- 各链条评估标准独立
- 允许玩家专精或均衡发展
- 跨链组合创造build多样性

---

## 模式三：赛季循环式

周期性重置，保留部分进度作为新赛季起点。

**适用场景：** 在线竞技、排名赛季制游戏

**重置规则示例：**
| 赛季末等级 | 新赛季起始 | 保留奖励 |
|-----------|-----------|---------|
| 顶级 | 高级 | 专属外观 |
| 高级 | 中级 | 加成道具 |
| 中级 | 低级 | 基础资源 |

---

## 挫败感控制技术

### 降级缓冲设计

1. **降级预警**：表现下滑时提前提示
2. **降级豁免**：首次触发降级时给予一次机会
3. **降级保护期**：升级后N场内即使表现不佳也不降级

### 心理补偿机制

- 降级时给予"复仇任务"，完成可快速回归
- 显示"历史最高"作为成就锚点
- 降级后匹配对手难度同步调整

---

## 数学参考：动态平衡公式

**期望胜率计算：**
```
E = 1 / (1 + 10^((R_opponent - R_player)/400))
```

**等级调整：**
```
R_new = R_old + K × (S - E)
```
其中：
- R = 等级分数
- K = 调整系数（通常16-32）
- S = 实际结果（胜=1，平=0.5，负=0）
- E = 期望胜率

**阈值映射：**
| 分数区间 | 显示等级 |
|---------|---------|
| 0-199 | 青铜 |
| 200-399 | 白银 |
| 400-599 | 黄金 |
| 600+ | 大师 |
