# 可传递进度系统案例分析

## 案例一：《GT赛车》职业模式

**系统结构：**
- 驾照等级：B → A → S → S+（国际A级）
- 车辆性能：N200 → N400 → N600 → N1000

**可传递关系应用：**
- 低级别赛事限制车辆性能等级
- 高级别驾照解锁高性能赛事
- 形成驾照等级与车辆性能的双重可传递链

**降级机制：**
- 驾照考试可重复挑战
- 在线排名根据近期表现动态调整

## 案例二：《英雄联盟》排位系统

**可传递层级：**
铁 → 青铜 → 白银 → 黄金 → 铂金 → 钻石 → 大师 → 王者

**关键设计：**
- 大段位间有晋级赛（缓冲挫败感）
- 小段内无降级保护，大段间有降级保护
- 隐藏分（MMR）与显示段位分离，实现平滑匹配

**可逆性体现：**
- 钻石5 0胜点后连败会降级至铂金1
- 但隐藏分保留，回归时晋级赛有优势

## 案例三：《怪物猎人》武器升级树

**非典型应用：** 将可传递关系用于装备而非玩家等级

**结构特征：**
```
铁剑 → 铁剑改 → 钢剑 → 钢剑改 → 银火龙剑
        ↓
      毒狗龙剑 → 毒狗龙剑改 → 剧毒剑
```

**设计洞察：**
- 分支选择创造差异化路径
- 素材需求形成进度门槛
- 无降级机制，但存在"机会成本"（选择A则延迟B）

## 反例警示：《星际争霸2》早期联赛

**问题：**
- 赛季重置过于彻底，高玩与新手混排
- 无降级机制导致等级通胀
- 正反馈过强，新手体验断裂

**改进：**
- 引入隐藏分继承
- 增加定位赛缩短收敛时间
- 青铜以下增加"新手"保护段位
