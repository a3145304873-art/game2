# 可传递关系进度系统设计

设计基于可传递关系的玩家升级系统，创建正反馈循环与动态平衡机制。

## 何时使用

- 设计长期进度或等级系统
- 需要创建玩家成长感和成就感
- 存在可传递关系的选项层级（弱/中/强）
- 希望实现表现挂钩的动态难度调整
- 构建赛车游戏职业模式或其他竞技进阶系统

## 核心设计流程

### 1. 建立可传递选项层级

定义三个或以上具有明确优劣关系的选项：
- **基础等级**：玩家起始选项（最弱）
- **中间等级**：进阶奖励选项
- **顶级等级**：最优选项

> 示例：雪佛兰（弱）→ 道奇（中）→ 福特（强）

### 2. 设计升级路径

**正向进阶规则：**
1. 玩家从唯一的基础选项开始
2. 优秀表现触发升级至下一等级
3. 逐级解锁，不可跳级
4. 每次升级强化成就感，形成正反馈

### 3. 设计降级机制（动态平衡）

**降级触发条件：**
- 当前等级表现不达标
- 连续失败或排名下滑

**降级执行原则：**
| 原则 | 说明 |
|------|------|
| 单级降级 | 每次只降一级，避免过度惩罚 |
| 可逆性 | 优秀表现可立即重新升级 |
| 透明度 | 玩家明确知道降级原因 |

### 4. 表现评估标准

定义明确的升级/降级判断依据：
- 比赛排名阈值（如前3名升级，后3名降级）
- 连续表现窗口（如最近3场平均成绩）
- 难度系数调整（根据对手强度加权）

## 关键约束检查

- [ ] 允许重新升级（可逆性保证）
- [ ] 降级幅度可控，避免挫败感
- [ ] 评估标准对玩家透明
- [ ] 各级选项差异可感知

## 快速示例

**赛车游戏职业模式：**
```
起始：驾驶雪佛兰参加业余联赛
    ↓ 获得前3名
升级：解锁道奇，参加职业联赛
    ↓ 连续2场前3名
升级：解锁福特，参加顶级联赛
    ↓ 排名跌出前5
降级：回到道奇，保留重新升级机会
```

## 常见变体

- **多分支路径**：不同赛事类型拥有独立等级链
- **保护机制**：新升级后N场内不降级
- **赛季重置**：周期性回归中间等级，保留部分进度
