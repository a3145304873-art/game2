# 多模态输出设计原则

## 感官通道的互补与冗余

### 信息分层

| 层级 | 通道 | 用途 | 失败回退 |
|-----|------|------|---------|
| 主要 | 视觉中心 | 核心玩法信息 | 听觉提示 |
| 次要 | 视觉周边 | 状态指示 | 听觉/触觉 |
| 辅助 | 听觉 | 空间定位、警告 | 视觉闪烁 |
| 沉浸 | 触觉 | 物理反馈 | 视觉/听觉模拟 |

### 冗余设计原则
关键信息必须在至少两个通道呈现。

示例：低生命值警告
- 视觉：屏幕边缘红色渐变 + 心跳图标
- 听觉：心跳音效渐强
- 触觉：手柄脉冲节奏匹配心跳

## 无障碍适配模式

### 视觉替代方案

**色觉障碍适配**
- 从不单独用颜色区分状态
- 必须配合：形状、纹理、标签、动画

**低视力适配**
- 核心机制输出 → UI层放大/高对比度转换
- 屏幕阅读器接口：将视觉信息转换为语音描述

**全盲适配**
- 空间音频：3D音效替代屏幕空间信息
- 触觉反馈：复杂振动模式编码状态
- 语音UI：菜单和状态朗读

### 听觉替代方案

**听力障碍适配**
- 所有听觉信息必须有视觉对应
- 方向性音效 → 屏幕边缘指示器
- 语音对话 → 字幕 + 说话者标识 + 情感标注

## 性能与保真度权衡

### LOD（细节层次）策略

根据情境动态调整输出精度：

```
if 玩家注意力聚焦:
    全精度渲染 + 全音效层
elif 玩家注意力分散:
    简化渲染 + 关键音效
else (背景/边缘):
    最小更新 + 仅警告音效
```

### 网络同步场景

- 本地预测：UI层基于本地模拟立即响应输入
- 服务器校正：收到权威状态后平滑插值
- 核心机制始终处理权威状态，UI层处理表现层插值

## 调试与验证

### 单通道测试
- 遮蔽视觉：仅通过音频能否游玩？
- 静音：仅通过视觉能否感知所有警告？
- 关闭触觉：关键反馈是否仍被感知？

### 感知延迟测试
- 输入到视觉反馈：目标 < 16ms（1帧@60fps）
- 输入到听觉反馈：目标 < 20ms
- 输入到触觉反馈：目标 < 30ms
