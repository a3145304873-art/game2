# 游戏UI媒介层设计

## 何时使用此技能

- 设计新游戏系统架构，需要明确核心机制与玩家的交互边界
- 重构现有游戏，将混杂的UI逻辑与游戏逻辑分离
- 实现跨平台输入适配（同一核心机制支持键鼠/手柄/触屏）
- 优化无障碍功能，需要调整输出呈现而不改动核心机制
- 解决"输入延迟"或"输出反馈不清晰"等体验问题

## 核心原则

用户界面不是单纯的显示层或输入层，而是**核心机制与玩家之间的双向翻译器**。核心机制与玩家永不直接交互——所有通信必须经过UI媒介层。

## 执行流程

### 第一步：建立输出通道（核心机制 → 玩家）

1. **识别核心机制输出内容**
   - 列出所有需要传达给玩家的游戏状态信息
   - 区分关键信息（必须感知）与辅助信息（增强体验）
   - 示例：赛车速度、对手位置、碰撞预警、引擎状态

2. **设计多模态呈现方案**
   | 信息类型 | 首选通道 | 备用/强化通道 |
   |---------|---------|------------|
   | 空间位置 | 视觉（屏幕图像） | 听觉（3D音效定位） |
   | 时间压力 | 视觉（倒计时UI） | 听觉（节奏音效加速） |
   | 物理冲击 | 视觉（屏幕震动） | 触觉（手柄振动） |
   | 状态变化 | 视觉（角色动画） | 听觉（音效反馈） |

3. **验证转换保真度**
   - 检查：玩家能否从输出中准确还原核心机制状态？
   - 消除歧义：同一感官通道是否承载冲突信息？

### 第二步：建立输入通道（玩家 → 核心机制）

1. **映射物理输入设备**
   - 枚举目标平台的所有可用输入：按键、摇杆、触摸、体感等
   - 记录输入特性：离散/连续、有界/无界、绝对/相对

2. **定义游戏语义行动**
   - 从核心机制需求出发，列出玩家可执行的所有游戏内行为
   - 为每个行动标注：触发条件、参数范围、组合可能性

3. **建立转换规则**
   ```
   物理输入 → [转换规则] → 游戏语义行动
   
   示例：
   - 摇杆X轴偏移量[-1,1] → 映射为转向角度[-45°,45°]
   - 按键按下事件 → 触发"跳跃"行动（含防抖动处理）
   - 鼠标移动Δx,Δy → 映射为摄像机旋转（含灵敏度曲线）
   ```

4. **处理平台差异**
   - 同一游戏语义可绑定多种物理输入方案
   - 保持核心机制代码不变，仅在UI层做适配

### 第三步：验证双向隔离

- [ ] 核心机制代码不包含任何设备相关调用
- [ ] 玩家输入处理代码不直接修改游戏状态
- [ ] 更换输入设备无需修改核心机制
- [ ] 调整输出呈现无需修改核心机制
- [ ] 核心机制单元测试可脱离UI运行

## 常见陷阱

| 陷阱 | 症状 | 解决方案 |
|-----|------|---------|
| UI层过薄 | 核心机制直接读取输入设备 | 强制所有输入通过UI层转换 |
| 语义泄露 | 核心机制包含"按空格跳跃"字样 | 核心机制只识别"Jump"行动，按键映射在UI层 |
| 单向设计 | 只考虑输出呈现，忽视输入转换 | 同步设计双向通道，保持对称性 |
| 过度抽象 | 输入延迟过高，手感迟钝 | 在UI层允许部分预测性处理 |

## 快速检查清单

设计完成后，用以下问题验证：

1. 能否在不改动核心机制的情况下，将游戏移植到VR平台？
2. 能否为视障玩家添加屏幕阅读器支持而不改动核心机制？
3. 能否将"按键触发"改为"语音触发"而不改动核心机制？
4. 核心机制单元测试是否需要初始化图形设备？

若任一答案为"否"，重新检查UI层边界划分。
