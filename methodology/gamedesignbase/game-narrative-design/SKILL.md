# 游戏叙事设计

## 使用场景
- 设计游戏故事和叙事系统
- 确定游戏结局机制
- 评估是否使用交互式故事元素
- 设计故事讲述引擎

## 核心原则

### 以玩家为中心的叙事决策
**主要任务**：设计游戏，娱乐玩家

**决策逻辑**：
- IF (故事可以帮助娱乐玩家 = TRUE) THEN (把它用到你的游戏中)
- ELSE IF (故事不能帮助娱乐玩家 = FALSE) THEN (就别用)

### 故事讲述引擎核心原则
**随机性和重复性会摧毁戏剧性紧张**
- 叙事事件不能随机发生
- 叙事事件不能任意发生
- 叙事事件绝不能重复

## 执行步骤

### 步骤1：确定故事编写时机

#### 概念设计阶段（禁止编写故事）
工作范围：
- 定义玩家角色
- 确定游戏可玩性种类
- 制作剧集或关卡列表

#### 详细设计阶段（可以开始编写）
**最低要求**：设计了主要的游戏可玩性模式之后
**更佳时机**：设计出了所有较重要的可玩性模式之后

**等待编写的原因**：
1. 必须先知道游戏将提供什么种类的可玩性
2. 必须先确定玩家将被允许使用什么样的动作
3. 必须先确定玩家不能采取什么类型的动作

### 步骤2：确定结局决定因素类型

#### 基于技能/挑战
- 结局反映玩家克服挑战的能力
- 将最后得分作为反映玩家技能的水平
- 成功结局：以"适度的积极的方式"结尾
- 失败结局：无需创造完全美满的结局

#### 基于戏剧性选择
- 结局反映玩家做出的重要决定（特别是道德选择）
- 必须创建多个结局来展示选择的结果
- 包含道德选择的游戏应该是非线性的

### 步骤3：选择叙事协作模式

#### 模式A（关卡间叙事）
- 使用大的间隔尺度编写故事
- 在完成每一个关卡设计之后编写
- 甚至可在所有关卡都设计完之后编写

#### 模式B（关卡内叙事）
- 必须在设计关卡的同时编写故事
- 关卡设计创造了玩家可以经历的时时刻刻的体验序列

### 步骤4：设计故事讲述引擎

#### 禁止随机性
- 每个叙事事件必须与整体故事有明确的因果关联

#### 禁止重复性
- 每个叙事事件必须是独特的、推进故事发展的片段

#### 交织设计要求
- 游戏可玩性必须与叙事事件交织
- 叙事事件必须散布在游戏可玩性事件之中
- 所有事件应感觉彼此相关

#### 主题一致性要求
- 游戏可玩性应涉及和叙事相同的主题
- 呈现出一个连贯与和谐的整体

## 设计检验标准

### 故事编写时机检验
- [ ] 是否已完成概念设计阶段？
- [ ] 是否已设计主要游戏可玩性模式？
- [ ] 是否已确定玩家可用的动作和不可用的动作？

### 结局设计检验
- [ ] 结局是否与玩家核心行为（挑战或选择）相匹配？
- [ ] 基于选择的结局是否避免了虚假重要性？
- [ ] 基于技能的结局是否反映了玩家的技能水平？

### 故事讲述引擎检验
- [ ] 叙事事件是否避免了随机性？
- [ ] 叙事事件是否避免了重复性？
- [ ] 游戏可玩性与叙事是否有机交织？
- [ ] 主题是否保持一致？
