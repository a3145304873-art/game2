# 游戏类型设计

## 使用场景
- 设计特定类型的游戏
- 定义新游戏概念
- 向利益相关者解释游戏
- 准备在平台发布游戏

## 平台游戏定义与核心机制

### 确认标准
1. **视觉风格**：游戏必须是卡通化的
2. **环境特征**：环境在垂直方向上非常夸张，包含不同高度的平台
3. **核心移动机制**：化身在不同高度的平台上跳上跳下
4. **游戏目标**：避免障碍同时和敌人战斗
5. **化身物理能力**：
   - 拥有非自然的跳跃能力
   - 从很高的地方跳下来时不会受到伤害
   - 例外：除非跳到某些危险的东西上或者跳进一个无底的沟壑中
6. **玩家操作构成**：大部分动作由跳跃组成
7. **增强移动方式**：通过各种各样的翻滚移动或者环境中有弹性的物体增多弹跳的程度
8. **物理规则**：使用非现实的物理规则
9. **空中控制**：化身通常可以在半空中改变方向

### 适用性判断
```
IF (游戏主要涉及在垂直夸张环境中跳跃移动)
THEN 应用平台游戏分类
ELSE (如模拟真实物理规则的游戏)
THEN 不适用此分类
```

## 建设与管理模拟游戏（CMS）核心机制

### 核心定义
- 全称：建设与管理模拟游戏（Construction and Management Simulation，简称CMS）
- 游戏本质：关于过程的游戏，不是关于结果或对抗的游戏
- 核心体验：玩家对于程序了解得越多，控制得就越好，在建设方面就会越成功

### 玩家目标设定
- 非对抗性目标：不是打败敌人
- 建设性目标：在正在进行的环境内建造一些东西（例如蚁穴或者城市）

### 约束条件设计
- 必须包含：经济条件的限制
- 操作环境：在经济条件的限制下进行操作

### 游戏模式设计（两套标准模式）
1. **自由建设模式**：玩家可以随意建造东西，无预设限制，适合探索和实验
2. **预设情节模式**：有特定目标和约束的情景，提供结构化挑战

### 工具系统设计（两套工具）
1. **建设工具**：用于构造物体，建设一般是比较容易的
2. **管理工具**：用于运营和调控已建设的内容，管理的确很棘手（核心挑战所在）

### 挑战类型规划
CMS主要提供的挑战：
- 经济方面的挑战：资源分配、成本控制、收益最大化
- 概念方面的挑战：规划布局、系统设计、效率优化
- 明确排除：很少涉及冲突或探索
- 明确排除：几乎从来不包括实体的挑战（如动作操作、反应速度等）

## 策略游戏的结构分类

### 主要子类划分（二元分类）
- **类别A**：经典的回合制游戏（Turn-based Strategy）
- **类别B**：实时策略游戏（Real-time Strategy）

### 纯度判定规则（关键约束）
- **定义**：纯策略游戏 = 只包含冲突挑战的游戏（无经济/探索等延迟元素）
- **运行机制规则**：纯策略游戏"一般都是回合制的，而不是实时运行的"
- **推论**：若游戏为纯冲突挑战（无经济/探索元素），则应采用回合制；若采用实时制，通常包含非冲突挑战元素

### 表现形式与抽象程度映射
- 实时策略游戏通常表现为具象化战争
- 回合制游戏可覆盖从高度抽象（西洋跳棋）到具象化的全谱系

### 玩家偏好提示
- 战略思维玩家偏好计划与策略维度
- 对实体对抗元素"不是很感冒"，设计时应注意平衡

## 游戏类型定义与验证策略

### 利用类型框架降低风险
- 理解类型不限制想象力，但提供"框架设计的经验"
- 避免一切从零开始建立游戏，利用既有框架降低设计新游戏时的风险

### 沟通与解释策略
- 利用著名类型帮助向"资助机构、零售商和玩家"解释游戏概念

### 市场分类差异分析
- 观察平台：MobyGames、雅虎游戏、安卓或苹果应用商店
- 分析维度：哪些游戏类别呈现或缺乏不一样的定位？
- 归因分析：导致这些差异的原因是什么？

### 概念契合度检查
- 核心问题：提供给玩家的游戏挑战和动作是否符合某一种既定的游戏类别？
- 示例验证：如"驾驶"这类玩家花绝大多数时间用到的动作，是否趋向于放到某种特有的类别中？

### 销售渠道分类适配
- 适用场景：通过游戏商店、在线游戏商店或游戏门户网站销售
- 操作：参考雅虎游戏或苹果应用商店的分类页面，确定游戏归属

### 玩家盲测验证
1. 向潜在玩家描述游戏，但不能告诉他们该游戏的类别
2. 让玩家区分/猜测该游戏的类别
3. 确认玩家分类是否符合预期分类

### 个人偏好与区分标准分析
- 任务：简述喜欢、不关注、特别不喜欢的游戏类别，并说明区分标准
- 视角转换：从玩家角度出发，并与喜好不同的人讨论，分析喜好差异的原因

## 执行流程

### 设计平台游戏
```
1. 确认卡通风格
2. 设计垂直夸张环境
3. 实现非现实跳跃机制
4. 设计空中控制
5. 添加增强移动方式
```

### 设计CMS游戏
```
1. 确定建设对象（蚁穴、城市、农场等）
2. 设计经济条件限制
3. 实现双模式（自由建设/预设情节）
4. 实现双工具系统（建设工具/管理工具）
5. 规划经济和概念挑战
```

### 设计策略游戏
```
1. 确定挑战纯度（是否仅包含冲突挑战）
2. 选择时间机制（纯冲突→回合制；混合挑战→可选实时制）
3. 确定抽象程度
4. 平衡战略思维与实体对抗元素
```

### 验证游戏类型
```
1. 分析核心挑战和动作
2. 检查概念契合度
3. 进行玩家盲测
4. 确定销售渠道分类
```
