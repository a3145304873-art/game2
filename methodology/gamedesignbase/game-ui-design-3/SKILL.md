# 游戏界面设计

## 使用时机
- 需要创建比窗口视图更具沉浸感的全屏视图
- 需要向玩家显示指标/分数等辅助信息
- 系统需要降低UI复杂度
- 存在明确的当前上下文
- 已完成核心玩法定义
- 已选定交互模型
- 已确定游戏视角

## 平视显示器(HUD)设计原则

### HUD基本概念与隐喻

**定义**
- HUD（Head-Up Display，平视显示器）是叠加在主视图上的图形元素虚拟屏幕

**设计隐喻**
- 想象成"放置在玩家和主视图之间的假想玻璃屏幕"

**术语说明**
- 单个HUD元素也称为"覆盖层"（overlays）

### 覆盖层透明度设计原则

**可选类型**
- 覆盖层可以是不透明或半透明的

**半透明覆盖层的优势**
- 玩家可以通过覆盖层看到一部分游戏图形
- 感觉比不透明覆盖层更好
- 对于飞行模拟器中的驾驶舱视图仪器效果尤佳

**关键限制**
- 半透明覆盖层背后的图形材料渗透可能干扰覆盖层本身信息的识别
- 具体控制要求："要控制覆盖层的透明效果不宜太高"——即透明度不能设置得过高，需平衡可见性与信息可读性

### HUD元素数量控制原则

**核心警告**
- "要注意不能使用太多的覆盖层，否则你的 HUD 将变得非常混乱"

**解决方案**
- 具有大量信息的游戏应允许玩家自定义HUD
  - 功能1：允许玩家打开或关闭个别HUD元素
  - 功能2：允许玩家重新定位HUD元素

**参考案例：《指环王 Online》**
- 允许玩家用一个按键隐藏整个HUD
- 目的：让玩家查看纯净主视图，确保没有其他项目干扰

## 上下文敏感界面设计原则

### 核心原则

通过动态筛选，仅向玩家展示当前上下文中有意义的选项，隐藏或禁用无意义的选项。

### 实现方式一：完全隐藏不可用选项

- 在当前上下文中没有意义的菜单选项直接不显示
- 优点：最大程度减少视觉干扰
- 缺点：用户可能困惑于选项的消失（"为什么几分钟前看到的选项突然不见了"）

### 实现方式二：灰色显示不可用选项

- 用灰色显示不可用的菜单选项
- 用黑色（或正常颜色）显示可以使用的菜单项
- 效果："在某种程度上减少了用户的迷惑，因为她不会再怀疑为什么几分钟前看到的选项突然消失了"
- Microsoft Windows采用的方法

### 实现方式三：上下文敏感的鼠标指针/箭头

**应用场景**
- 常用于图形冒险游戏、角色扮演游戏和其他鼠标控制的游戏

**工作方式**
- 当鼠标指向可交互物体时，箭头自动改变形状

**具体示例**
- 指向一棵树时，箭头变为斧子形状，提示"按下鼠标键就会砍倒这棵树"

**玩家学习机制**
- "通过用鼠标指向游戏世界不同的物体并看到它是怎样变化的，就可以知道鼠标可以做到的各种各样的事情"

**优点**
- 无需额外UI元素，直观传达交互可能性

## 屏幕布局选择决策流程

### 第一阶段：确定主视野的呈现方式

1. 明确主视野是屏幕上最大的视觉元素
2. 从三种呈现方式中选择其一：
   - **窗口模式**：主视野占据屏幕的一部分，剩余空间用于UI元素
   - **全屏模式**：主视野占据整个屏幕
   - **覆盖模糊模式**：主视野部分区域被覆盖物（overlay）遮挡而变得模糊

### 第二阶段：平衡屏幕空间分配

1. 评估两个竞争需求所占的屏幕空间：
   - 主视野（游戏世界显示）所需空间
   - 反馈元素（状态显示、提示信息）和屏幕控制（操作按钮、菜单）所需空间

2. 按平台类型进行差异化处理：
   - **个人计算机和控制台游戏**：高分辨率屏幕使此平衡"根本不算是一个问题"
   - **掌上设备**："还是一个严重的挑战"
   - **手机**："一个非常严重的挑战"——原因包括缺乏标准屏幕大小和形状

### 第三阶段：整合UI元素布局

将所有屏幕上的UI特征放置在游戏世界主视野的上方及周围区域，形成层次化的视觉结构。

## 关键变量

| 变量名 | 类型 | 描述 |
|--------|------|------|
| overlay_transparency | percentage | 控制HUD元素半透明程度，过高会干扰信息识别 |
| hud_element_count | integer | 叠加显示的信息元素个数，过多会导致界面混乱 |
| current_context | GameState | 玩家当前所处的游戏状态、位置、选中对象等 |
| available_options | Set<UIElement> | 在当前上下文下有意义的功能选项 |
| cursor_mapping | Map<ObjectType, CursorShape> | 物体类型到指针形状的对应关系 |
| main_view_mode | enum | 主视野呈现方式：窗口/全屏/覆盖模糊三种模式 |
| platform_type | enum | 平台类型：个人计算机/控制台/掌上设备/手机 |
| screen_resolution | numeric | 影响空间平衡决策的关键硬件参数 |

## 输出结果

应用HUD设计后，应形成：
1. 半透明但透明度受控的覆盖层
2. 可自定义开关和位置的HUD元素
3. 一键隐藏全部HUD的功能选项

动态调整后的界面：隐藏/灰显不可用选项，或显示对应上下文的指针形态，从而降低认知负荷

确定的屏幕布局方案，包括：
- 主视野呈现方式决策
- 各UI元素的空间分配比例
- 针对特定平台的适配策略
