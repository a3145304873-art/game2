# 游戏条件逻辑定义与使用规范

使用条件逻辑定义游戏中的因果关系、过程控制和规则例外，确保逻辑完整性和无歧义性。

## 适用场景

- 定义胜利和失败条件
- 创建基于游戏状态的事件触发器
- 控制过程的启动和停止行为
- 建立规则的一般规定与例外处理
- 编写行为判定代码的逻辑规范

## 标准语法结构

使用以下三种标准格式定义条件逻辑：

### 1. 基本条件-动作
```
if (条件) then (执行一个事件，开始或者停止一个过程)
```

### 2. 持续监控
```
whenever (条件) take action to (执行一个事件，开始或者停止一个过程)
```

### 3. 持续时间控制
```
continue (一个过程) until (条件)
```

## 应用场景示例

### 胜利/失败条件
```
if (玩家生命值 <= 0) then (触发游戏结束事件)
if (敌人数量 == 0) then (触发胜利序列)
whenever (时间耗尽) take action to (停止游戏过程并判定失败)
```

### 过程控制
```
continue (资源生成过程) until (存储容量已满)
if (玩家进入触发区域) then (开始敌人刷新过程)
```

## 否定条件与例外处理

### 语法格式
```
if (条件) then do not (执行一个事件，开始或者停止一个过程)
```

### 关键约束
**否定条件不能单独使用**，必须配合一般规则，因为它是不完整的（未定义默认行为）。

### 正确用法示例

**步骤1 - 定义一般规则**：
```
当一只猫看见一只老鼠时，猫就会攻击老鼠。
```

**步骤2 - 定义例外**：
```
但是如果老鼠伪装成了猫，那么猫就不会攻击它。
```

### 错误用法示例

**无效定义**：
```
如果老鼠伪装成了猫，那么猫就不会攻击它。
```

**问题**：没有告诉程序员猫什么时候**会**攻击老鼠，逻辑不完整。

## 逻辑设计原则

1. **完整性**：每个例外必须依附于一个明确的一般规则
2. **布尔判定**：条件必须是可判断真假的明确状态
3. **动作具体化**：结果必须是具体的事件或过程控制指令
4. **避免歧义**：使用标准语法，避免自然语言的模糊性

## 验证清单

- [ ] 在添加例外之前已建立一般规则
- [ ] 条件是可布尔检查的真/假状态
- [ ] 动作是特定事件或过程控制（开始/停止）
- [ ] 没有独立的否定条件（所有否定都有对应的一般规则）
- [ ] 逻辑覆盖所有可能的边界情况
