# 实体设计详细案例

## 符号实体示例：交通灯

### 状态集合
- 红色（Red）
- 黄色（Yellow）
- 绿色（Green）

### 状态转换机制
```
初始状态：红色
定时器触发：红色 → 绿色
定时器触发：绿色 → 黄色
定时器触发：黄色 → 红色
```

### NPC司机交互机制

**机制1：看到红灯**
```
IF 交通灯状态 == 红色 THEN
  NPC司机：停止
  等待状态改变
```

**机制2：看到黄灯**
```
IF 交通灯状态 == 黄色 THEN
  IF 距离 < 安全距离 THEN
    NPC司机：停止
  ELSE
    NPC司机：加速通过
```

**机制3：看到绿灯**
```
IF 交通灯状态 == 绿色 THEN
  NPC司机：继续行驶
```

### 完整性验证
- 必须覆盖红、黄、绿三种状态
- 如果遗漏黄色状态，司机在黄灯时不会有任何反应


- 避免负值：行进速度不能为负

## 机制与UI分离示例：燃料警告

### 错误架构
```
UI层：
  IF 燃料 < 10% THEN
    点亮警告灯
```

**问题：**
- UI直接检测游戏数值
- 修改警告阈值需要修改UI代码
- UI设计师需要理解底层机制

### 正确架构
```
机制层：
  实体：燃料警告（状态：开/关）
  机制：
    IF 燃料 < 10% THEN
      燃料警告.状态 = 开
    ELSE
      燃料警告.状态 = 关

UI层：
  IF 燃料警告.状态 == 开 THEN
    点亮警告灯
  ELSE
    熄灭警告灯
```

**优势：**
- 机制与UI解耦
- 修改阈值只需修改机制
- UI设计师专注于显示逻辑

## 实体专属机制示例

### 陷阱实体
```
实体：陷阱
属性：
  - 功能属性：伤害值、触发范围
  - 外表属性：外观、位置

专属机制：
  触发条件：
    IF 玩家进入触发范围 THEN
      陷阱.状态 = 触发
      玩家.生命值 -= 伤害值
```

### AI控制NPC
```
实体：守卫NPC
专属机制：AI行为
  巡逻模式：
    沿预定路径移动
  警戒模式：
    IF 发现敌人 THEN
      追击敌人
    ELSE
      继续巡逻
```

## 设计调整阶段

### 值调整
- 在设计调整阶段将花费大量时间调整这些值
- 开始时不必过于担心准确度
- 通过迭代找到平衡点

### 机制修改
- 机制与UI分离后，修改机制不影响UI
- 修改UI不影响机制
- 提高开发效率
