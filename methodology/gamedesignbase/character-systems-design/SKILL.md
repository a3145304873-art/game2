# 角色系统与设计方法论

## 何时使用
- 设计游戏角色属性系统时
- 区分动态变化与静态特征时
- 确定角色设计主导方法论时
- 解决美术与叙事冲突时

## 角色属性二元分类框架

### 属性定义确认

识别描述角色的数据值，包括：
- 位置
- 健康状态
- 财富
- 感情状态
- 人际关系

这些变量构成游戏核心机制的一部分

### 分类判定标准（二元决策树）

**判定维度A**：变化频率（频繁 vs 不频繁）
**判定维度B**：数值变化幅度（大变化 vs 小变化/无变化）

**分类逻辑**
- IF (变化频繁 = TRUE) AND (数值变化大 = TRUE) THEN 归类为"状态属性（Status Attribute）"
- IF (变化频繁 = FALSE) AND (数值变化小或无 = TRUE) THEN 归类为"特征属性（Characterization Attribute）"

### 状态属性详细规范

**核心特征**
- 在游戏过程中随时改变
- 数值波动范围大

**功能定位**
- 反映角色当前临时状态
- 反映环境互动结果

**典型示例**

《龙与地下城》中的生命值（Hit Point, HP）或健康值
- 在打斗过程中随时改变

《模拟人生》中的需求系统
- 饥饿、舒适、卫生、活力、娱乐、社会需求和空间需求
- 通过指导角色从事活动（拜访邻居、洗澡）或改善环境来满足

**设计要点**
- 需要设计相应的恢复/消耗机制
- 与游戏核心玩法循环紧密耦合

### 特征属性详细规范

**核心特征**
- 改变得不频繁
- 改变的数值很小或者根本不改变
- 定义角色个性的基础细节

**功能定位**
- 建立角色身份认同
- 建立行为倾向的基线

**稳定性原则**
- 除非角色精神上生病，否则这些属性不会经常改变

**典型示例**

《龙与地下城》中的体质（Constitution）
- 表示角色的硬度和反抗伤害或毒气的整体程度
- 很少改变或根本不改变

《模拟人生》中的性格特质
- 整洁、外向、积极、顽皮及和蔼等性格特质
- 与其他模拟市民的关系属性
- 拥有相互冲突属性的模拟市民如果被迫交往，不能很好地相处

### 分类验证检查点

- 检查状态属性是否确实随游戏进程动态波动（如战斗、时间流逝）
- 检查特征属性是否保持稳定以维持角色个性一致性
- 确认两类属性的交互规则（如特征属性如何影响状态属性的变化速率或阈值）

## 艺术驱动与故事驱动角色设计方法论

### 方法论定义

**艺术驱动角色设计（Art-driven Character Design）**
- 核心原则：视觉美学、风格表达、艺术愿景优先
- 决策起点：美术团队的角色概念设计
- 叙事适配：故事需为视觉设计服务，调整背景以匹配外观
- 典型特征：独特视觉风格、形式重于功能、艺术表达优先

**故事驱动角色设计（Story-driven Character Design）**
- 核心原则：叙事功能、性格一致性、情节需求优先
- 决策起点：编剧/叙事设计师的角色功能需求
- 视觉适配：外观设计需服务于角色背景、性格和叙事弧
- 典型特征：深度背景故事、性格决定外观、功能重于形式

### 异同分析

**相似点**
- 都追求角色一致性
- 都追求玩家认同感
- 都追求美学价值

**差异点**
- 优先级冲突：视觉冲击力 vs 叙事合理性
- 决策权威：美术总监 vs 创意总监/叙事总监
- 迭代起点：草图视觉 vs 角色传记

### 互斥性原理执行逻辑

**根本原因**
- 两种方法论在决策冲突时的优先级判定标准根本不同
  - 艺术驱动："这个角色看起来酷/独特/有风格"为最终标准
  - 故事驱动："这个角色在故事中是谁、做什么"为最终标准

**资源集中需求**
- 高质量角色设计需要明确的主导方向
- 混合方法导致：
  - 视觉设计与背景故事脱节（如华丽盔甲但设定为贫困流浪者）
  - 叙事妥协以保留视觉元素，或视觉重做为符合叙事
  - 团队冲突（美术 vs 叙事部门）

**只能取其一原则**

步骤1：评估项目核心卖点（Core Selling Point）
- 如果是视觉风格/艺术体验（如《风之旅人》《Gris》）→ 选择艺术驱动
- 如果是叙事体验/角色关系（如《最后生还者》《巫师3》）→ 选择故事驱动

步骤2：确立主导部门权威

步骤3：另一部门转为支持/适配角色（而非平等决策）

### 混合模式警告

- 试图平衡两者通常导致角色缺乏鲜明特色（视觉平庸）
- 或叙事不一致（外观与行为矛盾）

## 设计决策流程

1. **定义角色属性**：列出所有描述角色的数据值
2. **分类属性类型**：根据变化频率和幅度分类为状态属性或特征属性
3. **设计属性机制**：为状态属性设计动态更新机制，为特征属性设计初始生成机制
4. **选择设计方法论**：根据项目核心卖点选择艺术驱动或故事驱动
5. **确立决策权威**：明确主导部门和决策流程
6. **验证一致性**：确保角色设计与整体游戏风格一致
