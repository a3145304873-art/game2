# 创造性玩法设计

## 使用时机
- 游戏设计包含创造性元素
- 玩家反馈要求无限制创造空间
- 需要支持玩家个性化表达
- 需要构建创造性玩法系统

## 创造型玩法分类框架

### 基础原理

所有游戏玩法均包含自我表达成分，因为玩家做出的决定会反映其游戏风格特征（如：小心谨慎 vs 粗心鲁莽，主动进攻 vs 被动防守等）。电子游戏扩展了这种表达可能性。

### 四种核心创造型/表现型玩法

#### 1. 自定义型玩法（Customization Gameplay）
- 玩家可以改进代表自己的化身（Avatar）
- 通过外观、装备、属性等维度实现自我表征

#### 2. 受限的创造型玩法（Constrained Creative Gameplay）
- 玩家可以发挥创造力，但是受到一定的限制
- 限制类型：资源限制、规则限制、空间限制等
- 在边界内创新

#### 3. 自由/无限制的创造型玩法（Free/Unrestricted Creative Gameplay）
- 玩家拥有高度自主权
- 创造过程不受或极少受到系统约束

#### 4. 编故事型玩法（Storytelling Gameplay）
- 玩家自己发明故事并展示给其他玩家
- 强调叙事创造和社会分享

### 进阶工具补充

- **关卡编辑器（Level Editor）**：允许玩家创建和修改游戏关卡内容
- **游戏修改（Game Modification/Mod）**：允许玩家修改游戏机制、资源或规则
- **机器人（Bots）**：允许玩家创建自动化代理或AI行为

目的：让玩家能够改进游戏且能自娱自乐

## 自由创造型玩法设计

### 核心概念定义

#### 自由创造型玩法的判定标准
- 玩家可使用「所有提供的设施」
- 「没有时间或资源上的任何限制」
- 唯一保留的限制是「强加的技术限制」（如硬件性能、引擎固有限制）

#### 沙盒模式（sandbox mode）的特征
- 是「受限的创造性玩法游戏」中的「特殊模式」
- 功能：「移除常规的限制」
- 玩家体验：「随意操作」，自由度极高
- 关键区别：「通常不像受限模式那样提供奖励」
- 本质转变：「在这种模式下的游戏更像是一个工具，而不是通常认为的电子游戏」

### 设计决策准则

#### 历史教训与必要性
- **反面案例**：第一代《过山车大亨》「并不包括沙盒模式」，在评论中「被列为一个缺陷」
- **改进结果**：「开发人员在以后的版本中加入了沙盒模式」
- **结论**：沙盒模式的缺失会被玩家和评论家视为设计缺陷

#### 通用设计建议
- **前提条件**：「如果你正在做一个提供创意的游戏」
- **建议行动**：「那你应该包括一个沙盒模式（如果可以的话）」
- **理由1**：「玩家喜欢它们」
- **理由2**：「沙盒模式不会与游戏的核心机制进行很多的互动（如果有的话），因此它们相当容易调整」——实现成本低，维护简单

### 典型案例分析

#### 早期成功案例：《豪华弹珠》
- 核心玩法：「让玩家建立并操作自己设计的虚拟弹球机」
- 类型：自由创造型玩法

#### 当代最成功的案例：《我的世界》创意模式
- 资源特征：「玩家拥有无限数量的方块」
- 移动能力：「还可以在空中飞行」
- 结果：「建设活动在很大程度上是不受约束的」

#### 内容创作扩展案例：《小小大星球》
- 创造范围：「允许玩家创建和共享所有关卡」
- 扩展内容：「大量其他模式的内容」

#### 元游戏创作案例：《星火计划》（微软即将发布）
- 野心层级：「让玩家构建整个视频游戏」

#### 简化创造案例：《你画我猜》
- 平台：「双人手机游戏」
- 玩法结构：
  - 玩家1：「绘制一个表示游戏给出的词的图片」
  - 玩家2：「必须通过查看图片来识别该词」
- 创造自由度：「执行绘图的玩家可以绘制他喜欢的任何东西」
- 初始限制：「颜色选择在最初是有限的」（渐进解锁设计）
- 证明：创作型玩法「不限于在一个复杂游戏世界中的沙盒模式」，简单机制也可实现

## 设计决策逻辑

根据目标玩家群体的创造能力、表达需求强度以及技术实现成本，从四种类型中选择合适的组合集成到游戏系统中。

## 关键变量

| 变量名 | 类型 | 描述 |
|--------|------|------|
| expression_style | enum | 玩家游戏风格类型（谨慎/鲁莽/进攻/防守等） |
| gameplay_type | enum | 创造型玩法类型（自定义/受限创造/自由创造/编故事） |
| constraint_level | string | 创造限制程度（高/中/低/无） |
| expression_target | enum | 表达对象（自我化身/游戏世界/故事叙事/其他玩家） |
| limit_type | enum | 限制类型：时间限制、资源限制、技术限制——前两者可移除，后者不可移除 |
| reward_mechanism | boolean | 奖励机制：沙盒模式通常为false，常规模式为true |
| creative_complexity | enum | 创造复杂度：从简单绘图到完整游戏构建的连续谱系 |

## 输出结果

设计决策：
- 是否在创意游戏中加入沙盒模式
- 若加入，确定其资源无限性、移动自由度、与核心机制的隔离程度
- 获得完整的创造型玩法分类体系，用于指导游戏设计中玩家自我表达机制的选择与实现
- 根据产品定位选择1种或多种玩法类型组合
- 决定是否引入关卡编辑器、Mod支持或机器人系统等进阶工具
