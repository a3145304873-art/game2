# 游戏调整高效方法论

## 触发条件

IF (需要调整游戏平衡性/移除统治性策略/修复难度突变) AND (游戏处于后期开发阶段) THEN 应用此调整方法论

## 前置条件

- 游戏已进入后期开发阶段
- 存在可调整的参数系统
- 具备测试环境

## 四项核心原则

### 1. 一次只修改一个参数

**执行流程：**
- 调整一个参数 → 检查结果 → 再调整另一个参数
- 禁止同时修改多个参数

**重要性：**
- 如果同时修改多个参数，无法确定哪个更改导致了结果
- 虽然看似乏味，但确实非常有用

**风险：**
- 如果开发人员无法正确调整游戏，或程序太烂，发布商可能取消项目

### 2. 修改幅度要大，不能太小

**专家建议**（Brian Reynolds，Big Huge Games）：
- 开始时加倍参数值，或减半个参数值
- 检查修改后的结果

**原因：**
- 小的调整可能产生检测不到的微妙改变
- 大的改变更容易接近最合适的设置

**操作流程：**
1. 做出大的改变
2. 反复减少和测试
3. 一步步向理想值移动

### 3. 保持记录

**记录内容：**
- 所做的参数修改
- 修改后的测试结果
- 观察到的游戏表现变化

**目的：**
- 避免在相同的事情上重复浪费精力
- 可以看到改变的效果并从中学习经验

### 4. 确保程序员使用伪随机数

**目的：**
- 控制偶然性的效果
- 在改变参数和测试结果时保持机制的稳定

**参考：**
- 第14章中关于伪随机数的详细讲解

## 约束条件

- 不适用于前期原型阶段
- 不适用于无参数化设计的游戏

## 输出成果

通过系统化的参数调整流程，逐步逼近游戏的最佳平衡状态，同时积累可复用的调整经验。
