# 伪随机数生成与种子管理

使用数学算法和种子(seed)生成确定性的随机数序列，实现开发阶段的可重现性与发布阶段的体验多样性。

## 适用场景

- 游戏开发中需要可重现的随机事件（程序化地图生成、掉落表、AI行为）
- 软件测试需要确定性结果以便复现特定随机触发的bug
- 需要"录制"和"回放"随机过程的场景（如游戏录像、自动化测试）
- **不适用**：密码学密钥生成、安全令牌、赌博系统审计等需要密码学安全随机性的场景

## 核心概念

**真正随机数 vs 伪随机数**
- 真正随机数：依赖物理过程（硬件噪声、量子现象），不可重现，需要特殊硬件
- 伪随机数：基于确定性数学公式，序列完全由初始输入（种子）决定

**种子(Seed)机制**
- 种子是随机数生成算法的初始输入值
- 关键特性：相同种子 → 完全相同的随机数序列
- 类比：就像玩棋盘游戏时，如果这一次和上一次使用相同的"运气序列"，虽然每一掷看起来随机，但整个游戏过程中的骰子序列会完全相同

## 执行流程

### 1. 选择并配置随机数生成器

确认你的编程环境是否支持种子设置：

**如果标准库支持种子设置**（如Python的`random.seed()`, C++的`srand()`, Java的`Random(seed)`）：
- 直接使用标准库功能

**如果标准库不支持种子设置**（如早期JavaScript的`Math.random()`）：
- 寻找支持种子的第三方库（如seedrandom.js）
- 或自行实现简单的伪随机数生成器（如线性同余生成器）
- 在互联网搜索"[你的语言] random number generator with seed"

### 2. 开发阶段：使用固定种子

在编码和调试期间，硬编码一个固定种子值：

```
seed = 12345  // 或使用有意义的数字如版本号
initialize_generator(seed)
```

- 确保团队成员每次运行看到相同的随机事件序列
- 便于复现特定随机触发的边界情况
- 支持"录制-回放"调试：记录种子即可重现整个随机过程

### 3. 生成并使用随机数序列

基于种子生成确定性序列：

```
// 初始化后，序列已确定
random_value_1 = generate_next()  // 总是相同的第一个值
random_value_2 = generate_next()  // 总是相同的第二个值
// ... 序列完全由种子预先决定
```

### 4. 发布阶段：切换为动态种子

在最终构建发布版本前，修改代码使种子来自不可预测的来源：

```
// 发布版本代码
seed = get_system_timestamp()  // 或硬件熵源
// 或使用保存的存档中的种子（如果需要跨会话一致性）
initialize_generator(seed)
```

- 确保玩家每次新游戏获得不同体验
- 保留伪随机数的统计分布特性
- 如果需要可分享的种子（如《我的世界》地图种子），提供选项让玩家查看和输入特定种子

## 关键检查点

- [ ] **种子可设置性**：确认使用的随机数库允许显式设置种子
- [ ] **开发一致性**：调试 builds 使用硬编码种子，确保所有人看到相同序列
- [ ] **发布随机性**：发布 builds 使用系统时间、进程ID或硬件熵作为种子
- [ ] **存档兼容性**：如果随机状态需要跨存档保持，确保保存当前生成器状态或种子
- [ ] **避免混淆**：确保不会意外将开发用的固定种子编译进发布版本

## 常见陷阱

- **并发问题**：多线程环境下，每个线程需要独立的随机数生成器实例，避免共享种子状态导致竞争条件
- **种子冲突**：使用系统时间作为种子时，快速连续启动可能获得相同时间戳，应添加额外熵源（如进程ID）
- **周期限制**：简单伪随机数算法有周期限制，超长序列可能开始重复，游戏开发通常无需担心，但模拟和科学计算需注意
- **分布偏差**：确保使用的算法符合你需要的统计分布（均匀分布、正态分布等）
