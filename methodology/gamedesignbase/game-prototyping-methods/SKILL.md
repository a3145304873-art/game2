# 游戏原型设计方法

## 原型定义

原型是一个简化的，但可进行测试的游戏版本，用于在正式投入时间和物力之前测试游戏功能，有时让目标人群参与测试以判断玩家满意度。

## 类型一：软件原型

### 构建原则
- 不需要完整包含整个游戏，只需测试某一部分即可

### 推荐工具
- Game Maker（比从头开始更容易）
- Unity、Adobe Flash、HTML 5（提供许多功能）

### 人员要求
- 需要程序员朋友，或自己就是程序员

### 仿真度特征
- 允许创建"高仿真的原型"，与真实游戏非常接近（但也可能是低仿真）

### 时间成本
- 比其他类型需要更长的时间

### 转化优势
- 产生的结果可以很容易地转化为真实的东西

### 关键警告
- "不要假设在最终的游戏中你会使用为原型创建的软件"

### 核心要点
- "能够快速完成，而不必担心代码或图形的质量"

### 可抛弃原则
- 创建原型时可以抛弃所有的音效、艺术和代码
- 让艺术师、音效师和程序员快速工作而不必担心调试漏洞

### 分模块策略
- 不必在同一个软件原型中实现游戏的所有方面
- **示例：** 在几乎没有图形的原型中实现游戏的内部经济
- **示例：** 在不包含工作机制的不同原型中尝试图形引擎和用户界面

## 类型二：纸质原型

### 定义
桌面版本的游戏——棋盘游戏、纸牌游戏或其他非计算机操作的游戏

### 适用对象
- 设计团队一起玩游戏
- 或在代表目标受众的朋友身上尝试

### 不适用情况
- "不适用于需要大量数字处理的或者基于物理模型的游戏"

### 流行领域
- "团队竞技、解谜等这些需要玩家互动的多人游戏中尤为盛行"

### 组合策略
- "即使游戏的一部分是基于物理模型的，你仍然可以制作一个纸质原型来测试其他部分"

### 必备工具清单
- 骰子
- 计数器或令牌（如扑克牌的筹码）
- 方格纸
- 空白卡
- 笔记本

### 核心优势
- "能够快速更改游戏的规则，并进行二次尝试"

### 执行方式
- 使用工具快速设计出电子游戏的纸上版本
- 与朋友一起尝试

## 类型三：物理原型

### 定义
在现实生活中扮演玩家的角色

### 应用场景示例
- 在游戏构建的环境中尝试战斗移动
- 玩涉及物理知识的游戏，例如投掷物体

### 现实限制
- "不可能真的像马里奥那样跳跃"

### 核心价值
- 使用身体和物理定律来试验游戏中可能的玩家动作
- 找出实现电子游戏可能需要什么样的动画

### 与运动捕获的关系
- 是"进行运动捕获的自然前提"

### 与纸质原型的关系
- "很好地补充了纸质原型"

### 组合策略示例
- 策略和战术元素的游戏：在纸质原型上测试策略部分
- 在物理原型中试验战术部分

## 原型类型选择决策树

### 评估维度

1. **测试目标**：需要验证的具体游戏功能或玩家体验维度
2. **仿真度需求**：高仿真/低仿真
3. **时间预算**：可用于原型制作的时间
4. **程序员资源**：是否有程序员支持
5. **物理模型依赖度**：高/中/低，影响纸质原型适用性

### 选择建议

| 条件 | 推荐原型类型 |
|------|------------|
| 需要高仿真度 + 有程序员支持 | 软件原型 |
| 需要快速测试规则 + 无程序员 | 纸质原型 |
| 需要测试物理动作 + 动画设计 | 物理原型 |
| 策略游戏 + 战术游戏 | 纸质原型 + 物理原型组合 |
| 经济系统测试 | 软件原型（简化图形） |

## 通用生产管理建议

"试图在预生产期间就构建好生产质量管理体系，以防因质量管控问题延误时间"
