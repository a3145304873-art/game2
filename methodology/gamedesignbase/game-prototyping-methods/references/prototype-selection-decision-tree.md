# 原型类型选择决策树

## 开始

### 问题1：你的测试目标是什么？

- A. 验证核心游戏机制和规则 → 转问题2
- B. 验证玩家交互和物理动作 → 转问题3
- C. 验证完整游戏体验和视觉效果 → 转问题4

### 问题2：是否有程序员支持？

- 是 → 转问题5
- 否 → **推荐：纸质原型**

### 问题3：动作是否依赖复杂物理模拟？

- 是 → **推荐：物理原型**
- 否 → 转问题2

### 问题4：时间预算是否充足（超过2周）？

- 是 → 转问题6
- 否 → **推荐：纸质原型**

### 问题5：需要高仿真度吗？

- 是 → **推荐：软件原型（高仿真）**
- 否 → **推荐：软件原型（低仿真）或纸质原型**

### 问题6：是否有足够的技术资源？

- 是 → **推荐：软件原型**
- 否 → **推荐：纸质原型 + 视觉概念图**

## 组合策略

### 策略游戏
- 纸质原型：测试策略和规则
- 软件原型：测试UI和反馈

### 动作游戏
- 物理原型：测试动作和动画
- 软件原型：测试碰撞和响应

### 模拟游戏
- 纸质原型：测试经济系统
- 软件原型：测试数值平衡

## 原型评估标准

- [ ] 是否回答了测试目标的问题？
- [ ] 是否在时间预算内完成？
- [ ] 是否提供了可操作的反馈？
- [ ] 是否可以快速迭代？
