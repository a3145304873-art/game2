# NPC个性化偏好谜题系统设计

## 何时使用

当满足以下条件时，实施此系统：
- 游戏核心循环包含为NPC客户创造/选择物品（服装、配饰、造型、室内装潢等）
- 需要避免"一刀切"的评分标准，让每个客户成为独立谜题
- 希望通过重复交互建立玩家与NPC的长期关系
- 需要支持非传统搭配的多样化解决方案

## 核心实施流程

### 1. 配置NPC偏好数据
为每个客户分配独特的审美档案：
- **风格标签**：公主风、朋克风、哥特风、现代风、复古风等（枚举类型）
- **难度曲线**：初始模糊需求，随关系深入逐渐明确
- **特殊禁忌**：某些NPC可能明确厌恶特定元素（如"讨厌粉色"）

### 2. 设计迭代反馈循环
建立四步交互流程：
1. **需求提出**：NPC给出初始需求描述（可能模糊或具体，取决于关系等级）
2. **方案提交**：玩家提出套装/设计方案
3. **判断反馈**：
   - **接受**：交易成功，记录满意度等级（1-5或类似）
   - **拒绝**：NPC提供暗示线索（如"我更喜欢尖锐的配饰"或"这太朴素了"）
4. **迭代优化**：玩家根据线索调整，返回步骤2

### 3. 满意度与回头客机制
- **满意度计算**：基于方案与隐藏偏好的匹配度
- **回头客生成**：高满意度客户会再次光顾，带来重复业务
- **关系进展**：重复业务解锁更具体的偏好信息，降低后续服务难度

### 4. 多样化解决方案支持
- 允许多个"正确答案"：只要符合该NPC的特定口味，非传统搭配也能成功
- 避免全局统一标准：每个NPC是独立谜题，A喜欢的方案B可能讨厌

## 关键变量配置

| 变量名 | 类型 | 说明 |
|--------|------|------|
| `npc_style_tags` | 枚举数组 | 该NPC偏好的风格标签组合 |
| `satisfaction_level` | 整数 | 当前交互的满意度，影响回头客概率 |
| `hint_clues` | 字符串数组 | 拒绝时可轮播的提示语库 |
| `relationship_level` | 整数 | 关系等级，决定初始需求明确度 |

## 与固定规则系统的区别

| 维度 | 固定规则系统 | 个性化偏好系统 |
|------|-------------|---------------|
| 评价标准 | 单一标准适用于所有情况 | 每个客户独立标准 |
| 解决方案 | 通常只有一个最优解 | 允许多样化方案共存 |
| 重复可玩性 | 低，最优解一旦找到即固化 | 高，每个新客户都是新谜题 |
| 玩家体验 | 机械执行 | 解谜与关系建立 |

## 示例场景

**NPC档案**：莉莉（哥特风爱好者，讨厌明亮颜色）
- **初次交互**："我需要一件适合音乐会的衣服"（模糊）
- **玩家提交**：粉色公主裙
- **反馈**："这太甜腻了，我喜欢更暗一点的风格"
- **调整后提交**：黑色蕾丝裙+银色配饰
- **结果**：满意度★★★★☆，解锁回头客"下周的派对我还需要你帮忙"
