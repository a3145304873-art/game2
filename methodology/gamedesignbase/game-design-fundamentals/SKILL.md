# 游戏设计基础理论

## 使用场景
- 需要界定某项活动是否属于游戏
- 分析游戏的结构完整性
- 设计游戏核心机制和规则系统
- 对游戏进行分类和类型定义

## 游戏的核心定义

### 判定标准
某项活动要被定义为游戏，必须满足以下条件：

1. **虚拟环境**：必须存在一种虚拟环境或模拟场景
2. **规则约束**：参与者必须按照规则行动
3. **目标导向**：旨在实现至少一个既定的、带有重要目标任务
4. **娱乐性质**：属于娱乐性活动

### 四大必备要素
1. **可玩性**：即"能玩"
2. **假想性**：即能满足某些幻想
3. **游戏目标**：参与者试图达成的既定结果
4. **游戏规则**：限制和引导参与者行动的规范

> 注意：该定义旨在覆盖大多数情况，而非绝对严谨。现实中存在例外（有些明显是游戏但不符合上述定义）。

## 游戏可玩性的构成

游戏的可玩性由两部分组成：

### 1. 挑战（Challenge）
起到娱乐作用的任务或障碍，能产生紧张和戏剧性效果。

**挑战的心理学机制：**
- **基于能力的挑战**：只要人们期盼自己拥有完成挑战的能力，就说明他们是喜欢挑战的
- **意外惊喜的挑战**：人们也希望尝试不曾期盼过的"低风险、高回报"的挑战
- **基础级别设计**：在最简单的挑战级别下，呈现给玩家的挑战要加上"你能做到吗？"之类的问句

### 2. 动作（Action）
玩家应对挑战或自主进行的行为。

**动作的特征：**
- 现实补偿：在现实中昂贵或不可能的事情，在游戏中可以得到满足
- 独立价值：即使有些动作不会对游戏最终结果产生影响，它仍然值得去做（如儿童游戏中的玩具元素）

## 游戏规则的六大功能组件

### 组件列表
1. **符号语言**：游戏所使用的不同符号的意义和联系（抽象符号如击球/出局，具象符号如游戏军队与现实相似性）
2. **可玩性**：包括游戏的挑战性和玩家的可操作性
3. **操作序列**：组成游戏的一系列动作
4. **任务目标**：由规则定义的游戏目标
5. **终止条件**：使游戏结束的条件（如果游戏能够结束）
6. **超规则**：关于规则的规则，指出规则可被改变的情况或允许例外发生的时机

### 规则设计原则
- **明确性要求**：应当是明确无误的，以避免解释时存在争议
- **一致性要求**：各规则要一致，不应该存在冲突
- **冲突解决**：如有冲突发生，应设定超规则来决定采用哪条规则
- **质量标志**：规则模糊或存在冲突都是不好的游戏设计的标志

## 游戏类别（Genre）的定义

### 核心定义
在电子游戏行业中，"类别"表示游戏中提供的**挑战**，而非内容。

### 独立性原则
游戏类别独立于游戏内容之外存在。游戏的具体设置或世界观（如古代西部、魔幻世界、外太空）不影响其类别归类。

### 现代混合性
现代游戏常混合多种游戏类别：
- **单一模式混合**：在单一可玩性模式中结合多种挑战
- **多模式混合**：在不同游戏模式中加入多种挑战

## 执行流程

### 分析游戏是否为游戏
```
IF (存在虚拟环境 AND 有规则约束 AND 有既定目标 AND 属于娱乐活动)
THEN 判定为游戏
ELSE 视作例外情况处理
```

### 设计游戏可玩性
1. 确定挑战类型（基于能力或意外惊喜）
2. 设计应对挑战的动作
3. 确保动作具有现实补偿价值或独立娱乐价值

### 构建规则系统
1. 定义六大功能组件
2. 确保规则明确且一致
3. 设定超规则处理潜在冲突

### 确定游戏类别
1. 识别游戏提供的核心挑战
2. 检查是否混合多种挑战类型
3. 根据挑战而非背景题材确定类别
