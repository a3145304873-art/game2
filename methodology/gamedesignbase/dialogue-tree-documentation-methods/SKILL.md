# 对话树文档化方法

## 使用场景
- 需要记录包含条件内容的脚本化对话
- 不使用专业设计软件
- 需要确保技术实现准确性
- 团队具备基础编程经验或办公软件使用能力

## 文档化方法选择

### 1. 电子表格方法
**适用情况**：
- 团队偏好结构化数据管理
- 需要灵活扩展对话规模

**操作优势**：
- 可轻松添加行和列，适应对话规模变化
- 保持文档整洁，便于阅读和审阅
- 使用多个表格管理不同场景或角色对话

**实施建议**：
- 利用单元格组织对话节点 ID
- 记录文本内容、跳转条件、语音文件名等字段

### 2. 伪代码方法
**前提条件**：团队成员需要有一点编程经验

**操作方法**：
- 编写伪代码描述对话树逻辑结构
- 使用类编程语法（IF、ELSE、GOTO）表示对话流程
- 使用缩进结构表示对话层级

**沟通优势**：
- 程序员可直接理解逻辑结构
- 无需解释图形化表示
- 最简单的技术沟通方式

**示例**：
```
IF (player_has_key) THEN
  SHOW "你打开了门"
ELSE
  SHOW "门被锁住了"
  OPTION "离开" -> END
```

### 3. 箭头图表方法
**局限性**：
- 对于包含复杂条件分支的对话可能难以清晰表达
- IF-THEN 逻辑、变量检查等复杂逻辑难以展示

## 关键沟通验证步骤

无论选择何种方法，必须执行以下验证：

1. **核心原则**：让程序员理解对话
2. **验证要求**：确保编程团队完全理解
   - 对话结构
   - 条件逻辑节点
   - 流程跳转规则
3. **最终目标**：游戏运行时对话行为与设计意图完全一致
4. **协作检查**：通过原型或文档审查确认理解无误

## 约束条件
- 箭头图表可能不适用于复杂条件内容
- 伪代码方法要求团队具备编程背景
- 电子表格方法可能缺乏可视化流程展示
