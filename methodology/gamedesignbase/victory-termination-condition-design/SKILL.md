# 胜利条件与终止条件设计

## 何时使用

- 设计包含2名或以上玩家的竞技游戏结束机制
- 需要明确区分"谁获胜"与"何时停止游戏"两个独立概念
- 确定多人游戏中第一名产生后是否继续决出后续名次
- 建立比赛系统的胜负判定标准和流程终止规则

## 核心概念

**胜利条件（Victory Condition）**：游戏规则定义的成功条件，明确判定谁获胜。关注"谁赢"。

**终止条件（Termination Condition）**：决定游戏何时结束的规则，与胜利条件逻辑上独立。关注"何时停"。

## 执行流程

### 步骤1：确认玩家数量
确定游戏是双人对抗（2人）还是多人竞技（>2人）。

### 步骤2：应用对应规则

**情况A：双人游戏（玩家数量 = 2）**
- 终止条件与胜利条件重合
- 一方达成胜利条件时，游戏立即终止
- 执行：定义明确的胜利条件即可，终止条件自动继承

**情况B：多人游戏（玩家数量 > 2）**
选择以下两种模式之一：

**模式1：即时终止（终止条件 = 胜利条件）**
- 第一名产生时游戏立即结束
- 适用：只需确定冠军，不关心后续名次的场景
- 执行：设置触发器为"首个玩家达成胜利条件"

**模式2：完整排名（终止条件 ≠ 胜利条件）**
- 第一名产生后游戏继续进行
- 持续至决出第二名、第三名，或最后一名完成
- 适用：需要完整排名、积分计算或淘汰制的场景
- 执行：单独定义终止触发器（如最后一名完成、特定比例玩家完成、时间耗尽等）

### 步骤3：定义平局处理（可选）
如需避免平局，建立附加赛机制（tie-breaker）确保明确获胜方。

## 决策树速查

```
IF 玩家数量 = 2 THEN
    终止条件 = 胜利条件
    游戏在一方获胜时立即结束
ELSE IF 玩家数量 > 2 THEN
    IF 只需要确定冠军 THEN
        终止条件 = 胜利条件（第一名产生即结束）
    ELSE IF 需要完整排名 THEN
        终止条件 = 最后一名完成 / 特定比例完成 / 时间结束
        游戏持续进行以确定后续名次
    END IF
END IF
```

## 关键检查点

- [ ] 胜利条件定义清晰（具体达成什么目标算获胜）
- [ ] 根据玩家数量正确区分终止条件与胜利条件的关系
- [ ] 多人游戏中已明确是否继续决出后续名次
- [ ] 终止触发器具体且可判定（如"最后一名通过终点线"）
- [ ] 如需避免平局，已设计平局打破机制
