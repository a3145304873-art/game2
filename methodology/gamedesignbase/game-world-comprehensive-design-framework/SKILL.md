# 游戏世界综合设计框架

## 使用时机
- 需要设计或验证游戏世界的空间架构
- 需要设计或验证游戏世界的时间系统
- 处于游戏设计文档(GDD)编写阶段
- 已具备基础游戏概念，需要构建或完善游戏世界架构

## 第一阶段：物理维度评估

### 1. 物理维度必要性评估

**判定问题**
- 游戏是否需要物理维度系统？
- 物理维度的具体用途是什么（gameplay机制 vs 视觉表现）？
- 物理维度是游戏设置的核心必要部分，还是仅作为装饰性元素存在？

### 2. 虚构空间维度数量与结构

**确定维度数量**
- 不考虑技术实现或显示限制，确定需要多少个虚构空间维度（2D/3D/高维）

**连续性评估**
- 若存在三维或更高维度，物体能否在这些维度之间连续移动？
- 或这些维度是否分割成相对独立的图层（layers）或区域（zones）？

### 3. 世界尺度与计量单位

**确定整体大小量级**
- 光年级宇宙尺度
- 英尺级室内尺度
- 其他尺度

**评估比例准确性**
- 足球竞技游戏需要精确比例
- 卡通动作游戏可接受夸张比例

### 4. 多比例系统需求

**判定是否需要多重比例系统**
- 室内比例与室外比例差异
- 不同场景下的比例应用

**计算实际需要的比例数量**
- 避免过度设计

### 5. 相对尺寸与速度关系

**设定相对尺寸标准**
- 物品与人物之间的相对尺寸

**设定相对速度关系**
- 物品移动速度与人物移动速度的相对关系

**确保物理交互一致性**

### 6. 世界边界设计

**设计边界物理形态**
- 无形墙
- 自然障碍
- 循环空间
- 其他形式

**评估掩盖需求**
- 是否需要投入资源掩盖"世界的边界"？
- 掩盖手段：迷雾、山脉、海洋等

**设计系统响应**
- 玩家尝试走出边界时的系统响应：
  - 阻挡
  - 伤害
  - 传送
  - 剧情杀
  - 其他

## 第二阶段：时间维度评估

### 1. 时间系统基础设定

**判定时间因素是否有意义**

**选择时间流逝模式**
- 模式A：时间始终变化（即使玩家无操作）
- 模式B：时间静止，仅在玩家移动/操作时推进

### 2. 时间对世界环境的影响

**列举具体影响**
- 食物腐烂机制
- 电灯泡烧坏机制
- 建筑风化
- 其他环境变化

**设计环境衰败或演变规则**

### 3. 时间对玩家角色的影响

**设计生理影响**
- 饥饿值累积
- 疲倦度增加
- 年龄增长
- 其他影响

**确定gameplay后果**

### 4. 时间系统的目的性验证

**明确加入时间因素的实际目的**
- 目的A：纯粹烘托游戏氛围（沉浸式体验）
- 目的B：游戏可玩性的必要组成部分（机制驱动）

**验证与核心玩法的关联度**

### 5. 时间量化与计量系统

**判定是否存在时间比例**
- 游戏时间 vs 现实时间压缩比

**选择量化精度**
- 精确量化：使用小时、天、年等单位
- 模糊时间：无需严格量化，使用"早晨/傍晚"等描述

**评估UI需求**
- 玩家是否需要钟表/日历界面记录时间？

### 6. 时间段跳过机制

**识别需要跳过或摒弃的时间段**
- 长途旅行中的夜晚
- 农作物生长等待期
- 其他等待场景

**选择跳过方式**
- 方式A：需要玩家在场（黑屏过渡、动画展示）
- 方式B：无缝跳过（后台计算，瞬间完成）

### 7. 昼夜与季节系统

**判定是否需要昼夜循环系统**

**设计昼夜区分要素**
- 外观层面：光照、天空盒、环境色调变化
- 功能层面：NPC行为变化、怪物刷新规则、商店营业时间

**评估是否需要四季系统**
- 四季对gameplay的深度影响

### 8. 时间异常事件设计

**判定是否会出现时间异常**
- 时间倒流
- 时间停滞
- 时间加速区域
- 其他异常

**设计发生原因**
- 剧情触发
- 玩家技能
- 特定区域特性

**评估影响范围**
- 视觉干扰
- 机制改变
- 剧情分支

**设计解释机制**
- UI提示
- NPC对话
- 环境叙事

### 9. 玩家时间控制权

**判定是否允许玩家调整时间**
- 睡眠跳过
- 时间魔法
- 设置菜单
- 其他方式

**明确允许调整的原因**
- 便利性
- 核心机制

**设计调整方法**
- 床铺交互
- 物品使用
- 菜单选项

**设定可调整的时间窗口**
- 随时可调整
- 仅限安全区域

## 执行要求

每个问题的回答必须形成书面设计决策，并记录在案作为后续开发的基准规范。

## 关键变量

| 变量名 | 类型 | 描述 |
|--------|------|------|
| spatial_dimension_count | integer | 游戏世界空间维度数量（2/3/4+） |
| world_scale_unit | string | 世界尺度计量单位（光年/公里/米/英尺等） |
| time_flow_mode | enum | 时间流逝模式（continuous/player_triggered） |
| time_compression_ratio | float | 游戏时间与现实时间压缩比例 |
| boundary_masking_method | string | 世界边界掩盖技术方案 |
| temporal_anomaly_enabled | boolean | 是否启用时间异常机制 |

## 输出结果

生成完整的《游戏世界维度设计规范文档》，包含：
1. 物理维度设计决策表（含尺度、边界、多比例方案）
2. 时间系统设计决策表（含流逝模式、昼夜季节、玩家控制权限）
3. 技术实现优先级清单
4. 与核心玩法机制的关联性说明
