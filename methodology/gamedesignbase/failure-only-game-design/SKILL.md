# 仅含失败条件的游戏设计

## 何时使用此技能

- 设计无尽跑酷、生存模式、高分挑战类游戏
- 需要避免明确胜利状态，让玩家持续游玩
- 目标从"击败游戏"转换为"打破个人记录"
- 适用对象：无尽跑酷游戏、生存游戏、高分挑战游戏、街机游戏

## 不适用场景

- 叙事驱动游戏
- 有明确结局的关卡制游戏
- 需要明确胜利者的竞技游戏

## 核心设计流程

### 第一步：定义失败条件

确定游戏结束的唯一触发方式：

| 失败类型 | 典型触发条件 | 适用游戏 |
|---------|-----------|---------|
| 碰撞型 | 撞击障碍物、敌人 | 跑酷游戏 |
| 资源型 | 生命值归零、能量耗尽 | 生存游戏 |
| 时间型 | 倒计时结束 | 限时挑战 |
| 位置型 | 掉落深渊、离开安全区 | 平台跳跃 |

### 第二步：构建无限进行机制

确保游戏可以理论上无限持续：

1. **程序生成内容**：关卡/障碍物动态生成，无预设终点
2. **难度递增曲线**：随时间或进度提升挑战，但不过早达到不可能完成的难度
3. **状态重置机制**：每局独立，不累积永久性优势

### 第三步：转换玩家目标

将玩家动机从"获胜"重新定位为：

- **生存时长**：能坚持多久
- **分数竞争**：全球/好友排行榜
- **成就解锁**：特定条件下的徽章/称号
- **技能精进**：操作熟练度的自我证明

### 第四步：设计反馈循环

```
开始游戏 → 持续挑战 → 接近失败边缘 → 触发失败条件
    ↑                                    ↓
    ←←←← 显示成绩/打破记录/再试一次 ←←←
```

关键反馈元素：
- 即时死亡反馈（无延迟）
- 本局成绩与历史最佳对比
- 可分享的里程碑（"存活60秒！"）

## 快速检查清单

- [ ] 已定义单一、清晰的失败条件
- [ ] 游戏机制支持无限进行（无硬编码终点）
- [ ] 玩家有明确的替代目标（分数/时长/排名）
- [ ] 失败反馈即时且激励重试
- [ ] 难度曲线可持续但不至于早期崩盘

## 经典参考

《疯狂喷气机》(Jetpack Joyride)：撞上障碍物即失败，否则无限进行，目标为赚取最高分。
