# 仅含失败条件游戏的设计模式

## 难度递增算法

### 线性递增
```
difficulty = base_difficulty + (time_elapsed * scaling_factor)
```
- 优点：可预测，玩家易建立心理模型
- 缺点：后期可能过于困难或单调

### 波浪式递增
```
difficulty = base_difficulty + wave_amplitude * sin(time_elapsed / wave_period) + (time_elapsed * slow_scaling)
```
- 优点：给予玩家喘息空间
- 缺点：需要精细调校避免"简单段"过长

### 自适应难度（动态）
```
difficulty = f(player_performance_recent_30_seconds)
```
- 优点：适配不同水平玩家
- 风险：可能被玩家察觉并操控

## 玩家留存机制

### 短期循环（单局内）
| 机制 | 目的 | 示例 |
|-----|------|------|
| 连击系统 | 维持专注 | 连续躲避奖励递增分数 |
| 危险奖励 | 鼓励冒险 | 靠近障碍物获得额外分 |
| 临时强化 | 能力波动 | 短暂无敌/加速 |

### 长期循环（跨局）
| 机制 | 目的 | 示例 |
|-----|------|------|
| 元进度 | 持续解锁 | 新角色/皮肤/起始道具 |
| 任务系统 | 每日回归 | 完成特定挑战获奖励 |
| 赛季排行榜 | 社群竞争 | 周期性重置排名 |

## 失败条件的变体设计

### 多重失败条件（任一触发即结束）
- 生命值归零 **或** 时间耗尽 **或** 掉落深渊
- 增加复杂度，玩家需多维度监控

### 累积式失败（渐进警告）
- 三次小失误 = 最终失败
- 给予玩家挽回机会，降低挫败感

### 可选失败条件（玩家自选难度）
- 普通模式：碰撞即死
- 硬核模式：任何擦碰即死 + 速度加倍
- 增加重玩价值

## 心理学原理

### 心流通道维持
仅含失败条件的游戏必须精确维持心流状态：
- 挑战过低 → 无聊放弃
- 挑战过高 → 焦虑放弃
- 甜蜜点：技能与挑战持续匹配

### 损失厌恶的应用
- 显示"距离前一名还差 X 分"比"你的排名是 Y"更有效
- 本局获得的临时强化失去时产生强烈重启动机

### 蔡格尼克效应
未完成的挑战（"差一点就破纪录"）驱动玩家再次尝试

## 常见设计陷阱

| 陷阱 | 表现 | 解决方案 |
|-----|------|---------|
| 过早封顶 | 顶尖玩家达到理论极限后失去目标 | 引入分数膨胀或新维度挑战 |
| 随机暴毙 | 玩家感觉死亡非自身失误 | 确保所有威胁可预测/可学习 |
| 单调循环 | 长时间游玩后感觉重复 | 阶段性引入新机制/变体 |
| 虚假选择 | 道具/升级无实际影响 | 确保所有选择有显著差异 |

## 电影《战争游戏》引用解析

> "一个奇怪的游戏，唯一能取得胜利的方法就是不去玩它"

在仅含失败条件的游戏设计中，这句话的悖论性启示：
- 玩家通过"持续游玩"来"获胜"（打破记录）
- 但"停止游玩"意味着承认当前极限
- 设计应让玩家感到"再来一次就能突破"而非"永远无法真正完成"

## 跨平台适配要点

| 平台 | 特殊考量 |
|-----|---------|
| 移动端 | 单局时长控制在2-5分钟，支持随时暂停/退出 |
| 主机/PC | 可支持更长单局，更复杂操作 |
| 街机 | 强调即时重投币，视觉反馈夸张化 |
| 网页 | 加载极快，进度云端同步 |
