# 角色深度与个性设计

## 使用场景
- 设计主要角色的背景故事时
- 测试角色性格一致性时
- 设计同伴角色系统时
- 创建互补型双人合作角色时
- 需要在游戏中展示角色个性时

## 角色深度设计流程

### 1. 区分角色类型与设计深度
- **小角色**（如仅出现30秒的服务生）：仅需通过外表和声音传达信息，无需详细生平
- **主要角色**：需要丰富的人物性格，必须进行深度设计

### 2. 创建人物背景单（Backgrounder）

#### 格式要求
- 不必用叙述方式，写下各个特征的列表即可
- 重要的是把相关信息记录在纸上

#### 必须回答的问题清单（针对普通人）
- 角色在哪里出生？
- 童年家庭生活是什么样的，教育背景是什么？
- 现在住在哪里？
- 描述他的工作
- 描述他的经济状况
- 描述他对衣服、书籍、电影等的品位。最喜欢的食物是什么？
- 最喜欢的活动是什么？
- 业余爱好是什么？
- 描述他所有的独特的人格特性及它们是如何出现的
- 他是内向还是外向的？是贪婪还是慷慨的？
- 他有怪癖吗？
- 他迷信吗？
- 他有恐惧症吗？
- 他在生命中受到创伤的时刻有哪些？
- 他最大的成功是什么？
- 描述他过去重要的浪漫史
- 描述他当前的恋人或者恋人们
- 他怎样对待朋友、爱人、老板、仆人？
- 描述他的政治信仰，过去的和现在的
- 描述他的宗教信仰，过去的和现在的
- 他有趣或者重要的财富是什么？
- 他养宠物吗？
- 他有不寻常的天赋吗？
- 发生在他身上的最好的事情是什么？最坏的呢？
- 他喝茶还是喝咖啡？

### 3. 设定设计目标
- 成为该角色所在世界的专家，知道关于他的所有值得知道的事情
- 尽最大努力想象他在各种环境下的行为方式

### 4. 在游戏中展示角色（Show, Don't Tell）

#### 核心原则
- 向玩家展示角色的信息，而不是直接告诉他们
- 玩家只能忍受很少的说明材料

#### 展示个性的三个因素
1. **外表**：通过视觉设计传达
2. **语言**：通过对话和台词传达
3. **行为**：向观众表达角色最精妙的方式

#### 行为设计要求
- 外表具有欺骗性，而行为则胜过语言
- 通过行为确定人物形象花费的时间更长，必须给玩家观察角色动作的机会
- 设计逻辑：考虑"角色想做什么"以及"在那种意愿下他会遇到什么样的事情"

## 极端情境角色特质推演法

### 流程步骤

#### 1. 原型特征提取
- 选择现实人物（朋友、家庭成员或自己）
- 记录此人的"显著特征"
- 提炼"关键特征"——如果这些特征转移到游戏角色中必须保留的核心属性

#### 2. 极端情境选择（三选一）
- **情境A（犯罪指控）**：此人被错误指控犯了一系列罪：谋杀、持枪抢劫等
  - 测试：正义感、应对压力、求生本能
- **情境B（外星入侵）**：地球被外星舰队侵袭，并且毁灭了地球上的一切生物
  - 测试：极端生存压力、道德底线、孤独应对
- **情境C（身体交换）**：此人睡醒之后发现自己在身边一个陌生的地方，甚至自己的身体都是陌生的，但他还有原来的思想性格
  - 测试：身份认同、适应力、心理韧性

#### 3. 叙事短文撰写要求
- "在这些情境中他会做什么？"——具体行为描述
- "虽说以上情境极度不平常，但要是真正发生将会是什么样的？"——情境的现实推演
- "一个像你选择的普通人是否会有一个引人注目的特征？"——平凡中的非凡特质挖掘

#### 4. 角色设计转化
- 将分析结果转化为游戏角色的背景故事
- 验证角色在极端情境下行为的一致性和可信度
- 确保"真正发生"时的逻辑合理性

## 同伴角色设计

### 设计原则
1. **建立性格对比**：设计同伴角色时，使其性格与英雄形成对比
2. **扩展游戏机制**：利用同伴赋予玩家附加的移动和动作
3. **延伸情感范围**：通过展示与英雄拥有不同人格的角色，丰富游戏的情感维度
4. **传递关键信息**：利用同伴向英雄传达无需其他途径获得的信息

### 互动模式
- **可信度提升**：这些动作如果是单角色执行可信度较低，通过同伴执行则更合理
- **绑定行动**：如《阿邦与阿尔》中阿尔在阿邦背包里
- **独立操作**：同伴可独立执行某些任务

## 互补型双人角色设计

### 设计规范

#### 1. 外观差异化
- 两者从外观上看起来非常不同
- 通过体型、颜色、物种、装备等形成强烈视觉对比

#### 2. 能力互补矩阵
- 角色A的优势领域 = 角色B的劣势领域
- 角色B的优势领域 = 角色A的劣势领域
- 确保没有功能重叠，强制合作必要性

#### 3. 合作机制设计
- **协同状态（Powerful When Together）**：当两个游戏角色同时出现时，要体现出彼此互补的特征，合作起来很强大
  - 设计组合技、互助动作或协同能力
  - 确保1+1>2的效果体现
- **分离状态（Vulnerable When Apart）**：当他们分开时彼此会变得十分脆弱
  - 设计单人无法克服的障碍
  - 确保单独行动时能力受限或风险增加
  - 强制玩家保持合作或频繁汇合

### 参考案例
- 《班卓熊》（Banjo-Kazooie）
- 《瑞奇与叮当》（Ratchet & Clank）

### 验证标准
- 确保合作机制符合选定的游戏类型核心玩法
- 验证角色特征在双人同时出现时的协同效果是否"强大"
- 验证单人行动时的脆弱性表现是否足够明显以驱动合作行为

## 设计决策流程

1. **确定角色重要性**：主要角色 vs 小角色
2. **创建背景单**：回答所有关键问题
3. **应用极端情境测试**：验证角色一致性
4. **设计同伴角色**（如需要）：性格对比、机制扩展
5. **设计双人系统**（如需要）：外观差异、能力互补、合作机制
6. **规划展示方式**：Show, Don't Tell - 通过行为展示个性
