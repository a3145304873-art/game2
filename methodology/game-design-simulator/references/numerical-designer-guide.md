## 一、需求理解框架

### 1.1 核心问题清单

阅读需求文档时，始终思考以下问题：

**设计目标类：**
- 这个机制/系统要解决什么问题？
- 预期玩家体验是什么？（爽快感/策略性/成长感）
- 目标用户群体是谁？（休闲/中度/硬核）

**数值结构类：**
- 核心公式是什么？（加减法/乘除法/指数/对数）
- 主要成长线有几条？（等级/装备/技能/BUFF）
- 数值投放节奏如何？（前期/中期/后期）

**平衡性类：**
- 是否存在明显的最优解？（单一策略过强）
- 随机性占比多少？（纯策略/纯随机/混合）
- 付费点在哪里？付费影响多大？

### 1.2 常见设计模式识别

#### 战斗数值模式

**减法公式体系**
```
伤害 = 攻击力 - 防御力
```
- 特点：直观易懂，防御收益固定
- 适用：轻度游戏、回合制 RPG
- 注意：防御不能超过攻击，否则伤害为 0

**比例公式体系**
```
伤害 = 攻击力 × (1 - 防御/(防御 + K))
减伤比 = 防御/(防御 + K)
```
- 特点：防御收益递减，不会溢出
- 适用：MMORPG、MOBA
- 注意：K 值决定曲线陡峭程度

**乘区体系**
```
最终伤害 = 基础伤害 × 技能系数 × BUFF 系数 × 元素系数 × 暴击系数
```
- 特点：多区独立计算，平衡性好
- 适用：复杂战斗系统
- 注意：避免单一乘区过大

---

#### 成长数值模式

**线性成长**
```
属性 = 基础值 + 等级 × 成长值
```
- 特点：稳定可预期
- 适用：基础属性、资源产出

**指数成长**
```
属性 = 基础值 × (1 + 成长率)^(等级 -1)
```
- 特点：后期膨胀快
- 适用：HP、攻击等主属性

**分段成长**
```
if 等级 <= 10: 成长率 = 10%
elif 等级 <= 30: 成长率 = 8%
else: 成长率 = 5%
```
- 特点：不同阶段不同节奏
- 适用：长期养成系统

---

#### 概率设计模式

**基础概率**
```
P(触发) = 基础概率
```
- 适用：暴击、闪避、触发效果

**保底机制（硬保底）**
```
if 未触发次数 >= 保底次数:
    必定触发
    重置计数器
```
- 适用：抽卡、高价值掉落
- 注意：明确保底是否共享

**软保底（概率递增）**
```
当前概率 = 基础概率 + (未触发次数 × 递增系数)
```
- 适用：需要平滑体验的场景
- 注意：设置最大概率上限

## 二、边界情况识别专家系统

### 2.1 数值边界检查清单

**极值检查：**
- [ ] 攻击力为 0 时会发生什么？
- [ ] 防御力超过攻击力时如何处理？
- [ ] HP 为负数时是死亡还是保留 1？
- [ ] 冷却时间为 0 时是否立即可用？
- [ ] 概率为 0% 或 100% 时是否正常？

**溢出检查：**
- [ ] 伤害超过目标 HP 时，溢出部分如何处理？
- [ ] 治疗超过最大 HP 时，超额部分如何处理？
- [ ] 数值超过整数范围时是否溢出？
- [ ] BUFF 层数超过上限时是否阻止叠加？

**连携检查：**
- [ ] 多个同类型 BUFF 如何叠加？（加算/乘算/取高）
- [ ] 互斥效果同时存在时优先级如何？
- [ ] 触发链是否会导致无限循环？
- [ ] 同时触发的效果结算顺序是什么？

---

### 2.2 常见设计漏洞

**漏洞 1：防御溢出**
```
问题：防御力 > 攻击力时，伤害为 0 或负数
解决：设置最低伤害 = 1 或 攻击力的 10%
```

**漏洞 2：无限叠加**
```
问题：BUFF 无上限，后期数值爆炸
解决：设置最大叠加层数，或收益递减
```

**漏洞 3：保底滥用**
```
问题：多次保底叠加，实际概率远高于标称
解决：明确保底是否共享，独立计数
```

**漏洞 4：乘区叠加**
```
问题：多个乘区相乘，最终倍率过大
解决：设置乘区上限，或改为加法叠加
```

## 三、澄清问题生成策略

### 3.1 模糊词汇映射表

| 模糊词汇 | 可能含义 | 建议追问 |
|----------|----------|----------|
| 大幅提升 | 50%/100%/150% | "具体提升幅度是多少？" |
| 少量恢复 | 10%/50/100 固定值 | "具体恢复多少？百分比还是固定值？" |
| 短时间内 | 1 回合/3 回合/10 秒 | "具体持续多久？" |
| 大概率触发 | 50%/70%/90% | "触发概率具体是多少？" |
| 快速冷却 | -1 回合/-50%/立即 | "冷却减少多少？" |

### 3.2 问题优先级排序

**P0（必须明确，否则无法设计）：**
- 核心公式（伤害计算、成长公式）
- 关键数值（基础值、系数、上限）
- 胜负条件（如何判定成功/失败）

**P1（重要，影响平衡性）：**
- 边界处理（负数、溢出、互斥）
- 叠加规则（加法、乘法、取高）
- 触发时机（回合开始/结束时）

**P2（次要，可后续调整）：**
- 具体数值（可在测试中调整）
- 表现效果（动画、音效）
- UI 呈现方式

## 四、数值敏感性分析

### 4.1 关键参数识别

**高敏感性参数（微小变化导致巨大影响）：**
- 伤害系数（直接影响战斗节奏）
- 成长率（影响长期数值膨胀）
- 概率值（影响随机体验）

**低敏感性参数（变化影响较小）：**
- 基础 HP（相对固定）
- 固定值加成（影响有限）
- 次要属性（非核心战斗）

---

### 4.2 平衡性判断标准

**战斗节奏评估：**
| 通关回合数 | 评价 | 建议 |
|------------|------|------|
| < 3 回合 | 太快 | 降低攻击或提升防御 |
| 3-6 回合 | 适中 | 保持 |
| 7-10 回合 | 偏慢 | 提升攻击或降低防御 |
| > 10 回合 | 太慢 | 大幅提升攻击 |

**随机性评估：**
| 实际波动范围 | 评价 | 建议 |
|--------------|------|------|
| < 5% | 过于稳定 | 增加随机因子 |
| 5-15% | 适中 | 保持 |
| 15-25% | 波动较大 | 考虑降低随机 |
| > 25% | 过于随机 | 增加保底或降低随机 |

## 六、案例分析

### 案例 1：技能伤害设计

**原始需求：**
> 怒气技能造成大量伤害，怒气越多伤害越高，满怒气时伤害翻倍。

**问题分析：**
1. "大量伤害" - 模糊，需要具体数值
2. "怒气越多伤害越高" - 线性？指数？分段？
3. "满怒气翻倍" - 基础怒气是多少？满怒气是多少？

**澄清后需求：**
> 怒气技能造成 150% 伤害。
> 怒气值范围：0-100。
> 伤害系数 = 1.5 × (1 + 怒气值/100)。
> 满怒气 (100) 时：伤害系数 = 1.5 × 2 = 3.0（翻倍）。

---

### 案例 2：BUFF 叠加设计

**原始需求：**
> 每次攻击叠加 1 层攻击 BUFF，每层增加 10% 攻击力。

**需要明确：**
1. BUFF 是否有上限？（避免无限叠加）
2. BUFF 持续时间？（何时移除）
3. 多层 BUFF 是加法还是乘法？
4. 刷新时是重置持续时间还是延长？

**完整设计：**
> 每次攻击叠加 1 层"攻击力提升"BUFF。
> - 每层效果：攻击力 +10%（加法叠加）
> - 最大层数：10 层
> - 持续时间：5 回合（从叠加时重新计算）
> - 叠加方式：刷新持续时间，不重置层数

3. **预判边界问题** - 提前指出可能的数值漏洞
4. **提供专业建议** - 基于经验给出合理的默认值建议
5. **保持质疑态度** - 对不合理的设计要提出疑问
