# 快速开始（5 步上手）

> 面向**不写代码的协作者**。装好 harness（见下）、拿到代码和需求后，按这 5 步走，约 30 分钟产出全部交付文档。
>
> 这是速查版。完整操作细节见 [mode-B-noncode/02-协作者操作流程.md](./mode-B-noncode/02-协作者操作流程.md)。

---

## 开始前，确认 4 样东西齐了

| # | 要确认 | 怎么确认 |
|---|--------|---------|
| 1 | kit 已下载解压 | 本地有 `01-harness/` 和 `02-collaboration/` 两个文件夹 |
| 2 | harness 已安装 | 跑过 `01-harness\install.ps1`；Claude Code 里输入 `/` 能看到 `/kickoff` |
| 3 | 拿到 main 代码 | 项目负责人给的最新主干代码（含 backend/frontend 等） |
| 4 | 拿到需求 Issue | 项目负责人给的需求说明（要做什么、验收标准） |

任一项没齐 → 找项目负责人，不要硬开始。

---

## 第 1 步 · 把项目规范放进代码

把 `02-collaboration/` 文件夹**复制**到 main 代码根目录（和 `backend`、`frontend` 同级），并**重命名为 `collaboration`**。

```
main 代码根目录/
├── backend/
├── frontend/
├── ...
└── collaboration/      ← 放这里（由 02-collaboration 重命名而来）
```

> 这样后面所有话术里的 `collaboration/xxx` 路径才有效。

---

## 第 2 步 · 启动 Claude Code

在 **main 代码根目录**打开终端（PowerShell），运行：

```powershell
claude
```

> 为什么在代码根目录启动？因为《代码差异分析》要基于真实的 main 代码，AI 必须能看到 `backend/`、`frontend/`。

---

## 第 3 步 · 让 AI 读懂你的任务

启动后，**复制下面这段话**发给 AI：

```
我是协作者，负责非代码交付。请依次阅读：
1. collaboration/README.md
2. collaboration/快速开始.md（本文）
3. collaboration/mode-B-noncode/ 下的全部文档
4. 我的 ISSUE.md（需求，路径：XXX）

读完后用 3 句话向我复述：我要做什么、交付什么、在哪里停止。
确认无误后，我们进入需求澄清。
```

AI 复述后，核对她理解对了再继续。

---

## 第 4 步 · AI 写文档 + 四步自查

和 AI 把需求聊透（她会问你几个问题，**拿不准的问项目负责人，别猜**）。

然后**复制这段话**让 AI 跑自动化流程：

```
请运行 /kickoff，基于 ISSUE.md 和已确认的需求完成规划。

重要：这是非代码交付。/kickoff 跑到「一致性审核」通过即停止，
不要进入 readiness / alignment / implement / QA / merge。
当 .consistency-passed 出现，四步独立审核全部完成，立即停下通知我。
```

AI 会自动：写规格书 → 规格 审 → 写计划 → 计划审 → 写任务 → 任务审 → 一致性审。

**看到 `.consistency-passed` → 四步全过 → 停下**。

接着让她写最后一份《代码差异分析》：

```
请按 collaboration/templates/DIFF-ANALYSIS.template.md 撰写《代码逻辑差异分析》，
基于当前 main 代码，说明现状、改动点、影响、风险。只分析不写代码。
写完用一致性审核复核四份文档（含这份）是否对齐。
```

---

## 第 5 步 · 自检 + 交付

```
请按 collaboration/templates/DELIVERABLE-CHECKLIST.template.md 逐项自检，
列出已具备/缺失的交付物，全齐后告诉我可以打包了。
```

自检通过，把 `specs/{N}/` 整个目录回传项目负责人，附一句话：

```
非代码交付完成，四步独立审核已过（.consistency-passed），含差异分析。
请做对齐审核。
```

**你的工作到此结束。** 后续项目负责人做对齐审核 + 写代码。

---

## 如果 harness 没装上（降级路径）

万一 `/kickoff` 用不了（harness 没装成功），**不用慌**，用裸 Claude Code 也能完成：

1. 让 AI 按 `collaboration/templates/` 下的模板手写四份文档（SPEC/PLAN/TASKS/差异分析）。
2. 让 AI 对照 `collaboration/checklists/` 下的清单逐项检查（01-spec → 02-plan → 03-tasks → 04-consistency）。
3. 全过后同样按交付清单自检、打包。

> 降级路径的审核是"AI 对照清单检查"，不如 harness 的独立审核 Agent 严格，但能保证基本质量。项目负责人收货时会加强把关。

---

## 三个绝不（贴在显示器上）

1. **绝不写业务代码** —— 你只产文档，代码由项目负责人写。
2. **绝不跳过四步审核** —— 看到 `.consistency-passed` 才算完成。
3. **拿不准绝不瞎猜** —— 直接问项目负责人。

---

## 卡住了？

| 情况 | 怎么办 |
|------|--------|
| `/kickoff` 命令不存在 | harness 没装好，重跑 `01-harness\install.ps1`；或走上面的降级路径 |
| AI 审核某步反复 FAIL | 达上限时 AI 会停下，把问题转给项目负责人一起判断 |
| AI 写的差异分析引用了不存在的代码 | 让她"请引用真实文件路径证明你读过代码"，重新写 |
| 需求本身有矛盾 | 停止，找项目负责人澄清，不要带着错误理解硬写 |
