# OPS Review - 策划文档评审工具
专门用于评审游戏策划文档的技能，重点关注三大核心问题：
1. **规则完整性** - 规则是否完整、无遗漏
2. **设计完整性** - 设计方案是否覆盖所有场景
3. **边界问题** - 边界条件、异常情况是否处理
## 何时使用此技能
当用户需要：
- 评审策划文档，检查是否有遗漏
- 检查设计方案的边界条件处理
- 发现规则描述中的漏洞和矛盾
- 在上线前进行文档完整性审查
- 对已有设计进行查漏补缺
## MCP 工具依赖
通过 WPS MCP 或 Office MCP 读取 Excel 策划文档：
- **WPS MCP**: `wps_open_spreadsheet`, `wps_read_cells`
- **Office MCP**: `excel_open_workbook`, `excel_read_range`
## 评审框架
### 一、规则完整性检查
检查策划文档中的规则是否完整、无遗漏。
#### 1.1 规则定义检查
| 检查项 | 检查内容 | 常见问题 |
|--------|----------|----------|
| 触发条件 | 规则何时触发？ | 条件描述模糊、缺少前置条件 |
| 执行逻辑 | 规则如何执行？ | 逻辑不清晰、缺少步骤 |
| 结果产出 | 规则产生什么结果？ | 结果未明确、缺少数值 |
| 生效范围 | 规则影响哪些对象？ | 范围未界定、遗漏对象类型 |
| 优先级 | 多规则冲突时如何处理？ | 优先级未定义、冲突未处理 |
#### 1.2 规则遗漏检查清单
```
□ 是否定义了所有状态的转换规则？
□ 是否定义了所有资源的获取/消耗规则？
□ 是否定义了所有操作的前置条件？
□ 是否定义了所有操作的冷却/限制？
□ 是否定义了所有奖励的发放规则？
□ 是否定义了所有惩罚的触发规则？
□ 是否定义了跨系统交互规则？
□ 是否定义了版本兼容/迁移规则？
```
#### 1.3 规则矛盾检查
- 同一条件下是否有多个互斥的规则？
- 不同模块的规则是否存在冲突？
- 规则链是否存在死循环？
---
### 二、设计完整性检查
检查设计方案是否覆盖所有场景和用例。
#### 2.1 用户场景覆盖
| 场景类型 | 检查内容 | 常见遗漏 |
|----------|----------|----------|
| 首次体验 | 新手引导、初始状态 | 缺少引导、初始值未定义 |
| 常规使用 | 主要玩法流程 | 流程断点、操作不闭环 |
| 高频使用 | 日常重复操作 | 体验疲劳、缺少便捷操作 |
| 边缘场景 | 极端/特殊情况 | 未考虑异常、缺少兜底 |
| 回归场景 | 流失用户回归 | 数据过期、追赶机制 |
#### 2.2 功能模块覆盖
```
□ 入口设计：如何进入此功能？所有入口是否都已定义？
□ 主流程：核心操作路径是否完整？
□ 分支流程：所有分支是否都有处理？
□ 退出设计：如何退出？中途退出如何处理？
□ 反馈设计：操作结果如何反馈给玩家？
□ 引导设计：玩家如何知道怎么操作？
□ 数据展示：需要展示哪些数据？数据来源？
□ 红点/提示：何时显示提示？如何消除？
```
#### 2.3 系统联动检查
- 与其他系统的数据依赖是否明确？
- 与其他系统的事件触发是否定义？
- 系统间的调用时序是否正确？
- 系统离线/不可用时如何处理？
---
### 三、边界问题检查
检查边界条件和异常情况的处理。
#### 3.1 数值边界
| 边界类型 | 检查内容 | 常见问题 |
|----------|----------|----------|
| 最小值 | 数值为0或负数时 | 除零错误、负数显示 |
| 最大值 | 数值达到上限时 | 溢出、超限处理 |
| 空值 | 数据为空时 | 空指针、显示异常 |
| 初始值 | 功能首次使用 | 未初始化、默认值错误 |
| 临界值 | 数值刚好达到阈值 | 条件判断边界 |
#### 3.2 时间边界
```
□ 跨天处理：0点刷新时玩家在线怎么办？
□ 跨周/跨月：周期重置时的数据处理？
□ 活动开始：活动开始瞬间的并发处理？
□ 活动结束：活动结束时玩家正在操作？
□ 时区问题：不同时区玩家的体验？
□ 服务器时间：客户端与服务器时间不同步？
□ 倒计时归零：倒计时结束时的状态切换？
□ 时间回溯：玩家修改本地时间？
```
#### 3.3 状态边界
```
□ 并发操作：同时触发多个操作？
□ 重复操作：连续点击同一按钮？
□ 中断恢复：操作中途断线重连？
□ 状态冲突：多个状态同时存在？
□ 状态过期：状态超时后的处理？
□ 状态回滚：操作失败后的回滚？
```
#### 3.4 资源边界
```
□ 资源不足：扣除时资源不够？
□ 资源溢出：获得时超过上限？
□ 资源锁定：资源被其他系统占用？
□ 资源过期：限时资源到期？
□ 资源转换：不同资源间的兑换精度？
```
#### 3.5 用户行为边界
```
□ 非法输入：输入超长文本、特殊字符？
□ 快速操作：短时间内大量操作？
□ 逆向操作：不按预期顺序操作？
□ 中途放弃：流程中途退出？
□ 多端登录：同账号多设备操作？
□ 作弊行为：时间/数据篡改？
```

## 评审流程
### 1. 读取文档 (`/review-read`)
使用 MCP 读取 Excel 策划文档：
**WPS MCP:**
```
1. wps_open_spreadsheet(filepath)
2. wps_read_cells(sheet="全部", range="A1:Z100")
3. 解析文档结构，识别各模块内容
```
**Office MCP:**
```
1. excel_open_workbook(filepath)
2. excel_read_range(sheet="全部")
3. 解析文档结构
```
### 2. 执行评审 (`/review-check`)
按三大维度逐项检查：
```
1. 规则完整性检查
   ├── 逐条检查规则定义
   ├── 对照规则遗漏清单
   └── 检查规则矛盾
2. 设计完整性检查
   ├── 用户场景覆盖检查
   ├── 功能模块覆盖检查
   └── 系统联动检查
3. 边界问题检查
   ├── 数值边界检查
   ├── 时间边界检查
   ├── 状态边界检查
   ├── 资源边界检查
   └── 用户行为边界检查
```
### 3. 生成报告 (`/review-report`)
输出评审报告，可写入 Excel 新 Sheet 或独立文件：
```markdown
# 策划文档评审报告
**文档名称**: [文档名]
**评审日期**: YYYY-MM-DD
**评审人**: AI Review
---
## 评审总结
| 维度 | 问题数 | 严重 | 一般 | 建议 |
|------|--------|------|------|------|
| 规则完整性 | X | X | X | X |
| 设计完整性 | X | X | X | X |
| 边界问题 | X | X | X | X |
| **合计** | X | X | X | X |
---
## 问题清单
```

## 快捷命令
| 命令 | 说明 |
|------|------|
| `/review [文件路径]` | 完整评审流程（读取+检查+报告） |
| `/review-read [文件路径]` | 仅读取并解析文档结构 |

---
## 问题严重等级
| 等级 | 标记 | 定义 | 处理要求 |
|------|------|------|----------|
| 严重 | 🔴 | 会导致功能无法正常运行或严重体验问题 | 必须修复后才能开发 |
| 一般 | 🟡 | 可能导致部分场景异常或体验不佳 | 建议修复后开发 |
| 建议 | 🟢 | 优化建议，不影响功能实现 | 可选优化 |

## 最佳实践
1. **先读后审**: 先完整阅读文档，理解设计意图后再评审
2. **分类记录**: 按三大维度分类记录问题，便于追踪
3. **给出建议**: 不只指出问题，还要给出可行的解决建议
4. **标注位置**: 精确标注问题在文档中的位置
5. **优先级排序**: 严重问题优先处理
6. **复查确认**: 修改后需复查确认问题已解决
