# 运营小游戏提示词库

做小程序/H5 运营活动小游戏用的。不是照着某个游戏抄一个，而是从下面的玩法库里挑一个原型，配合通用的运营模块，拼出一条提示词丢给 AI 即可。

使用方法：**「骨架提示词」＋ 选一个「玩法原型」的内容 ＋ 「运营模块」＝ 完整提示词**。

同类参考：`html5-games-collection/` 里有 Tetris、2048、Pacman、FlappyBird 等 10 款现成单文件游戏，想偷懒可以直接改皮肤；`benchmarks/大鹅吃草_单文件版.html` 当交付形态（单文件、base64 内联资源）的参照即可。

## 一、骨架提示词（挖空版）

```
请用【单个 HTML 文件】实现一个移动端竖屏小游戏，要求：
- 所有代码/样式内联，无外部依赖；图片优先 Canvas 程序化绘制，
  音效用 WebAudio 合成；若必须用图片/音频则 base64 内联
- 不指定美术时用简洁的高对比风格，中文 UI

【玩法主体】
<把下面"玩法原型"中选中的一款整段贴进来>

【主题包装】
活动主题是：<你们的品牌/IP/节日，如"XX酸奶中秋季">，
请把角色、道具、障碍物全部替换为主题元素，
配色围绕品牌色 <色值> 设计。

【技术要求】
- viewport-fit=cover 处理刘海屏，env(safe-area-inset-*) 底部安全区
- touch-action:none 防止页面滚动，画布自适应窗口，桌面端也支持鼠标试玩
- 目标 60fps，粒子和同屏对象数量要有上限
```

## 二、玩法原型库（挑一款）

| # | 原型 | 一句话机制 | 适合的运营目的 | AI 一次成型率 |
|---|------|-----------|---------------|--------------|
| 1 | 接落物（红包雨） | 底部篮子横移接天上掉的东西 | 节日大促、发券 | 高 |
| 2 | 打地鼠 | 点击随机冒头的目标 | 拉停留时长 | 很高 |
| 3 | 跳一跳 | 长按蓄力跳上下一平台 | 品牌形象、排行榜裂变 | 中 |
| 4 | 贪吃蛇式成长 | 吃食物变长变大躲危险 | 竖屏沉浸，曝光期长 | 中 |
| 5 | 合成进化 | 两个同级物体碰撞合成更高级 | 收集欲强，适合层级丰富的产品线 | 中 |
| 6 | 翻牌配对 | 翻两张找相同 | 记忆品牌卖点/菜谱文案 | 很高 |
| 7 | Flappy 式飞行 | 点击上升穿缝隙 | 低门槛冲榜裂变 | 高 |
| 8 | 节奏下落点击 | 音符到底线按轨道点击 | 有 BGM 素材的活动 | 中 |
| 9 | 找不同 / 寻物 | 限时找差异或藏起来的物件 | 植入产品/门店信息的软广 | 很高 |
| 10 | 物理弹射 | 拖拽发射打倒目标 | 互动感强，晒分传播 | 中 |

> 选型建议：第一次上线选 ✅"很高"的两款之一试水（打地鼠/翻牌配对几乎不会翻车）；想要裂变刷屏就选排行榜型的（跳一跳/Flappy）；要讲清产品卖点就用翻牌配对或找不同，玩法本身就是广告位。

### 各原型详解（作为"玩法主体"段落贴入）

#### 1. 接落物
```
底部有一个篮筐，跟随手指在屏幕下半区左右移动；
天空随机掉落 <正常物 A/B/C> 和 <陷阱物>：
- 接住正常物 +10 分，连续接住触发 combo（x2/x3 分数倍率）
- 误接陷阱物扣生命值，共 3 条命
- 每 30 秒为一波，波次间隔掉落速度提升 20%
- 限时 90 秒或命耗尽结束；高分进结算
```

#### 2. 打地鼠
```
屏幕上有 3×3 个洞口，<目标物> 从洞口随机弹出停留约 0.6 秒后缩回：
- 点中普通目标 +10，点中每局最多出现 1 次的 <金色特殊目标> +100 并播放特殊特效
- 点空 3 次、误点到 <干扰物> 各会短暂冻结交互 0.8 秒作为惩罚
- 总时长 45 秒；分数刷新越快目标停留时间越短（最低 0.35 秒）
```

#### 3. 跳一跳
```
屏幕上是一串高低错落的圆柱平台，主角站在当前平台边缘；
长按蓄力、松手起跳，跳跃距离与按压时长成正比：
- 落在下一平台得分 +1；落在平台正中心的圆环内得分翻倍并连击递增
- 落到平台外/前方即为失败，展示历史最高分
- 平台间距 80~220px 随机，平台表面允许放 <品牌 logo/道具> 作装饰彩蛋
```

#### 4. 贪吃蛇式成长
```
俯视视角场地，玩家滑动屏幕（或摇杆）控制主角移动：
- 场上散布大量食物，吃到后身体变长一格、得分 +1
- 场上存在 1~2 只追击者，靠近主角减少生命
- 吃满 20/50/100 分各升一级：体型变大同时移速提升
- 撞墙/被追击抓到 3 次结束；以最终长度和得分结算
```

#### 5. 合成进化
```
容器内有两种初始尺寸的圆形物体持续投放；
拖拽松手后落入容器，两个相同等级的物体接触即合成为高一级：
- 共设 10 级，各级用不同的 <品牌产品/IP 形象> 表示，合成瞬间播放音效+光效
- 物体堆出容器口线持续 3 秒即结束
- 合成最高级一次额外奖励积分；总分=合成事件积分累计
```

#### 6. 翻牌配对
```
4×4 共 16 张背面朝上的卡牌，每次翻开 2 张：
- 图案一致则保持正面并计一对，不一致则 0.8 秒后自动盖回
- 卡面图案用 <成对的卖点文案或产品图>，这正是植入信息的位置
- 以"总用时+总步数"综合排名；限时 90 秒未完成也算作完成度结算
- 全部配对成功后展示品牌结尾页
```

#### 7. Flappy 式飞行
```
主角悬浮在屏幕左侧 1/3 处，点击一下向上跃动一次，平时受重力下坠；
右侧不断生成上下留有缺口的障碍柱，穿过缺口 +1 分：
- 缺口宽度 28% 视口高起步，每 10 分收窄 2%，最低不低于 20%
- 碰到柱子/地面/天花板立即结束
- 手感关键：重力加速度、点击冲量、下坠上限速度请调到"死亡多但不劝退"
```

#### 8. 节奏下落点击
```
屏幕分 4 条竖直轨道，<音符方块> 沿轨道匀速下落至底部判定线：
- 方块接近判定线时点击对应轨道：Perfect ±40ms 得分 x2，Good ±120ms 正常得分，Miss 断连击
- 连击达到 10/30/50 时播放对应鼓点强化反馈
- 整曲时长 60~90 秒；通关标准为准确率 ≥70%
```

#### 9. 找不同 / 寻物
```
A 模式：并排展示两张相似场景图，其中 5 处有差异，点对一处放大镜标记，
        点错扣 2 秒；找出全部差异结束
B 模式：一张杂乱场景图里隐藏 10 个 <品牌相关物件>，点中 8 个即可过关
两者都以总用时排名；美术希望程序化生成简单卡通场景即可
```

#### 10. 物理弹射
```
左下角有一具弹弓，主角装在皮筋上：
- 向任意方向拖拽放开，主角沿抛物线飞出，可空中二次点击加速一次
- 右侧摆放着积木塔和 <目标靶子>，击倒靶子得对应分
- 每局 3 发，剩余未使用的弹药每发折算 +200 分加入结算
#### 11. 任务累积养成型（长周期活动的"容器玩法"，对标网易《式神福气赏》）

```
本游戏是长周期运营活动的"攒资源容器"，没有单局胜负与 game over：
- 主界面三区布局：顶部资产栏（福气值图标+数值、声音开关）、中部主舞台
  （大立绘+主按钮）、底部入口区（任务面板/规则页入口）
- 发奖主引擎是【任务面板】而非关卡：任务分每日类与一次性类，
  完成后返回本页领"召唤券"；接入外部 SDK 时，任务完成状态由服务端
  下发的 isDone 字段渲染，前端只做展示不判定
- 核心动作：消耗 1 张召唤券点击「立即召唤」，随机获得一份福气值；
  召唤演出 = 金光落下 + 卡牌翻面 + 数值滚动跳动，约 2 秒；
  约 1% 概率触发「欧皇降临」金光加强变体（双倍福气）作为惊喜彩蛋
- 全场进度：累计福气值推动全周期奖励进度条，下一节点显示
  "红包开放倒计时"，每天固定时段开放领取；到点后红包挂件呼吸晃动引导点击，
  领取后永久替换为"已领取"静态素材并禁点，防重复领取
- 引导兜底：页面常驻"今日剩余召唤次数"角标；剩余为 0 时主按钮切换为
  "去完成任务再得券"，任务面板角标同步点亮
```

> 选型提示：这款不适合让 AI 从零生成完整工程（登录/任务要接公司 SDK），适合生成**可换皮的静态壳子 + 假数据联调版**给评审走流程用。

## 三、运营模块（无论哪个原型都要加）

直接追加在提示词末尾：

```
【运营模块】
- 新手引导：首局出现半透明手势示意（点击/滑动），完成一次操作后淡出，此后不再出现
- 顶部 HUD 常驻：左侧得分/进度，右侧倒计时；吃分、升级、受击必须有即时视觉+音效反馈
- 结算弹窗：本次得分、历史最高(localStorage)、名次预估；主按钮「再来一次」
- 转化位：结算后追加「恭喜获得限时礼包」弹窗卡片，
  含两个按钮：「立即领取」(data-href 占位，后续接活动链接) 和
  「邀请好友再玩一次」(预留唤起分享的函数占位 shareToFriend()，先空实现)
- 成绩接口预留：上报函数 submitScore(score) 写成可替换的空壳
- 埋点点位预留：onGameStart/onGameOver/onGiftClick 三组埋点函数占位
- 语言：全中文 UI；时间显示带"秒"，分数变化滚动动画
```

3. "结算弹窗太挤，改成两段式：先成绩页→点继续才出礼包页"

## 五、合规红线备忘

- 避免"分享到群才能继续玩"这类硬性强制分享（平台会拒审/封禁）；
  改成"邀请好友得额外机会"
- 领奖链路必须人工可核销：礼包码/表单留资走服务端，不要只在 localStorage 里"领奖"
- 抽奖概率型玩法需在页面公示中奖概率（盲盒式合成同理）

## 六、AI 生图提示词包（美术素材全流程）

适用于即梦 / Midjourney / Stable Diffusion 等。核心分工：**手绘感的物件、角色、场景交给 AI；规整的 UI 元素（按钮、进度条、数字）用 Figma/AI 出底再精修；一切带文案的画面由 AI 出底、后期写字。**

### 6.0 开工前必读的四条铁律

1. **别要透明底**：主流模型只能出 JPG/PNG 带背景。全部按"纯白底 #FFFFFF + 单体居中 + 无阴影"出图，拿到手统一抠图（remove.bg / 即梦智能抠图 / PS）。
2. **一次一物**：想要系列感就"垫图重绘"逐张生成，别指望一句话出一整套。
3. **文字必翻车**：任何提示词里都写"无任何文字"，文字一律后期加。
4. **序列帧别硬刚**：让 AI 直出 6 帧连贯走路循环基本不可行（帧间形象漂移）。务实做法见 6.3。

### 6.3 动画的三个务实方案（按成本排序）

| 方案 | 做法 | 适用 |
|---|---|---|
| 代码变形 | 只要 1 张静帧，用 CSS/JS 做挤压拉伸、摇晃、位移来表现"活" | 首选。多数运营小游戏（含对标大鹅吃草）都这么干 |
| 关键帧插值 | AI 生成 3 张关键姿势（待机/吃/欢呼），软件补间 | 需要明显动作差异的场合 |
| 骨骼动画 | 让 AI 分别生成身体的分离部件（躯干/头颈/翅/腿）拼 Spine | 效果最好但层间风格一致性难保证，留给正式版 |

走"代码变形"路线时，立绘提示词务必加一句：**重心稳定、双脚着地、四肢自然下垂的对称站姿**——方便程序做骨骼节点。

## 七、奖励发放设计（先定奖，再定游戏）

> 核心：**这类游戏的一切数值都由"发奖计划"反推**，而不是反过来。大鹅吃草的正确读法：
> 吃草=制造"努力感"的填充动作，宝箱=发奖节点，终局礼包弹窗=唯一转化出口。

### 7.1 标准发奖链路拆解（对标大鹅吃草）

| 环节 | 它做的事 | 运营含义 |
|---|---|---|
| 过程小奖励 | 每挖到 1 个宝箱立即弹窗"已找到 1/3" | 把发奖拆成小步反馈，拉完播率 |
| 终局礼包 | 必然弹出"恭喜获得限时礼包"卡片 | **转化主出口**，按钮接真正的领奖链路 |
| 失败兜底 | 时间没找齐→"大鹅的认可"结算页 | 输了也给台阶，保住分享/再来一次的意愿 |
| 再玩入口 | 弹窗第二按钮"邀请好友再玩一次" | 把频次控制和裂变合并成一个按钮 |

### 7.2 四种奖励挂载模式（选一种或组合）

| 模式 | 触发条件 | 心理钩子 | 适合场景 |
|---|---|---|---|
| A · 终局礼包（标杆款） | 完成一局即得基础档，表现好升级档位 | 100% 有产出，安全感 | 转化新客、发券 |
| B · 过程掉落 | 游玩中踩到/挖到隐藏彩蛋物才有奖 | 惊喜感、再玩探索 | 促进局均时长 |
| C · 累计阶梯 | 单局分数/连续多日游玩累计达 X 档 | 目标感、留存 | 活动周期 3 天以上 |
| D · 排行榜名次 | 期榜 Top N 得大奖 | 社交攀比 | 拉分享裂变 |

**组合建议**：A 保底 + C 提留存 是最稳的主干；B/D 只给低成本小奖品。

### 7.3 数值反推步骤（写策划案用）

1. 先算账：活动预算 ÷ 预估参与人数 = 人均可发奖成本。
2. 定档位：一般 2~3 档（如 100% 得小额券 / 达标得中档 / 高分抽实物），
   **基础档达成率务必做到 85% 以上**——难在"心理紧张"，不在"真的拿不到"。
3. 反推游戏参数：为了把基础档达成率钉在 ~90%，
   用"延长时限""降低判定速度""必刷关键道具"去调，而不是砍奖励。
4. 频控：单人每日限 N 局、每周总量封顶——频控上限同时就是你的人均成本上限。
5. 库存红线：热销档设总库存，服务端发完自动降级为下一档文案"福利已领完，获得安慰奖"。

### 7.4 「奖励发放模块」提示词（替代通用运营模块里的转化位段）

对齐 7.2 选好模式后，把这段追加到任意玩法提示词后面：

```
【奖励发放模块】
- 奖项配置集中放在顶部常量 REWARDS = [
    { id:'base', name:'<基础奖名称>', pic:'ASSETS.xxx', condition:(s)=>true },
    { id:'mid',  name:'<进阶奖>', pic:'...', condition:(s)=>s.score>=<阈值> },
    { id:'top',  name:'<大奖>', pic:'...', condition:(s)=>s.score>=<阈值>, lottery:true },
  ]
- 结算逻辑：对局结束后按 condition 从高到低命中第一个奖项并弹出对应礼包卡片；
  未达到任何条件也必须弹出 base 档（保底）
- 抽奖类奖项(left=true)：前端仅播放"抽奖动画"后展示结果，
  真实结果必须等待下述接口返回后再展示
- 服务端接口占位：
    submitScore(payload)   上报成绩，payload 含 score/duration/timestamps/sessionId
    claimReward(rewardId)  领奖，返回 { success, code /*卡券码*/, stockOut }
    两函数先写成 console.log 占位，但调用位置和参数结构必须正确，便于后端对接
- 领奖 UI 流程：礼包卡片「立即领取」→ 领取弹层（需留资则放表单，
  phone 字段正则校验 11 位）→ 成功态展示卡券码/二维码，含"复制"按钮
- 频控展示：进入页时调 getConfig() 读 { remainingPlays }，为 0 时
  主按钮变为「邀请好友得 1 次机会」（裂变回收频次的统一入口）
- 埋点：reward_show / reward_claim_success / reward_stockout 三组新增点位
- 文案纪律：奖品金额描述合规（勿使用"稳赚""保证中奖"字样），
 大奖需带"奖品数量有限"角标
```

### 7.5 服务端三件套（前端再漂亮，这三点不做就是事故）

1. **判定权在服务端**：能不能得奖、得几档，一律以 `submitScore` 后服务端按同一套 condition 重算的结果为准，前端只负责演出。
2. **幂等**：同一 session/订单号重复调 `claimReward` 不多发；卡券码一次性核销。
3. **超发保护**：库存扣减走原子操作（Redis decrement 或数据库行锁），扣到底自动切换兜底档。
