# 美术与 UI 适配指南（Godot + HTML 路线）

> 针对问题：① 美术资源总是和设计不适配；② UI 设计不好。
> 参考项目结论：笨蛋勇者（HTML，UI 全代码化）→ UI 好看不需要美术；钟馗（Godot，先规格后素材）→ 美术适配靠"设计先行"。

---

## 一、为什么会"不适配"？四个根因

1. **顺序反了**：先找图/先生图，再回头改设计去迁就图。正确顺序是
   `设计定稿 → 写资产需求清单（尺寸/状态数/文案） → 按清单生成/采购 → 验收`。
   钟馗就是反例→正例：任务看板先写"新怪 sprite 沿用 Ghoul 风格 + 符箓图标×2"，素材才动手。

2. **没有 Art Bible（风格圣经）**：AI 生图每次都是随机风格，拼在一起必然违和。
   必须先把 5~8 条硬约束写死：**配色板、描边规则、视角、比例、光照方向、背景处理方式、帧数规格**。

3. **素材来源混杂**：Kenney 包 + AI 图 + 手绘三风格混用（钟馗曾混用，但靠"沿用 Ghoul 风格"克制住了）。
   解法：**每一类资产锁定单一来源**；跨来源时用 img2img 把全部素材按同一 style prompt 重绘统一画风。

4. **UI 与画面割裂**：UI 另起炉灶设计，没有从主视觉**抽色**。解法：UI 色板 = 画面色板的子集；
   先把主题 tokens（背景/面板/文字/强调/警示 5 组颜色 + 2~3 档字号）定死，再做界面。

5. **规格混乱**：立绘 4390×5370、图标 171×177、背景 1536×1024 混在一起（笨勇者就是），缩放后细节密度不一。
   解法：**每种资产类型一张标准尺寸表**，生成时直接按尺寸出图。

## 二、HTML 路线：UI 代码化，美术只干两件事

笨勇者的核心经验：
- **UI 全部用 CSS 画**（进度条 = div+渐变，按钮 = 圆角块，面板 = 半透明卡片），UI 永不"不适配"，因为它不依赖任何图片。
- **图片只保留两类**：① 立绘/立牌（透明背景 PNG，统一 drop-shadow）；② 背景大图。
- 立牌统一规格：**半身或全身、纯色/透明背景、同一投影角度**，用百分比高度适配窗口。
- 字体分角色：界面用无衬线（雅黑），叙事/结局用衬线（宋体/Georgia）——叙事感是 UI 质感的一半。

《末世后30天》按此路线：所有面板/弹窗/资源条/任务卡都是代码；需要图片的只有
**8 个 NPC 头像**和**1~2 张安全屋背景**。美术量从"几百张"降到"10 张"，不适配风险自动消失。

## 三、Godot 路线：先规格，后素材（钟馗全套）

1. 目录规格（新资产照放，agent 不用问）：
   `assets/characters/<名>/{idle,walk-1..N,attack-1..N,shadow}.png`、`assets/ui/<界面>/`、`assets/audio/<bgm|sfx>/`（先建目录放占位）。
2. 导入：全部**默认预设**，不逐图调参。
3. 动画：SpriteFrames 模板（idle 1帧 / walk 4帧 / 攻击 N帧），帧 = texture+duration+speed。
4. UI：菜单大图做"暗/亮"两版映射按钮四态；血条整图拉伸；**不用** NinePatch/图集/TileSet（钟馗实测 0 使用）。
5. 场景装饰：代码摆 Sprite2D（ArenaGroundDecor 模式），不为装饰单独出图。

## 四、《末世后30天》Art Bible（可直接当约束用）

**色板（冷末世 + 炉火暖点）**
| 用途 | 色值 |
|------|------|
| 页面底 | `#0d1218` |
| 面板 | `#141b24` |
| 面板描边 | `#243140` |
| 正文 | `#dfe9f3` |
| 次要文字 | `#7f92a8` |
| 冰雪/信息强调 | `#6ec6ff` |
| 炉火/暖意强调 | `#ffb347` |
| 危险/资源告急 | `#ff5d5d` |
| 士气 | `#b9a7ff` |

**立绘规格**：头像 512×512 半身像，透明背景，统一正面光（冷色顶光 + 暖色炉火侧光），描边 1px `#0d1218`。
**图标规格**：32px 线性图标，圆角线条，单色（使用时填 `currentColor`）。
**背景规格**：1920×1080，冷灰蓝调，噪点少，为 UI 留出左侧/底部负空间。

**AI 生图 prompt 模板（风格前缀固定，只换角色描述）**
```
风格前缀: dark post-apocalyptic survival, cold blue-grey palette #0d1218 base,
         thin dark outline, soft warm rim light from fireplace, flat shading,
         bust portrait, transparent background, 512x512
角色槽:  [角色名/年龄/职业/性格关键词/服装描述]
后处理:  Photoshop 抠背景 → 统一曲线压暗 → 描边 → 导出透明 PNG
```

## 五、资产需求清单（设计↔美术的接口，最重要）

每个界面先填这张表，再动笔/动模型——这就是"适配"的工程化保证：

| 界面 | 需要的资产 | 类型/尺寸 | 状态数 | 文案长度上限 |
|------|-----------|-----------|--------|--------------|
| 日出日报 | 无（纯代码） | — | — | 标题≤8字 |
| 任务分配 | 8 个 NPC 头像 | 立绘 512² | 1（加灰色态） | 任务名≤4字 |
| 事件弹窗 | 触发者头像 1 张 | 立绘 512² | 1 | 选项≤20字 |
| 夜间结算 | 无 | — | — | — |
| 结局 | 1 张救援远景 | 背景 1920×1080 | 1 | — |

**验收 4 查**（每个界面截图后过一遍）：
1. 颜色是否全部来自色板？ 2. 字号是否 ≤3 档？ 3. 图片是否同规格（尺寸/描边/光照）？ 4. 文案是否超框？
