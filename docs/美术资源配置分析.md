### 1.2 配置手法（全是 CSS，无引擎概念）
- **相对路径直引**：`<img src="cave_empty.png">`、`<audio src="...mp3">`——资源与 HTML 同目录，浏览器打开即玩。
- **百分比定高缩放**：立牌高度用 `height:38%/74.4%` 按舞台容器比例缩放，天然适配任意窗口（`#theater{aspect-ratio:16/10;width:min(920px,96vw)}`）。
- **投影统一**：`filter:drop-shadow(0 6px 4px #0008)` 给所有立牌加投影——透明背景 PNG + CSS 投影 = 立牌观感的关键。
- **混合模式做特效**：火焰 `mix-blend-mode:screen` 叠加发光；剑气用 CSS 渐变 `linear-gradient` + `skewX` 程序化生成，不占图片。
- **UI 全部代码绘制**：血条/倒计时条是 `<div>` + 渐变背景，按钮是 emoji + 圆角；文字分两种字体（正文微软雅黑，故事/结局用衬线 Georgia+宋体营造"叙事感"）。
- **美术来源**：AI 生成 + Photoshop 22 后期（PNG 内嵌 XMP 记录，2026-08-22 20:09/22:02 两次导出），比赛前一夜集中出图。同图多版本并存（`yongzhe.png`/`yongzhe_new.png`/`人物 勇者.png`）。

### 1.3 启示
美术配置成本 = 0（没有引擎、没有导入器、没有图集）。**UI 用代码画、图片只承担"立绘+特效"**，是 HTML 原型路线的核心省钱点。

## 二、Black Scroll·钟馗：Godot 全链路配置（重点）

### 2.1 总原则
- **248 个贴图导入块全部使用默认预设**：`importer="texture"` / `type="CompressedTexture2D"` / `metadata={"vram_texture": false}`——不逐图调参数，靠"默认预设 + 目录规范"管理。
- **不使用任何高级 UI 资源**：`NinePatch/scale_9/AtlasTexture/TileSet` 在包里出现次数全部为 0。血条=整图拉伸、按钮=整图四态、场景装饰=代码摆放 Sprite2D（`ArenaGroundDecor.gd`/`ArenaBoundaryBuildings.gd` 程序化铺场景）。

### 2.2 目录即配置（美术怎么放）
```
assets/
├── characters/<角色名>/    ← 每个角色一个文件夹：
│     idle.png / walk-1..9.png / attack-1..8.png / shadow.png / aperture.png(光圈)
│     （钟馗/ghoul/minion_01/elite_01/elite_02/boss_king/mysterious_elder/shield_puppet/tutorial_zhongkui…）
├── items/<武器名>/          ← 武器飞行动画帧：walk-1..N.png（七星护体剑/离火剑/符箓/爆符）
├── environment/<场景>/      ← 背景图：scene/atmosphere.png, tutorial_boss/floor.png
├── effects/<归属>/          ← 特效帧：boss/bullet_minion/flight_1..4.png
├── drop/                    ← 掉落物帧：diaoluo-1..7.png, proj.png
├── sprites/hero|knife|monster/  ← Kenney 素材包原始图（按来源分类的"素材库"层）
└── audio/                   ← 音效（曾因空目录出过事，看板里标注⚠️）
game/ui/mainmenu/            ← UI 整图跟着界面走，不集中放 assets：
     开场界面-底图3.png、入画斩鬼(暗/亮).png、影神图鉴(暗/亮).png、游戏设置(暗/亮).png
```
规律：**素材库（Kenney 包）按来源放 `assets/sprites/`；实际用图按角色/对象拆到 `assets/characters/<名>/`**。UI 图就近放界面代码旁。

### 2.3 角色怎么挂动画（从 Hero.tscn / BossKing 场景复原）
场景节点树（真实结构，字段名从二进制场景中提取）：
```
Hero (CharacterBody2D, motion_mode, collision_layer/mask, script=Hero.gd)
├── Camera2D
├── UndeadShadow (Sprite2D, texture_filter)   ← 阴影 = 独立 png + Sprite2D，不用动态阴影
├── body (AnimatedSprite2D, sprite_frames, animation)
├── GunRoot (Node2D)
├── CollisionShape2D (CircleShape2D)
├── PointLight2D2 (energy, shadow_enabled, texture_scale)  ← 主角带点光源
└── EquipRoot (Node2D)
```
动画配置 = `SpriteFrames` 资源（内嵌在场景里，`local://SpriteFrames_a2m0y`）：
| 动画名 | 帧数 | speed | loop | 帧来源 |
|--------|------|-------|------|--------|
| idle | 1 | 5.0 | ✅ | hero.png |
| run | 4 | 10.0 | ✅ | walk-1..4 |
| run_back | 4 | 10.0 | ✅ | walk-1..4（倒放） |
| dash | 3 | 7.0 | ❌ | walk-1..3 |
| die | 1 | 5.0 | ❌ | — |

BossKing 同理：`SpriteFrames_boss` = attack(8 帧 attack-1..8) / idle(1 帧) / run(5 帧 bosswalk-1..5)，另有 Aura 光环 Sprite2D（modulate 调色）和 Shadow 节点（shadow_size/shadow_color 参数化）。
每帧结构 = `texture` + `duration` + `speed`（FPS）三件套，**全部手写（或由 AI 按模板生成）**，不依赖编辑器 GUI 操作记录。

### 2.4 UI 怎么挂图（从 MainMenu.tscn 复原）
```
MainMenu (Control, anchors_preset=全屏, grow_horizontal/vertical=双向)
├── Bg (TextureRect, texture=开场界面-底图3.png,
│        expand_mode + stretch_mode=拉伸适配全屏)
├── start  (TextureButton: texture_normal=入画斩鬼(暗).png,
│                          texture_hover=入画斩鬼(亮).png, …四态)
├── codex  (影神图鉴(暗/亮).png)
└── settings (游戏设置(暗/亮).png)
```
手法：**每张菜单大图做"暗/亮"两版 PNG，映射到按钮 normal/hover 四态**；底图全屏拉伸；`ignore_texture_size` 让按钮热区独立于贴图大小。HUD 组件统一 `Ornate` 前缀（OrnateTimePanel/OrnateBossHealthFrame/OrnateCountdownFrame/OrnateStatusFrame）+ 字体独立 `.tres`（ZhongKuiDisplayFont/UIFont/Theme）。

### 2.5 音频配置
- 34 个 mp3 直接进 `assets/audio`（无 ogg/wav 转码、无逐文件 loop 配置），循环/音量逻辑全部写在 `AudioManager` 单例代码里。
- 命名带来源：`…_爱给网_aigei_com.mp3`、freesound 作者名（归因保留在文件名/项目里）。

### 2.6 值得一提的细节
- 项目根有 `wuzu_cat.png`（funplay/wuzu 工具链的猫图标）——**工具链资产也随项目提交**。
- `game/hero/Light (1).png` 这种"下载默认名"文件被直接放进代码目录——AI 落库不规范的真实痕迹。

## 三、DigHoleTest03：UE 全打包，程序化视觉为主

- 游戏内容全部在加密的 `.ucas/.utoc`（UE 5.8 IoStore），无法取证具体贴图/材质配置；`.pak` 里只有引擎自带的 Slate UI 皮肤（Checkerboard/Button.png 等）——说明游戏**几乎没有手绘 UI 资产**。
- 能看到的配置只有三段媒体：
  - `Content\Movies\CG\入场.mp4`（27.4MB）
  - `Content\Movies\CG\离场.mp4`（22.1MB）
  - 命名直白：入场/离场 CG 转场。
- 视觉主体靠 **Voxel Plugin**（`Plugins\VoxelPlu…V13_UE58`，含 embree3 光追加速库）程序化生成体素地形——**用插件替代手绘场景美术**，这是第三条美术路线：无美术资源型。
- 打包含 .pdb（调试符号），是开发中构建。

## 四、三路线对比

| 维度 | 笨蛋勇者（HTML） | 钟馗（Godot） | DigHole（UE+Voxel） |
|------|------------------|---------------|---------------------|
| 美术量 | 12 张 PNG + 2 mp3 | ~300 PNG（帧动画为主）+ 34 mp3 | 2 段 CG 视频 |
| 配置方式 | CSS 直引 | 默认导入预设 + SpriteFrames + 场景节点 | 插件程序化 + 引擎加密打包 |
| UI | 代码绘制（CSS/div） | 整图两态 + TextureButton 四态 + 血条整图拉伸 | 几乎无 UI 资产 |
| 动画 | CSS transition/keyframes | PNG 序列帧 + duration/speed | 体素/程序化 |
| 阴影 | CSS drop-shadow | shadow.png 独立贴图 | 引擎光照 |
| 关键投入 | AI 生图 + PS 后期 | Kenney 素材包 + 分层导图 + 帧命名规范 | 买插件，省美术 |

## 五、对《末世后30天》的配置建议（直接可用）

### 5.1 若走 HTML 路线（推荐先做原型）
- 一张背景 + NPC 立牌若干 + UI 全代码绘制；图片只留 `assets/characters/<名>/portrait.png` 和 `assets/bg/`。
- 立牌高度用百分比适配窗口；`drop-shadow` 投影；雪/火炉粒子用 CSS 渐变动画。
- 事件弹窗 = 钟馗"暗/亮"思路：底图 + 半透明卡片。

### 5.2 若走 Godot 路线
- 目录照抄钟馗：`assets/characters/<角色名>/{portrait,idle,walk-1..N}.png`、`assets/ui/<界面>/{底图,按钮暗/亮}.png`、`assets/audio/{bgm,sfx}/`（**提前建目录放占位文件**，避免"音频空目录"事故）。
- 全部贴图用**默认导入预设**，不调参数；动画用 `SpriteFrames`（idle/walk/… 命名固定，帧 duration+speed 模板化），一个角色一个场景模板，AI 按模板批量生成。
- UI 不用 NinePatch：菜单大图"暗/亮"两版 + TextureButton 四态，血条/资源条整图拉伸。
- 阴影用 `shadow.png` 独立贴图 + Sprite2D；室内暖光用 PointLight2D 点亮火炉。
- 音频：mp3 直进，循环/音量逻辑集中在 `AudioManager` 单例。

### 5.3 给 agent 的美术规范（写进 AGENTS.md）
```markdown
# 美术资产规范
- 目录：assets/characters/<角色名>/ 、assets/ui/<界面>/ 、assets/audio/<bgm|sfx>/
- 角色帧命名：idle.png、walk-{1..N}.png、attack-{1..N}.png、shadow.png
- UI：大图做 暗/亮 两版；按钮四态映射 normal=暗, hover=亮
- 素材来源：AI 生图→PS 修图→透明 PNG；小物用 Kenney 包，注明来源
- 音效：爱给网/freesound，文件名保留来源标注；入库前先建目录占位
- 禁止：把下载默认名文件（如 Light (1).png）直接提交
```
