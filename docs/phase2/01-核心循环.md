# 01 - 核心循环系统

## 系统概述

第二阶段的每日循环是游戏的骨架，驱动所有子系统运转。玩家角色从"执行者"变为"指挥官"，核心操作是"分配任务 + 处理事件"。

## 每日循环流程

### 阶段1：日出（自动）

触发时机：每天开始时自动执行

输出信息：
- 日期 / 室外温度 / 室内温度 / 天气
- 资源日报：食物余X天 / 水余X天 / 燃料余X天
- 全员状态检查：体温/饥饿/伤病/精神
- 检查是否有强制事件（暴风雪/入侵者/设备故障）

设计意图：让玩家每天醒来第一眼就感受到"压力"——资源在减少，温度在变化。

### 阶段2：任务分配（玩家操作）

这是玩家每天的**主要操作入口**：
- 给每个团队成员分配当日任务（含自己）
- 每人1个主任务（占全天）
- 任务类型：守屋/维修/搜刮/做饭/巡逻/休息/...

约束规则：
- 每人必须分配1个任务（不能闲着）
- 连续工作5天不休息 → 效率-30% + 精神压力+5/天
- NPC可能拒绝不合理的安排（士气低时）
- 某些任务需要特定条件（维修需工具，做饭需厨具等）

### 阶段3：日间执行（自动 + 事件插入）

系统自动推进：
- 各人执行任务 → 产出结果
- 外出搜刮 → 触发搜刮子流程（见06-外出搜刮）
- 可能触发随机事件/突发事件
- 可能有人来敲门（求助/威胁）

设计意图：玩家做完决策后"等待结果"，这段时间用事件打破等待感。

### 阶段4：夜间（玩家决策）

玩家需要处理：
- 燃料消耗结算（供暖过夜）
- 值夜安排（谁来守夜？不守夜 = 被偷袭风险+10%）
- 团队对话事件（NPC之间互动/矛盾/鼓励）
- 精神压力结算

### 阶段5：日终（自动）

系统自动结算：
- 资源消耗扣除
- 室内温度计算
- 健康状态更新
- 士气更新
- 天气预报（明天的天气/温度）
- 电台信息（如果有电台）
- 自动保存

## 流程图

```
┌─────────┐     ┌─────────────┐     ┌─────────────┐     ┌────────┐     ┌────────┐
│  日出    │────→│  任务分配    │────→│  日间执行    │────→│  夜间   │────→│  日终   │
│ (自动)   │     │ (玩家操作)  │     │ (自动+事件) │     │(玩家)  │     │ (自动)  │
└─────────┘     └─────────────┘     └─────────────┘     └────────┘     └────────┘
     ↑                                                                        │
     └────────────────────────── 下一天 ──────────────────────────────────────┘
```

## 系统交互关系

核心循环每天驱动以下系统：

| 阶段 | 触发的子系统 |
|------|-------------|
| 日出 | 环境系统（温度/天气）、事件系统（强制事件检查） |
| 任务分配 | 团队管理系统 |
| 日间执行 | 搜刮系统、事件系统、威胁系统 |
| 夜间 | 资源系统（燃料）、团队管理（士气/精神）、威胁系统 |
| 日终 | 资源系统（全体消耗）、安全屋系统、通讯系统 |

## 节奏设计

第二阶段30天的节奏变化：

| 天数 | 节奏感 | 设计意图 |
|------|--------|----------|
| Day 31~35 | 适应期 | 系统逐一上线（停水/停电），让玩家学习 |
| Day 36~40 | 压力上升 | 全面断供+气温骤降，开始紧张 |
| Day 41~45 | 极限期 | 死亡温度带，每天都在生死边缘 |
| Day 46~50 | 缓解期 | 气温回升，玩家放松 |
| Day 50~52 | 反转期 | 假回暖→骤降！最终考验 |
| Day 53~60 | 收尾期 | 真正回暖，等待救援 |
